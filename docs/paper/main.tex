\title{\sys: Semantic Profiling for AI Agents}
\author{Anonymous Submission}
\affiliations{}

\maketitle

\begin{abstract}
AI agents increasingly orchestrate long-running, multi-step activities across
users, tools, and system resources, so developers need to determine where
failures concentrate, which workflows trigger unsafe effects, and which task
categories consume the most budget across many executions.
% AI 智能体日益编排跨越用户、工具和系统资源的长时间、多步骤活动，因此开发者需要跨许多次执行确定故障集中在哪里、哪些工作流触发不安全副作用，以及哪类任务消耗最多预算。
Traditional systems profiling aggregates resource use over stable code paths,
whereas existing agent tools trace runs and aggregate metadata but do not link
additive system effects to responsible actions and fold them into selectable
profiles organized by semantic categories.
% 传统系统 profiling 聚合稳定代码路径上的资源使用，而现有智能体工具虽提供 trace 和 metadata 聚合，却不会将可加系统副作用连接回负责的 action，并按语义类别折叠成可选 profile。
Agent observability needs profiling, not only debugging.
% 智能体可观测性需要 profiling，而不仅仅是 debugging。
To implement our \emph{semantic operation stack model}, \sys represents
activities as uniform \emph{operations}, replaces runtime stacks with
\emph{operation stacks}, provides pluggable mechanisms for intent attribution
and stack construction, and exports pprof-compatible profiles. Its label-free
constructor learns recurring transitions between visible actions.
% 为实现语义 operation stack 模型，\sys 将活动表示为统一 operation，用 operation stack 替代运行时 stack，提供可插拔的意图归因和栈构造机制，并输出 pprof 兼容 profile；其中无标签 constructor 学习可见 action 之间的重复 transition。
We evaluate \sys on a 20-task real Codex capture suite, 405 human-staged
CodeTraceBench trajectories, three complete public localization benchmarks,
287 OSWorld-Human sessions, and four public cost workloads.
% 我们在 20 个真实 Codex 任务、405 条带人工 stage 的 CodeTraceBench 轨迹、三个完整公开 localization benchmark、287 个 OSWorld-Human session 和四个公开成本 workload 上评估 \sys。
Within the declared process/tool scope, AgentSight capture and joining reach
100.0\% precision and 96.6\% recall, reject 1{,}629/1{,}629 concurrent-control
effects, and pass
1{,}520 linked effects to \sys, which preserves every one during folding.
Label-free recurrence raises ordinary B$^3$ F1 against human stage
partitions from 0.541 to 0.649, with secondary token-weighted gains of
0.076--0.085.
% 范围化的 AgentSight-to-\sys 路径以 100.0% precision 和 96.6% recall 连接副作用，拒绝全部 1,629 个对照并保留全部 1,520 个已连接副作用；无标签 recurrence 将相对人工 stage partition 的标准 B$^3$ F1 从 0.541 提升至 0.649，辅助 token-weighted 增益为 0.076--0.085。
Semantic profiles improve MAP over raw-action grouping across trajectories containing
annotated targets in all three localization benchmarks.
On OSWorld-Human, label-free recurrence reaches 0.680 boundary F1 and 0.786 B$^3$ F1 versus
0.645 and 0.678 for the strongest simple control and 0.739 and 0.816 for the
supervised predictor. \sys processes 27{,}765 operations in 1.17\,s.
% Semantic profile 在三个 localization benchmark 上均提高相对 raw action 的 MAP；在 OSWorld-Human 上，无标签 recurrence 取得 0.680 boundary F1 和 0.786 B$^3$ F1，简单对照为 0.645 和 0.678，监督 comparator 为 0.739 和 0.816；\sys 在 1.17 秒内处理 27,765 个 operation。
\end{abstract}

% AI agents increasingly orchestrate long-running, multi-step
% activities involving thousands to millions of interactions with
% users, tools, and system resources.
% To optimize the quality, safety, and cost of agents, developers must 
% analyze behaviors across thousands of runs to 
% find where failures concentrate, 
% locate the workflow phases triggering unsafe effects, 
% and identify the tasks that consumes most budget. 

% While performance profiling traditionally answers these questions 
% for classic software by aggregating resource consumption, 
% traditional profilers fail for agents.
% unlike traditional software where code paths provide a natural hierarchy for profiling, 
% agent behaviors are driven by unstructured natural language prompts 
% and lack deterministic execution stacks. 
% To bridge this gap, we propose the Semantic Operation Stack model. 
% First, we unify all heterogeneous agent activities (prompts, tool calls, 
% and system I/O) into a single structured record called an operation. 
% Second, we construct dynamic call stacks at query time by projecting 
% these operations onto user-defined semantic fields (e.g., intent $\rightarrow$ phase $\rightarrow$ action), merging identical sequences to generate flame graphs.

% We implement this model in AgentProf, an offline profiler 
% with pluggable algorithms for intent attribution and stack construction, 
% compiling local agent trajectories into standard, pprof-compatible profiles.

\section{Introduction}
\label{sec:intro}

%% ¶1: Background + context
AI agents~\cite{sweagent,codex,claudecode,osworld} orchestrate multi-step activities
across a high-level intent layer (prompts, LLM calls, and tool invocations) and
a low-level system-effects layer (process spawns and file and network I/O).
% AI 智能体~\cite{sweagent,codex,claudecode,osworld}编排跨越两层的多步骤活动：高层意图（提示词、LLM 调用、工具调用）和低层系统副作用（进程创建、文件和网络 I/O）。
As agents evolve from short scripts into complex systems, production teams
accumulate many trajectories.
% 随着智能体从短小脚本发展为复杂系统，生产团队会积累大量轨迹。

%% ¶2: Problem
To improve agent quality, safety, and cost efficiency, developers
need to analyze agent behavior across many trajectories.
Which categories of tasks consume the most token budget? Where do
failures concentrate across workflows? Which behavioral patterns
trigger unsafe system effects?
% 为了提高智能体质量、安全性和成本效率，开发者需要跨轨迹和交互分析运维行为。哪类任务消耗最多 token 预算？故障跨工作流集中在哪里？哪些行为模式触发不安全系统副作用？
At scale, manual trajectory inspection is slow and expensive~\cite{agentrewardbench},
while per-trajectory LLM judging requires a separate evaluator pass for every
run~\cite{agentrewardbench,llm-as-judge}.
% 在规模化时，人工轨迹检查缓慢且昂贵，而逐轨迹 LLM judging 需要为每次运行单独执行一次 evaluator。

%% ¶3: Structural cause
Profiling provides the required aggregation method because traditional systems
profilers attribute additive resource consumption to stable code paths rather
than debug individual executions~\cite{pprof,flamegraphs}.
% Profiling 提供所需的聚合方法：传统系统 profiler 将可加资源消耗归因到稳定代码路径，而不是调试单次执行。
Agent trajectories lack the two structures that make this aggregation
possible.
% 智能体轨迹缺乏使这种聚合成为可能的两个结构。
Responsibility lies in semantic categories such as task intent and tool
operation rather than stable function names. Natural-language prompts provide
no common identifier for shared intent.
% 负责实体是任务意图和工具操作等语义类别而非稳定函数名；自然语言提示词不会为共享意图提供共同标识符。
Agent events also lack runtime call nesting. A prompt sequence may represent
multiple tasks, while one task may belong to a larger task.
% 智能体事件也缺少运行时调用嵌套：一段提示序列可能表示多个任务，而一个任务又可能属于更大的任务。
Thus adapting profiling requires stable semantic identifiers and an
attribution hierarchy that does not depend on a runtime stack.
% 因此，适配 profiling 需要稳定的语义身份，以及不依赖运行时调用栈的归因层次。

%% ¶4: Existing solutions
Existing agent tools provide rich tracing, metadata aggregation, and population
dashboards~\cite{langsmith,langfuse,phoenix,otel,datadog-llmobs,laminar-signals}.
Some derive hierarchical categories across traces and aggregate latency, cost,
or evaluation metrics~\cite{langsmith-insights,datadog-patterns}. Existing
agent tools do not link additive system effects to responsible agent actions
and aggregate them by semantic fields into selectable pprof profiles.
% 现有智能体工具提供 tracing、tag/metadata 聚合和群体级 dashboard；部分工具跨 trace 派生分层类别并聚合 latency、cost 或 evaluation metric，但不会将可加系统副作用连接回负责的 agent action，再按语义字段聚合为可选 pprof profile。

%% ¶5: Model
Agent observability needs profiling, not only debugging.
% 智能体可观测性需要 profiling，而不仅仅是 debugging。
Profiling transfers by projecting resources onto stable semantic tags in an
attribution hierarchy.
% 当资源被投影到负责的语义实体、赋予稳定标签并分层归因时，profiling 方法论可以迁移。
Our \emph{semantic operation stack model} provides this structure through
operations and operation stacks.
% 我们的语义 operation stack 模型通过 operation 和 operation stack 两个组件实现这种迁移。
\emph{Operations} are uniform records with string fields and additive measures
that represent prompts, LLM calls, tool invocations, and system effects
without type-specific objects.
% Operation 是带有字符串字段和可加度量的统一记录，无需特定类型对象即可表示提示词、LLM 调用、工具调用和系统副作用。
\emph{Operation stacks} replace the runtime call stack by ordering selected
fields. Changing those fields attributes the same operations by task category,
execution phase, session, or action type (Figure~\ref{fig:flamegraph}).
% Operation stack 通过排列所选字段替代运行时调用栈；改变这些字段即可按任务类别、执行阶段、会话或操作类型归因同一组 operation（Figure~\ref{fig:flamegraph}）。

%% ¶6: System
We implement this model in \sys, an offline profiler that compiles
local agent trajectories into pprof-compatible profiles~\cite{pprof}
(Figure~\ref{fig:architecture}).
% 我们在 \sys 中实现此模型，这是一个离线 profiler，将本地智能体轨迹编译为 pprof 兼容的 profile（Figure~\ref{fig:architecture}）。
\emph{Intent attribution} derives stable, low-cardinality tags from
natural-language fields via regex rules, a local LLM tagger, or unsupervised
clustering, replacing the identity supplied by function names.
% 意图归因通过正则规则、本地 LLM 标注器或无监督聚类从自然语言字段派生稳定、低基数的标签，提供传统 profiling 从函数名获得的语义身份。
\emph{Stack construction} uses either selected fields or label-free recurrence
over visible cross-session action transitions to replace runtime nesting.
% 栈构造使用用户指定的字段列表，或学习 reference session 间重复可见 action transition 的无标签 recurrence constructor，在没有运行时调用嵌套时提供层次。

%% ¶7: Results
On 20 real Codex tasks, scoped AgentSight~\cite{agentsight} capture and joining
reach 100.0\% precision and 96.6\% recall, reject all 1{,}629 controls, and pass
1{,}520 effects that \sys preserves during folding.
% 在 20 个真实 Codex 任务上，范围化的 AgentSight capture 与 process/tool join 达到 100.0\% precision 和 96.6\% recall 并拒绝全部 1,629 个对照；adapter 转换后，\sys 在折叠中保留全部 1,520 个已连接副作用。
On all 405 reconstructable failed CodeTraceBench trajectories~\cite{li2026codetracer},
label-free recurrence raises ordinary B$^3$ F1 against human stages over raw
action from 0.541 to 0.649, a gain of 0.108 with 95\% interval [0.087, 0.129].
% 在 released source 能生成官方 operation sequence 的全部 405 条失败 CodeTraceBench 轨迹上，recurrence 相比 matched raw action identity 将与人工 stage 的标准 B$^3$ F1 从 0.541 提升至 0.649，增益为 0.108，95\% 区间为 [0.087, 0.129]。
Secondary token-weighted gains remain 0.076--0.085 under three shared-response
allocations~\cite{demaere-darling-2016}.
% 在该 CodeTraceBench 比较中，使用 mapped operation-producing token 加权后，在共享 response 的均分、全部归于首 operation 和全部归于末 operation 三种分配下，增益均保持为 0.076--0.085。

Across three complete public workloads, MAP over target-bearing trajectories
rises from 0.773 to 0.789, 0.281 to 0.452, and 0.121 to 0.230,
respectively~\cite{agentprocessbench,hintbench,traceelephant}.
% 三个完整公开 workload 的全部 27,346 个 operation 均参与评分；在 614/400/220 条含目标 query 上，trajectory MAP 分别从 0.773 提升到 0.789、从 0.281 提升到 0.452、从 0.121 提升到 0.230。
On 287 OSWorld-Human development sessions~\cite{osworldhuman}, label-free
recurrence reaches 0.680 boundary F1 and 0.786 B$^3$ F1. Simple controls reach
0.645 and 0.678, whereas a supervised comparator reaches 0.739 and 0.816.
% 在 287 个 OSWorld-Human development session 上，无标签 recurrence 的 boundary F1 与 B$^3$ F1 为 0.680 和 0.786，简单对照为 0.645 和 0.678，监督 comparator 为 0.739 和 0.816。

On four public workloads, \sys profiles 27{,}765 operations in 1.17\,s and
464.5\,MiB, adding 18.2\% time and 1.3\% memory over raw action.
% 在四个公开 workload 上，\sys 用 1.17 秒和 464.5 MiB profile 27,765 个 operation，比 raw action 增加 18.2\% 时间和 1.3\% 内存。

%% ¶8: Contributions
This paper makes three contributions:
% 本文做出三项贡献：

\begin{enumerate}
\item \textbf{Semantic operation stack model.}
  Uniform operations and query-time stacks supply agent observability's
  missing profiling layer (Background and Motivation; Design).
% 语义 operation stack 模型。识别智能体可观测性中缺失的 profiling 层，提出统一 operation 和查询时 operation stack 的模型。
\item \textbf{System: \sys.}
  Pluggable intent attribution and stack construction produce pprof-compatible
  profiles (Implementation).
% 系统：\sys。实现此模型的 profiler，具有可插拔意图归因和栈构造，产生 pprof 兼容输出。
\item \textbf{Evaluation.}
  Semantic profiles preserve joined effects, improve attribution and problem
  ranking over raw action, and recover task partitions, declared task/action
  tags, and session-held-out groups; \sys profiles 27{,}765 operations in
  1.17 seconds (Evaluation).
% 评估。我们在 20 个真实 Codex 任务上评估源谱，在 405 条 CodeTraceBench 轨迹上评估独立标注的资源归因，在 325 条真实轨迹和 15 个映射公开 family 上评估资源视图，在三个完整公开基准上评估问题对应性，在 287 个 held-out task instance 上评估边界准确性，并在 27,765 个 operation 上评估构建成本。
\end{enumerate}

\section{Background and Motivation}
\label{sec:background}

\subsection{LLMs and AI Agents}
% AI 智能体

A typical agent trajectory interleaves two layers of
activity~\cite{sweagent,codex,claudecode,agentsight}.
% 典型的智能体轨迹交织两层活动。
At the intent layer, an agent receives prompts, issues LLM calls, and invokes
tools for code execution, search, and file editing.
% 在意图层，智能体接收用户提示词、发出 LLM 调用并调用工具（代码执行、网络搜索、文件编辑）。
Tool invocations trigger lower-layer process, file, and network
effects~\cite{agentsight}; trajectories repeat this cycle, and teams accumulate
many trajectories.
% 每次工具调用在下层触发系统副作用：进程创建、文件读写和网络请求。
% 单条轨迹会重复这样的意图-副作用循环，团队也会积累许多轨迹。

\subsection{System Profiling}
% 系统 Profiling

Profiling aggregates measurements to attribute resources to responsible
entities rather than debug one execution.
% Profiling 通过聚合将资源消耗归因到负责实体，区别于单次执行调试和 tracing。
Traditional profilers sample execution, attach each sample to its call stack,
and fold identical stacks~\cite{pprof,flamegraphs}.
% 在传统软件中，profiling 管线如下工作：profiler 周期性采样执行状态，将每个样本附加到当前调用栈，合并具有相同栈的样本。
Flame graphs~\cite{flamegraphs} and pprof~\cite{pprof} call graphs visualize
aggregate cost by width or node size, while Perfetto~\cite{perfetto} queries
trace events and derives new ones.
% 火焰图~\cite{flamegraphs}和 pprof~\cite{pprof} 调用图可视化其结果，宽度或节点大小代表聚合开销。
These tools start from stable code identifiers and runtime stacks; pprof can
also promote \texttt{tagroot}/\texttt{tagleaf} values to pseudo-frames.
% 这些工具通常从稳定的代码标识符和运行时栈开始；pprof 也可以聚合标签，并将 \texttt{tagroot}/\texttt{tagleaf} 值提升为伪帧。
Agent profiles must instead derive stable semantic fields and connect them to
downstream effects.
% 智能体轨迹则必须先获得稳定的语义责任字段，并将其连接到下游副作用，之后才能形成这类 profile 视图。

\subsection{Challenges for Agent Profiling}
% 智能体 Profiling 的挑战

Existing tools~\cite{langsmith,langfuse,phoenix,otel} record agent events as
per-execution span trees that support single-run debugging.
% 现有工具~\cite{langsmith,langfuse,phoenix,otel}将智能体事件记录为按执行划分的 span 树，有效调试单次运行。
AgentSight~\cite{agentsight} bridges intent and system-effect layers by
correlating extended Berkeley Packet Filter (eBPF) system events with intercepted LLM
traffic, but the resulting recordings still lack aggregate profiling.
% AgentSight~\cite{agentsight} 通过关联 eBPF 捕获的系统事件与拦截的 LLM 流量来桥接意图层和系统副作用层，但生成的记录仍缺乏聚合分析能力。


Agent profiling faces two challenges. First, responsibility lies in semantic
categories such as task intent and workflow phase, not code paths.
% 在传统软件中，profiling 将开销归因到代码路径，但在智能体轨迹中，相关实体是语义类别（如任务意图和工作流阶段）。
Standards represent application-supplied span attributes~\cite{otel,
openinference}, but natural-language histories lack stable categories because
different prompts or tools can express the same intent.
% 现有标准可以在 span 中表示应用提供的属性，但自然语言历史不会自动提供稳定的责任类别：表达相同意图的两个提示词和工具调用可能使用不同字符串。

Second, agent trajectories lack a runtime call hierarchy for semantic attribution.
% 第二个挑战是智能体轨迹没有能够自动提供语义归因的运行时调用层次。
In CPU profiling, the stack attributes \texttt{malloc}'s cost simultaneously
to \texttt{parse}, \texttt{process}, and \texttt{main}.
% 在 CPU 分析中，调用栈决定了每个层级的归因：\texttt{malloc} 的开销同时属于 \texttt{parse}、\texttt{process} 和 \texttt{main}。
A prompt sequence may contain one or several tasks within a larger workflow,
yet no runtime mechanism marks its boundaries or attribution granularity.
% 一串提示词可能构成一个任务也可能是多个任务，一个任务可能是更大工作流的一部分，但没有运行时机制标记这些边界或决定在哪个粒度归因开销。
RQ1 evaluates the attribution consequence, while RQ3 evaluates constructed
groups and boundaries.
% RQ1 评估其归因后果，RQ3 评估构造出的 group 与 boundary。

\subsection{Design Requirements for Agent Profiling}
% 智能体 Profiling 的设计需求

Traditional profiling relies on three mechanisms that the call stack provides automatically.
% 传统 profiling 依赖调用栈自动提供的三种机制。
Agent profiling needs all three but must achieve them without a call stack:
% 智能体 profiling 需要这三种机制，但必须在没有调用栈的情况下实现：

\begin{description}
\item[D1: Cross-layer resource projection.]
The profiler must connect resource consumption from file I/O and process
spawns to the responsible prompts and LLM calls.
% 分析器必须将系统层的资源消耗连接到意图层的语义类别。
\item[D2: Stable tags for folding.]
Without stable function names, the profiler must derive short, repeatable tags
from natural language before folding.
% 智能体提示词是自然语言，因此分析器必须在折叠前派生短小、稳定、可重复的标签。
\item[D3: Hierarchical attribution.]
Because span trees do not encode semantic responsibility through function-call
nesting, the profiler must construct attribution hierarchies from the data.
% 智能体 span 树不通过函数调用嵌套编码语义责任，因此分析器必须从数据中构造归因层次。
\end{description}

The next section maps these requirements to \sys's design.
% 下一节将这些需求映射到 \sys 的设计。

%% ===================================================================
\section{Design}
% 设计
\label{sec:design}

The design maps D1--D3 to ingestion, tags, and operation stacks.
% 三个需求（跨层资源投影、稳定标签和分层归因）驱动了设计。
For D1, source-specific ingestion links each system effect to its intent, and
operations preserve inherited semantic fields for projection and folding.
% Source-specific ingestion 与 operation 表示共同满足 D1：ingestion 将系统副作用连接到负责的意图后，operation 保留该连接及继承的语义字段，\sys 随后投影并折叠这些字段。
For D2, intent attribution derives stable tags from natural-language fields.
% Attribution and Stack Construction 中的意图归因通过从自然语言字段派生稳定标签满足 D2。
For D3, \emph{operation stacks} replace runtime stacks with query-time field
projections, supporting multiple attribution granularities over the same data.
% Operation stack 通过以查询时字段投影替代运行时调用栈，在多个粒度层级归因资源来满足 D3，使同一数据支持多种视图而无需重建输入。

The profiling pipeline has four stages: (1)~parse raw trajectories into operations, (2)~enrich operations via intent attribution or mapping rules, (3)~project each operation onto a stack frame sequence chosen at query time, and (4)~fold operations with identical stacks, summing their weights.
% 分析管线有四个阶段：(1) 将原始轨迹解析为 operation，(2) 通过意图归因或映射规则丰富 operation，(3) 将每个 operation 投影到查询时选择的栈帧序列上，(4) 折叠具有相同栈的 operation 并求和权重。

\subsection{Semantic Operation Stack Model}
% 语义 Operation Stack 模型
\label{sec:ops}

%% ¶1: Operations
\sys uses one data representation for the intent and system-effect layers
described in Background and Motivation.
% 由于智能体活动跨越 Background and Motivation 中描述的意图层和系统副作用层，分析器不应在数据表示层面区分它们。
\sys therefore represents every activity as an \operation, a weighted record
with string fields and additive measures.
% 因此 \sys 将每个活动表示为单一抽象——operation，一个带有字符串字段和可加度量的加权记录。
Each operation carries string fields (\texttt{project},
\texttt{agent}, \texttt{session}, \texttt{prompt\_tag},
\texttt{kind}, \texttt{model}, \texttt{path}, \texttt{domain},
\texttt{status}, \ldots) and additive measures (token count,
duration, event count).
% 每个 operation 携带字符串字段（\texttt{project}、\texttt{agent}、\texttt{session}、\texttt{prompt\_tag}、\texttt{kind}、\texttt{model}、\texttt{path}、\texttt{domain}、\texttt{status} 等）和可加度量（token 数、持续时间、事件数）。
The same schema represents prompts, LLM calls, tool invocations, file reads,
GUI clicks, and process events. Populated fields distinguish these operation
types.
% 提示词、LLM 调用、工具调用、文件读取、GUI 点击和进程事件都是具有相同 schema 的 operation，仅通过哪些字段有值来区分。
When a tool invocation triggers system effects, ingestion propagates its
semantic fields to the resulting operations, allowing downstream resource
weights to fold under the responsible intent.
% 当工具调用触发系统副作用时，输入处理将其语义字段传播到生成的 operation，使下游资源权重能够折叠到负责的意图之下。

%% ¶2: Operation Stacks
\label{sec:stacks}
An \opstack provides hierarchical attribution for agent trajectories, replacing the runtime call stack.
% 一个 operation stack 为智能体轨迹提供分层归因，替代运行时调用栈。
In CPU profiling, the call stack determines which code paths
share responsibility for a resource cost.
% 在 CPU 分析中，调用栈决定哪些代码路径共同承担资源开销。
An operation stack serves the same role. An ordered list of fields
$[f_1, f_2, \ldots, f_k]$ projects each operation $o$ to a frame
sequence $\langle o.f_1, o.f_2, \ldots, o.f_k \rangle$, and
operations with identical sequences are merged, summing their
weights.
% Operation stack 承担相同角色：有序字段列表 $[f_1, f_2, \ldots, f_k]$ 将每个 operation $o$ 投影到帧序列 $\langle o.f_1, o.f_2, \ldots, o.f_k \rangle$，具有相同序列的 operation 被合并，权重求和。
Unlike a call stack, the fields are chosen at query time, not
determined by execution.
% 与调用栈不同，字段在查询时选择，而非由执行决定。
The same operations can therefore support a flat task summary, a per-session
tree, a semantic phase/action hierarchy, or a trajectory organized by the
dataset's own annotations. Changing the fields changes attribution without
changing the data.
% 因此同一组 operation 可归因为扁平任务摘要、固定会话树、语义阶段/操作层次或使用数据集自身标注的轨迹，改变字段即改变归因方式而无需改变数据。
Sessions and spans are optional fields, not hierarchy levels. The same data
supports debugging views with \texttt{session} and aggregate profiling views
without that field.
% 会话和 span 是可选的 operation 字段而非固定层次级别，因此同一数据既支持调试视图（包含 \texttt{session}）也支持聚合 profiling 视图（排除它）。

We formalize each selectable profile as a view $(\varphi, \sigma, w)$. For operation $o$, the predicate
$\varphi(o)$ decides inclusion, an ordered field list
$[f_1, \ldots, f_k]$ defines
$\sigma(o)=\langle o.f_1, \ldots, o.f_k \rangle$, and $w(o)\geq0$ supplies its
weight.
% 一个视图是三元组 $(\varphi, \sigma, w)$：谓词 $\varphi$ 选择参与的 operation，栈函数 $\sigma = [f_1, \ldots, f_k]$ 将每个 operation 映射到其帧序列，权重函数 $w$ 赋予非负度量。
Users choose the stack function independently of the predicate and weight
function. Four built-in resource
choices define $\varphi$ and $w$ for common questions: (1)~\texttt{tokens} weights LLM
calls by token count, (2)~\texttt{time} weights timed operations by duration,
(3)~\texttt{files} weights file operations by event count, and
(4)~\texttt{network} weights network operations by event count.
% 栈函数保持独立可选。四个内置资源选择为常见问题定义 $\varphi$ 和 $w$：\texttt{tokens}（LLM 调用按 token 数加权）、\texttt{time}（所有计时操作按时长加权）、\texttt{files}（文件操作按事件数加权）和 \texttt{network}（网络操作按事件数加权）。

\subsection{Attribution and Stack Construction}
% 归因与栈构造
\label{sec:intent}

\paragraph{Intent attribution.}
% 意图归因。
Intent attribution maps natural-language fields to short, stable,
repeatable tags, giving agent trajectories the stable identifiers that traditional
profiling derives from function names, as discussed in Background and
Motivation.
% 意图归因将自然语言的提示词映射为短小、稳定、可重复的标签，为智能体轨迹提供传统 profiling 从函数名免费获得的稳定标识符，详见 Background and Motivation。
The framework supports three pluggable backends.
% 该框架支持三种可插拔后端。
Explicit rules provide repeatable user control, a local model tags
natural-language fields, and unsupervised grouping discovers candidate
categories that developers can encode as rules.
% 显式规则提供可重复的用户控制，本地模型标注自然语言字段，无监督分组帮助发现供后续规则编写使用的候选类别。
Structured trajectories use the same interface to derive fields from existing
action and quality attributes.
% 结构化轨迹使用同一接口从现有 action 和质量属性派生字段。
All backends emit ordinary operation fields, keeping the stack model
independent of how a tag was obtained.
% 所有 backend 都输出普通 operation 字段，使 stack 模型独立于标签的获取方式。

\paragraph{Stack construction.}
% 栈构造。
Stack construction builds attribution hierarchies from
available fields.
% 栈构造从可用字段构建归因层次。
When users supply an ordered list of fields, the projection is direct.
% 当用户提供有序字段列表时，投影是直接的。
When users enable automatic construction, \sys induces operation
stacks without a user-specified field list.
We call this constructor \emph{label-free recurrence}. Visible actions are
values of the action field available before any target annotation is read.
The constructor learns which adjacent visible actions reliably recur across
reference sessions. Weak or unseen transitions start a new segment, whereas
recurring transitions continue the current segment. The segment's
run-length-compressed action sequence becomes a reusable stack-frame value.
% 它学习哪些相邻可见 action 会在参考 session 中稳定重复。较弱或未见过的转移开始新的 segment；重复出现的转移延续当前 segment，其经游程压缩的 action 序列成为可复用的 stack-frame value。
The derived group and stack-frame values are ordinary operation fields, so the stack
function can compose them with task, phase, action, or session fields at query
time.
% 派生出的 group 与 stack-frame value 是普通 operation 字段，因此栈函数可在查询时将其与 task、phase、action 或 session 字段组合。
The constructor can learn from a separate label-free operation corpus, so it
does not use the target session's problem annotations.
% 参考数据可以是独立的无标签 operation 语料，因此构造过程不使用目标 session 的问题标注。

\section{Implementation}
% 实现
\label{sec:impl}

\sys implements the semantic operation stack model as an offline Rust
command-line interface (about 9.8K lines, Figure~\ref{fig:architecture}).
% \sys 将 operation 和 stack 模型实现为离线 Rust CLI（约 9.8K 行代码，Figure~\ref{fig:architecture}）。

\paragraph{Input reconstruction.}
% 输入重建。
\sys reads Codex and Claude Code local JSON Lines (JSONL) histories and
operation JSONL.
For native histories, it reconstructs prompts, LLM calls, and tool invocations.
Because the current CLI does not read AgentSight~\cite{agentsight} recordings
directly, those recordings pass through a source-specific adapter. For this
path, the declared process/tool scope contains the captured
target agent process and its launched tool command, excluding concurrent
control activity. AgentSight joins system effects within this scope, and the
adapter emits operations carrying those links.
\sys then projects and folds their fields and weights.
% \sys 读取 Codex 和 Claude Code 本地 JSONL history 及 operation JSONL，并从原生 history 重建 prompt、LLM call 和 tool invocation。AgentSight~\cite{agentsight} 记录则先经过源特定 adapter：AgentSight 在声明的 process/tool scope 内连接系统副作用，adapter 输出携带这些连接的 operation；\sys 随后投影并折叠其字段与权重。当前 CLI 不直接读取 AgentSight 记录。

\paragraph{Field derivation.}
% 字段派生。
Regex rules are the production default. Each rule has the form
\texttt{KIND:TAG=REGEX}, and rules use first-match semantics. Developers can refine
the rules by rerunning \sys and inspecting unmatched operations.
% 正则规则是生产环境默认：规则格式为 \texttt{KIND:TAG=REGEX}，按顺序求值（首个匹配胜出）；开发者可以通过重复运行 \sys 并检查未匹配 operation 来细化规则。
Through llama.cpp~\cite{llamacpp}, a local LLM tagger can run a quantized
3B-parameter model. The tagger either generates a single-word tag or assigns
one tag from a user-declared set of task tags. Both tagging modes use
grammar-constrained decoding and caching.
% 本地 LLM tagger（例如通过 llama.cpp~\cite{llamacpp} 运行的量化 3B 参数模型）既可生成单词标签，也可从用户声明的 task 标签集合中指派一个标签；两条路径均使用语法约束解码和缓存。
TF-IDF~\cite{salton-buckley-1988} and
K-Means~\cite{macqueen1967} discover candidate prompt groups without predefined rules,
while mapping rules derive fields for structured trajectories, for example
\texttt{phase:navigate=type:(click|scroll|key)}.
% TF-IDF~\cite{salton-buckley-1988} 和 K-Means~\cite{macqueen1967} 在没有预定义规则时发现候选 prompt 分组，而 mapping rule 为结构化轨迹派生字段，例如 \texttt{phase:navigate=type:(click|scroll|key)}。

\paragraph{Boundary construction.}
% 边界构建。
The Rust inducer counts adjacent action transitions in reference sessions and
scores each transition by normalized pointwise mutual information (NPMI),
$\mathrm{NPMI}(a,b)=
\ln[p(a,b)/(p_L(a)p_R(b))]/-\ln p(a,b)$, with all three probabilities defined
over the same transition sample space~\cite{bouma2009npmi}.

Occurrence-weighted one-dimensional $k$-means with $k=2$~\cite{macqueen1967}
starts at the minimum and maximum scores, assigns distance ties to the lower
center, and uses the converged midpoint as a global cutoff. The inducer repeats
this procedure over transitions between different actions to obtain a second
cutoff. Same-action pairs use the global cutoff, whereas pairs with different
actions use the smaller cutoff. The second cutoff can therefore remove but
never add a boundary from the global rule.
Unseen transitions or scores below the applied cutoff start a new segment.
Each segment's run-length-compressed action sequence becomes its stack-frame
value.
The inducer reads only session identity, input order, and action. Target annotations
and resource weights do not affect construction.
% Rust inducer 统计参考 session 中的相邻 action 转移，并用 NPMI 评分；所有概率来自同一转移样本空间。按出现次数加权的一维 k-means（k=2）从最小和最大分数初始化，将距离相同的点分到较低中心，并用收敛后两个中心的中点作为全局阈值；在 action-changing occurrence 上进行同样校准得到 cross-action 阈值。相同 action 使用全局阈值，不同 action 使用两者中较小者，因此 refinement 只能删除而不能新增全局规则边界；未见转移或低于应用阈值的分数开始新的 segment。经游程压缩的 action 序列成为 stack-frame value。inducer 只读取 session、输入顺序和 action；评分标签与资源权重不参与构造。

An optional reference-calibrated recurrence mode keeps the NPMI score but
selects one scalar cutoff that maximizes per-operation B$^3$ F1 on disjoint
reference groups. The mode enumerates score intervals, resolves exact ties
toward the smallest cutoff, and never reads target groups. Label-free
$k$-means remains the default.
% 可选的 reference-calibrated recurrence 模式保持同一 NPMI score，并在与目标不重叠的参考分组上选择使每个 operation 等权的 B$^3$ F1 最大的单一阈值。它枚举有限 score interval，在完全平局时选择最小阈值，且不读取目标分组；无标签 k-means 规则仍是默认模式。

\paragraph{Profile export.}
% Profile 导出。
Output formats are pprof protobuf for \texttt{go tool pprof -http}, folded
stacks for \texttt{flamegraph.pl}, standalone SVG flame graphs, and JSON.
% 输出格式包括 pprof protobuf（兼容 \texttt{go tool pprof -http}）、折叠栈文本（兼容 \texttt{flamegraph.pl}）、独立 SVG 火焰图和 JSON 摘要。

\section{Evaluation}

\label{sec:eval}

\paragraph{Research questions.}
% 研究问题。
The evaluation addresses four research questions:
% 评估回答四个固定的论文级研究问题：
\textbf{RQ1:} Does semantic profiling improve resource attribution?
\textbf{RQ2:} Does profiler output correspond to real problems?
\textbf{RQ3:} How accurate are the tags?
\textbf{RQ4:} What is the profiling cost?
Each RQ subsection pairs its protocol with the strongest answer its evidence
supports.

capture suite with concurrent controls.
% 真实输入包括一个多月项目中的 325 条可读 history（198 Codex、50 Claude、77 Claude subagent）及 183,714 个系统观测，以及一套独立的固定 20-task Codex capture suite 和并发对照。

\textbf{Annotated public trajectories (RQ1, RQ3, and RQ4)} comprise 15 real
agent or human execution families converted by mapping rules into 47{,}590
operations, plus a separate 405-trajectory, 20{,}866-operation CodeTraceBench
stage population.
% 公开标注轨迹包括通过 mapping rule 转换的 15 个真实 agent 或 human execution family、共 47,590 个 operation，以及独立的 405-trajectory、20,866-operation CodeTraceBench stage population。
They span web, API, coding, and mobile/GUI agents~\cite{weblinx,mind2web,
agenttrek,webshop,apibank,toolbench,taubench,sweagent,androidcontrol,
guiodyssey,scalecua}.
% 它们覆盖 web、API、coding 和 mobile/GUI agent。
Four families converted by mapping rules provide structured quality or
boundary annotations,
including AgentRewardBench~\cite{agentrewardbench}, SATraj-OS~\cite{safactory},
AgentNet~\cite{agentnet}, and OSWorld-Human~\cite{osworldhuman}.
% 其中四个映射后的家族提供结构化质量或边界标注：AgentRewardBench、SATraj-OS、AgentNet 和 OSWorld-Human。

\textbf{Problem-localization benchmarks (RQ2)} are AgentProcessBench,
HINTBench, and TraceElephant, which provide independent released
targets over 27{,}346 operations~\cite{agentprocessbench,hintbench,traceelephant}.
The 27{,}765-operation RQ4 union is drawn from four public workloads. These
experiment-specific totals are not pooled.
% AgentProcessBench、HINTBench 和 TraceElephant 在 27,346 个 operation 上为 RQ2 提供独立发布目标。RQ4 的 27,765-operation union 来自四个公开 workload；这些实验特定总数不合并。

\subsection{RQ1: Resource Attribution}
% RQ1：语义分析能否改善资源归因？

RQ1 asks whether semantic profiling improves resource attribution beyond what
traditional tag-free tools provide.
% 我们测试语义标签是否能超越传统无标签工具改善资源归因。
We first test whether the capture-and-join path assigns system effects within
the declared process/tool scope while rejecting concurrent controls. We use 20
real Codex tasks, each paired with one concurrent negative control. AgentSight
0.2.37 captures each pair and joins effects within that scope. An adapter
converts the joined effects to operation JSONL, which
\texttt{agentpprof 0.2.37} folds.
% 我们首先测试捕获与连接路径能否在声明的进程/工具范围内归因系统副作用并拒绝并发对照。评估包含 20 个真实 Codex 任务，每个任务配有一个并发负对照。AgentSight 0.2.37 捕获每一对运行并在该范围内连接副作用；adapter 将连接结果转换为 operation JSONL，再由 \texttt{agentpprof 0.2.37} 折叠。

All 20 tasks and their controls completed. The capture-and-join path recovers 1{,}520 of
1{,}574 in-scope effects with no false positives (100.0\% precision, 96.569\%
recall), and none of 1{,}629 control effects joins. \sys emits 1{,}520 samples in 152
stacks, exactly preserving the input total and all five predeclared
task-category totals.
% 20 个任务及其对照全部完成。连接路径恢复 1,574 个范围内副作用中的 1,520 个，0 个 false positive（precision 100.0\%、recall 96.569\%），且 1,629 个对照副作用均未连接。AgentProf 在 152 个 stack 中输出 1,520 个 sample，并精确保留输入总量及全部五个预先声明任务类别总量。

This result establishes capture-and-join precision and recall within the
suite's declared process/tool scope, and lossless folding by \sys. The task
categories are predeclared rather than automatically inferred.
% 该结果确立了套件声明进程/工具范围内的捕获与连接精确率和召回率，以及 AgentProf 的无损折叠；任务类别来自预先声明的配置，而非自动任务推断。

We next test whether the current operation stack assigns measured LLM resources
to independently annotated units of work more faithfully than raw operation
identity. We use all 405 failed CodeTraceBench trajectories whose released
sources yield the official operation sequence. The population contains
20{,}866 operations and 2{,}948 human-verified contiguous stage intervals
across OpenHands, mini-SWE-agent, SWE-agent, and
Terminus2~\cite{li2026codetracer}.
% 接着，我们测试当前 operation stack 是否比 raw operation identity 更准确地将实测 LLM 资源归因到独立标注的工作单元。我们使用 released source 能生成官方 operation sequence 的全部 405 条失败 CodeTraceBench 轨迹：来自 OpenHands、mini-SWE-agent、SWE-agent 和 Terminus2 的 20,866 个 operation 和 2,948 个人工验证的连续 stage interval。
We use the same recurrence constructor as in RQ3. It reads neither target
stages nor resource weights. Matched raw-action grouping starts a new group
whenever the source action field changes. Phase-only and action-kind grouping
use the named source field, while session grouping places each session in one
group. Per-operation grouping makes each operation a singleton. Every method receives
the same operations, stages, and provider-reported token measurements.
% 我们使用与 RQ3 相同的 recurrence constructor；它不读取目标 stage 或资源权重。匹配的 raw-action grouping 在源 action 字段改变时开始新组；phase-only 与 action-kind grouping 使用同名源字段；session grouping 将每个 session 作为一组；per-operation grouping 将每个 operation 作为单元素组。所有方法接收相同的 operation、stage 和 provider-reported token 测量。

We use ordinary operation-level B$^3$ precision, recall, and F1 as the primary
metric for partition agreement~\cite{bagga-baldwin-1998-entity-based}. We also
report token-weighted B$^3$~\cite{demaere-darling-2016} only as a
resource-sensitive secondary analysis.
% 我们使用普通 operation-level B$^3$ precision、recall 和 F1 作为标准主要 partition 指标，并将 token-weighted B$^3$ 作为资源敏感的次要分析；它不替代普通主要指标。

Table~\ref{tab:rq1-attribution} shows that recurrence raises ordinary B$^3$ F1

The adapter maps 494.9 million tokens from 17{,}148 responses that contain
operations. Of these, 1{,}426 responses contain multiple operations. Allocating
each shared response equally, entirely to its first operation, or entirely to
its last operation leaves the recurrence-minus-raw weighted F1 gain positive

% Adapter 从 17,148 个产生 operation 的 response 中映射 4.949 亿 token，其中 1,426 个 response 产生多个 operation。将每个共享 response 均分、全部归于第一个 operation 或全部归于最后一个 operation 时，recurrence 相对 raw 的 weighted F1 增益分别保持为 0.085、0.076 和 0.076；mapped mass 精确守恒。

Phase-only reaches a statistically indistinguishable 0.654 ordinary B$^3$ F1.
This experiment therefore supports attribution by semantic stages over raw
action identity, but it does not establish one semantic profile as universally
dominant. RQ3 separately tests the recurrence constructor against phase-only
boundaries on OSWorld-Human, where recurrence has a larger advantage. Because
this population influenced constructor selection, the result is post-hoc
support rather than independent confirmation.
% Phase-only 达到统计上不可区分的 0.654 普通 B$^3$ F1。因此，本实验识别出的关键差异是 semantic stage-aligned attribution 与 raw action identity，而不是选择一个普遍占优的 semantic view。RQ3 在 OSWorld-Human boundary 上单独测试 recurrence constructor 相对 phase-only 的优势。由于该 CodeTraceBench population 曾参与选择当前 constructor，我们将此结果视为 post-hoc supporting evidence，而非 untouched cross-family confirmation。

As a separate use case, five declared field hierarchies project the same
13{,}265 operations from nine trajectory families. The resulting profiles contain
9~dataset, 57~phase, 226~semantic, 455~action, or 3{,}757~per-session groups.
The families are WebLINX, WebShop, APIBank, AgentTrek, SWE-agent, Mind2Web,
ToolBench, AndroidControl, and GUI Odyssey.

The semantic hierarchy adds task,
operation type, tool, and status to dataset and phase. The five depths compare
budgets by task, repeated actions across sessions, and individual-session
details. The same model covers all 15 trajectory families without
type-specific objects.
% 作为独立用例，五种声明字段层次投影来自九个轨迹 family 的同一批 13,265 个 operation，分别形成 9 个 dataset、57 个 phase、226 个 semantic、455 个 action 或 3,757 个 per-session group。semantic hierarchy 在 dataset 与 phase 之上加入 task、operation type、tool 和 status；五种深度比较按任务统计的预算、跨 session 的重复 action 及单个 session 的细节。同一模型无需特定类型对象即可覆盖全部 15 个轨迹 family。

The \texttt{time} and \texttt{tokens} views of the same 325 trajectories share
only 7/10 top prompt categories (Spearman $\rho = 0.623$), and
\texttt{network}-tagged prompts rank 8th by time but 93rd by tokens.
% 同一 325 个轨迹的 \texttt{time} 和 \texttt{tokens} 视图仅共享 7/10 个顶级 prompt 类别（Spearman $\rho = 0.623$），且 \texttt{network} 标签 prompt 按时间排第 8、按 token 排第 93。
Thus, multiple weights expose bottlenecks that one metric would miss.
% 因此，多种权重暴露了单一指标会遗漏的瓶颈。

Figure~\ref{fig:flamegraph} shows the resulting \texttt{tokens}, \texttt{time},

predicate, stack fields, and weight function produces different
aggregates from the same input operation corpus.
% Figure~\ref{fig:flamegraph} 展示了 \texttt{tokens}、\texttt{time} 和 \texttt{files} 火焰图，说明仅改变选择谓词、栈字段和权重函数即可从同一输入 operation 语料产生不同聚合。
Together, these results answer RQ1. The capture-and-join path rejects concurrent

Selectable stack depths and

\subsection{RQ2: Problem Correspondence}
% RQ2：分析器输出是否对应真实问题？

RQ2 asks whether target-blind profiles place independently annotated problems
in groups a developer can inspect early. We run complete AgentProcessBench,
HINTBench, and TraceElephant workloads~\cite{agentprocessbench,hintbench,traceelephant}.
Of HINTBench's reported 629 trajectories, the released test snapshot used here
contains 536. A separate 80-trajectory validation snapshot selects one of 24
field orders before all 536 tests are scored.

Within each workload, \sys and raw-action grouping use identical operations
and the same benchmark-provided judge votes or localizer hits. The two methods
differ only in grouping. AgentProcessBench
averages judge votes within each group. For HINTBench and TraceElephant, every
root-to-frame stack prefix receives the 95\% Wilson lower bound~\cite{wilson1927}
of its member hits, and an operation inherits the maximum score among prefixes
containing it, with ties preserved.

We choose profiles, fields, and
scoring rules before revealing independent test targets. Each query is one
trajectory containing an annotated target. We report non-interpolated average
precision (AP) per query and mean average precision (MAP) across queries.
% RQ2 在完整的 AgentProcessBench、HINTBench 和 TraceElephant workload 上测试 target-blind profile 是否更早排列独立标注的问题。HINTBench 使用独立的 80-trajectory validation snapshot 从 24 个 field order 中选定一个，再评分全部 536 个 test。每个 workload 的 AgentProf 与 raw-action grouping 使用相同 operation 及 benchmark 提供的 judge vote 或 localizer hit，仅 grouping 不同。AgentProcessBench 在组内平均 judge vote；HINTBench 与 TraceElephant 为每个从根到 frame 的 stack prefix 计算成员 hit 的 95% Wilson lower bound，每个 operation 继承包含它的 prefix 中的最大分数并保留并列。profile、field 与 scoring rule 在打开独立 test target 前固定；每条含标注目标的 trajectory 是一个 query，评测每 query 的非插值 average precision（AP）及跨 query 的 mean average precision（MAP）。

\subsection{RQ3: Tag Accuracy}
% RQ3：标签有多准确？

RQ3 evaluates how accurately and consistently predeclared, target-blind
taggers and mappings recover independent task, phase, action, and
group-boundary annotations. Here, a \emph{tag} is an operation field produced by \sys, a
\emph{reference annotation} is benchmark-provided truth, and a predicted
group or boundary is structural output derived from tags. We compare predicted
task partitions, literal task-family and action tags, and group boundaries with
their reference annotations, then fold predicted OSWorld groups with their
original additive weights.
% RQ3 评估预先声明且不读取目标标注的 tagger 和 mapping 恢复独立 task、phase、action 与 group-boundary 标注的准确性和一致性。tag 是 AgentProf 生成的 operation 字段；reference annotation 是 benchmark 提供的真值；predicted group 或 boundary 是从 tag 派生的结构输出。本节比较预测 task partition、字面 task-family/action tag 和 group boundary 与对应 reference annotation，并使用原始可加权重折叠预测的 OSWorld group。

We test all 287 OSWorld-Human task-instance sessions~\cite{osworldhuman} with
complete group annotations, comprising 3{,}978 operations, 3{,}691 adjacent
pairs, and 2{,}042 groups.
% 我们首先测试所有具有完整人工分组标注的 OSWorld-Human session：287 个 task-instance session 中的 3,978 个 operation，共 3,691 个相邻对和 2,042 个人工独立标注的动作组。
For the supervised Bernoulli Naive Bayes predictor~\cite{mccallum-nigam-1998},
we fix the model family, nine input fields, adjacent-pair features, and training
procedure. Each session-held-out cross-validation fold fits its parameters and
threshold on training sessions and predicts every held-out session once.
% 我们评估一个监督式 Bernoulli Naive Bayes 相邻边界预测器。模型家族、用于构造相邻对特征的九个可见 operation 字段、特征构造和训练流程在评估前固定；每个 session-held-out cross-validation fold 只使用训练 session 拟合参数和选择阈值，并恰好预测每个 held-out session 一次。
Predicted boundaries become an ordinary group field that \sys projects and
folds through the Semantic Operation Stack Model's profile-construction path.
% 预测边界成为普通分组字段，\sys 随后通过 Semantic Operation Stack Model 的 profile-construction 路径投影并折叠该字段。

With the same five folds, label-free recurrence uses only the other sessions'
visible action transitions. Because we designed the recurrence rule after
inspecting earlier results on this corpus, we treat these results as
development evidence rather than independent cross-family confirmation.
% 我们还用相同的五个 session fold 运行内置 recurrence inducer：每个 held-out fold 仅使用其他 session 的可见 action 转移作为无标签参考。由于 recurrence 原理是在查看该语料的早期结果后选定的，我们将其作为机制开发证据，而非独立的跨 family 验证。
Optional reference-calibrated recurrence uses those training operations and
group annotations to fit one NPMI cutoff. Held-out folds contribute only
visible actions until predictions are fixed.
% 可选的 reference-calibrated recurrence 模式使用同一训练 fold 的 operation 及其 group 标注拟合一个 NPMI cutoff；held-out fold 在预测固定前只提供可见 action。

Three controls place a boundary after every operation, after a visible action
change, or after a visible phase change.
% 简单对照分别在每个 operation 后放置边界，或仅在可见 action 或 phase 字段变化时放置边界。

We report exact adjacent-boundary precision, recall, and F1, plus ordinary
per-operation B$^3$ partition F1~\cite{bagga-baldwin-1998-entity-based}, whose per-operation
predicted--human group overlap captures merging and fragmentation.
% 我们报告 exact adjacent-boundary precision、recall、F1，以及普通 per-operation B$^3$ partition F1；后者对每个 operation 的预测分组与人工分组重叠度求平均，同时反映合并与碎片化。

\subsection{Scope and Limitations}

RQ1 covers 20 fixed tasks under declared process/tool scope and all 405 failed
CodeTraceBench trajectories~\cite{li2026codetracer} reconstructable as official
operation sequences. Its 494.9 million mapped tokens cover operation-bearing
responses, not every released model call. Because this corpus influenced
constructor selection, its result is post-hoc support, not independent confirmation.

RQ3 tests Mind2Web/ScienceWorld partitions, a named backend over nine task
families and eight action tags, and session-held-out OSWorld-Human boundaries;
these measurements cover the named populations and declared tag sets.
% 离线 profile-construction evaluation 不含 capture、live-agent overhead、source adaptation 和 field/tag generation。RQ1 覆盖声明进程/工具范围内的 20 个固定任务，以及 released source 能生成官方 operation sequence 的全部 405 条失败 CodeTraceBench 轨迹；其中 4.949 亿 mapped token 覆盖包含 operation 的 response，而不是发布轨迹中的每个模型调用。CodeTraceBench 影响了当前 constructor 的选择，因此它是 post-hoc support 而非 independent confirmation。RQ3 在 Mind2Web/ScienceWorld 上确立 task partition，测量一个指定 backend 在九个声明的 task family 与八个 action tag 上的 accuracy，并在 OSWorld-Human 上确立 session-held-out group boundary；这些测量覆盖指定 population 和声明的 tag set。

\section{Related Work}
% 相关工作

\textbf{Agent observability.}
Platforms aggregate spans, metadata, and evaluations, while some derive
cross-trace categories or profile workflows~\cite{langsmith,langfuse,otel,
datadog-llmobs,langsmith-insights,nemo-agent-toolkit-profiler}. \sys instead
links effects to responsible actions and folds additive measures across
histories into selectable pprof profiles.
% Agent observability 平台收集 span、metadata 与 evaluation signal，并提供单次运行或群体 dashboard；部分系统派生跨 trace 类别，NeMo Agent Toolkit profiler 聚合 instrumented workflow 的 token、latency、bottleneck 与 concurrency。范围化的 AgentSight-to-\sys 路径将系统副作用连接到负责的 agent action；\sys 将其跨异构历史的可加度量折叠为可选 pprof profile。

\textbf{Systems profiling.}
pprof and flame graphs fold runtime stacks, while Perfetto queries trace
events~\cite{pprof,flamegraphs,perfetto}. \sys instead folds query-time semantic
stacks without code identities or runtime nesting.
% pprof 和 flame graph 折叠运行时调用栈以归因可加成本，Perfetto 查询并派生执行 trace event；这些工具从稳定代码标识和运行时嵌套开始。\sys 将其聚合原则迁移到 agent，并用可在查询时改变字段和权重的 semantic operation stack 替代运行时 stack。

\textbf{Agent diagnosis.}
AgentRx diagnoses failures, CodeTracer reconstructs states, and benchmarks
score faulty steps or agents~\cite{agentrx,li2026codetracer,agentprocessbench,
hintbench,traceelephant}. \sys instead profiles recurring categories that
accumulate resources or problems across trajectories.
% AgentRx 诊断执行失败，CodeTracer 重建层次化状态转移以支持定位与 replay；AgentProcessBench、HINTBench 和 TraceElephant 衡量方法是否识别故障 step 或 agent。\sys 回答互补的群体问题：哪些重复语义责任在跨轨迹中累积资源使用或问题，并将其表示为聚合 profile 而非另一种单次运行诊断。

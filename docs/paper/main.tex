\begin{abstract}
AI agents produce growing populations of multi-step execution histories.
% AI 智能体产生不断增长的多步骤执行历史集合。
Developers need population-level answers about where failures concentrate,
which workflows trigger unsafe effects, and which tasks consume the most
budget.
% 开发者需要群体级答案：故障集中在哪里、哪些工作流触发不安全副作用、哪些任务消耗最多预算。
Natural-language intent lacks stable cross-run identity, while native execution
nesting captures occurrence rather than a reusable hierarchy of semantic
responsibility.
% 自然语言意图缺少稳定的跨运行身份，而原生执行嵌套记录的是执行 occurrence，并不提供可复用的语义责任层次。
Existing tools trace runs and aggregate metadata, but do not recursively
construct this hierarchy while retaining source evidence and conserved
measures in a standard profile.
% 现有工具追踪运行并聚合 metadata，但不会递归构造这种层次，同时在标准 profile 中保留 source evidence 与守恒度量。
Agent observability needs profiling, not only debugging.
% 智能体可观测性需要 profiling，而不仅仅是 debugging。
\sys implements a \emph{semantic operation stack model}: recursive annotations
identify shared responsibilities over an ordered source tree, operation stacks
compose them with native evidence, and additive measures replay into standard
pprof-compatible profiles.
% \sys 实现语义 operation stack 模型：递归 annotation 在有序 source tree 上识别共享责任，operation stack 将其与原生 evidence 组合，可加度量则重放为标准 pprof-compatible profile。
We evaluate 405 human-staged CodeTraceBench trajectories, three complete
localization benchmarks, 287 OSWorld-Human sessions, four population case
studies, and four public cost workloads.
% 我们评估 405 条带人工 stage 的 CodeTraceBench 轨迹、三个完整 localization benchmark、287 个 OSWorld-Human session、四个 population case study 和四个公开成本 workload。
Direct Agent annotation raises ordinary B$^3$ F1 from 0.541 for raw action and
0.663 for recurrence to 0.764; profile refinement raises MAP over
benchmark-native diagnostics by 0.031, 0.107, and 0.117; and a TraceElephant
reader opens 53.0\% rather than 65.0\% of source evidence at equal ranking
quality.
% 直接 Agent 标注将普通 B$^3$ F1 从 raw action 的 0.541 和 recurrence 的 0.663 提升到 0.764；profile refinement 相对 benchmark-native diagnostic 将 MAP 分别提高 0.031、0.107 和 0.117；TraceElephant reader 在同等排名质量下只打开 53.0% 而非 65.0% 的 source evidence。
A profile-derived ToolSandbox repair reduces agent-side model tokens by
19.0\% across 69 confirmation pairs with non-inferior official similarity;
selective annotation reduces provider token volume by 20.4\% with complete
coverage and non-inferior structural quality; and, after marks are fixed,
\sys constructs a 27{,}765-operation profile in 1.16\,s.
% 由 profile 指导的 ToolSandbox 修复在 69 个确认 pair 上将 agent-side model token 降低 19.0%，且官方 similarity 非劣；选择性标注在完整覆盖和结构质量非劣下将 provider token volume 降低 20.4%；固定 mark 后，\sys 在 1.16 秒内构建 27,765-operation profile。
\end{abstract}

% AI agents increasingly orchestrate long-running, multi-step
% activities involving thousands to millions of interactions with
% users, tools, and system resources.
% To optimize the quality, safety, and cost of agents, developers must 
% analyze behaviors across thousands of runs to 
% find where failures concentrate, 
% locate the workflow phases triggering unsafe effects, 
% and identify the tasks that consumes most budget. 

% While performance profiling traditionally answers these questions 
% for classic software by aggregating resource consumption, 
% traditional profilers fail for agents.
% unlike traditional software where code paths provide a natural hierarchy for profiling, 
% agent behaviors are driven by unstructured natural language prompts 
% and lack deterministic execution stacks. 
% To bridge this gap, we propose the Semantic Operation Stack model. 
% First, we unify all heterogeneous agent activities (prompts, tool calls, 
% and system I/O) into a single structured record called an operation. 
% Second, we construct dynamic call stacks at query time by projecting 
% these operations onto user-defined semantic fields (e.g., intent $\rightarrow$ phase $\rightarrow$ action), merging identical sequences to generate flame graphs.

% We implement this model in AgentPProf, an offline profiler 
% with pluggable algorithms for intent attribution and stack construction, 
% compiling local agent trajectories into standard, pprof-compatible profiles.

\section{Introduction}
\label{sec:intro}

%% ¶1: Background + context
AI agents~\cite{sweagent,codex,claudecode,osworld} orchestrate multi-step
activities across a high-level intent layer (prompts, LLM calls, tool
invocations) and a low-level system-effects layer (process, file, and network
I/O), and production teams accumulate many such trajectories.
% AI 智能体~\cite{sweagent,codex,claudecode,osworld}编排跨越两层的多步骤活动（高层意图：提示词、LLM 调用、工具调用；低层系统副作用：进程、文件与网络 I/O），生产团队会积累大量此类轨迹。

%% ¶2: Problem
Developers lack population-level answers about agent quality, safety, and cost:
which task categories consume the most token budget, where failures concentrate
across workflows, and which behavioral patterns trigger unsafe system effects.
% 开发者缺少关于智能体质量、安全与成本的群体级答案：哪类任务消耗最多 token 预算、故障跨工作流集中在哪里、哪些行为模式触发不安全系统副作用。
Manual trajectory inspection is slow and costly~\cite{agentrewardbench}, and
LLM judging needs a separate evaluator pass per
run~\cite{agentrewardbench,llm-as-judge}.
% 人工轨迹检查缓慢且昂贵，而逐次运行的 LLM judging 需要单独执行一次 evaluator。

%% ¶3: Structural cause
Agent trajectories lack two structures needed for cross-run profiling:
responsibility lies in semantic categories such as task intent and tool
operation rather than stable function names, and natural-language prompts
provide no common identifier for shared intent.
% 智能体轨迹缺乏跨运行 profiling 所需的两个结构：负责实体是任务意图和工具操作等语义类别而非稳定函数名，且自然语言提示词不为共享意图提供共同标识符。
Native execution nesting may exist but provides no reusable cross-run hierarchy
of semantic responsibility: one prompt sequence may represent multiple tasks,
and one task may belong to a larger one.
% 原生执行嵌套可以存在，但不提供可跨运行复用的语义责任层次：一段提示序列可能表示多个任务，一个任务又可能属于更大任务。

%% ¶4: Existing solutions
Existing agent observability lacks this profiling abstraction: tools provide
rich tracing, metadata aggregation, and population
dashboards~\cite{langsmith,langfuse,otel,datadog-llmobs};
some derive hierarchical categories across traces and aggregate latency, cost,
or evaluation metrics~\cite{langsmith-insights,datadog-patterns}, and recent
research canonicalizes actions into process profiles or cross-run
graphs~\cite{traceprobe2026,graphectory2026,hodoscope2026,
tracegraph2026,actonomy2026,chief2026}. None combines recursively annotated
semantic responsibility, source-linked LLM/tool evidence, conserved additive
measures, and standard profiler output over the same histories.
% 现有工具提供 tracing、metadata 聚合与群体 dashboard，部分跨 trace 派生分层类别并聚合指标，近期工作把动作规范化为 process profile 或跨运行图；但没有同时结合递归标注的语义责任、source-linked LLM/tool evidence、守恒的可加度量和标准 profiler 输出。

%% ¶5: Model
Agent observability needs profiling, not only debugging.
% 智能体可观测性需要 profiling，而不仅仅是 debugging。
Our \emph{semantic operation stack model} provides this structure by projecting
resource measures onto stable semantic tags in an attribution hierarchy: source
nodes retain native session, prompt, LLM-call, and tool-call relations and
additive measures; an interchangeable backend names the session scope, each
user-prompt scope, and recursively refined intervals as operations; an
\emph{operation stack} emits the agent, those operations, and covered LLM/tool
evidence. Raw session and prompt IDs stay labels, not visible frames that
fragment aggregation (Figure~\ref{fig:motivating}).
% 我们的语义 operation stack 模型通过把资源度量投影到归因层次中的稳定语义标签上来提供该结构：source node 保留原生 session、prompt、LLM call、tool call relation 与可加度量；可替换 backend 将 session scope、每个 user-prompt scope 与递归细分区间命名为 operation；operation stack 输出 agent、这些 operation 及其覆盖的 LLM/tool evidence，raw session/prompt ID 仅作为 label，不作为打碎聚合的可见 frame。

%% ¶6: System
We implement this model in \sys, an offline profiler compiling local agent
trajectories into pprof-compatible profiles~\cite{pprof}
(Figure~\ref{fig:architecture}).
% 我们在 \sys 中实现此模型，这是一个把本地智能体轨迹编译为 pprof 兼容 profile 的离线 profiler（Figure~\ref{fig:architecture}）。
\emph{Operation annotation} lets an Agent, language model, or non-LLM backend
mark nested source intervals with shared semantic names, and \emph{stack
construction} deterministically emits
\texttt{agent}$\rightarrow$session-level operation$\rightarrow$prompt-level
operation$\rightarrow$recursive operations$\rightarrow$LLM call$\rightarrow$tool
call, retaining raw session and prompt identities as pprof labels for drilldown.
% Operation annotation 允许 Agent、语言模型或非 LLM backend 用共享语义名称标记嵌套 source interval；栈构造确定性地输出 agent→session-level operation→prompt-level operation→recursive operations→LLM call→tool call，raw session 与 prompt identity 作为 pprof label 保留供下钻。

%% ¶7: Results
Across 405 released CodeTraceBench trajectories reconstructable from
source~\cite{li2026codetracer},
direct Agent annotation reaches 0.764 ordinary B$^3$ F1 against human
stages, vs.\ 0.663 for multi-resolution recurrence and 0.541 for raw
action.
% 在 released source 能生成官方 operation sequence 的全部 405 条 CodeTraceBench 轨迹上，直接 Agent 标注相对人工 stage 的普通 B$^3$ F1 为 0.764，高于 multi-resolution recurrence 的 0.663 和 raw action 的 0.541。
Across three complete public workloads, AgentPProf refines benchmark-native
direct diagnostic ties and raises MAP by 0.031, 0.107, and 0.117,
respectively~\cite{agentprocessbench,hintbench,traceelephant}.
On TraceElephant, the same fixed hierarchy serves as a reading index:
a strong reader reaches the same ranking quality while opening less
source evidence than \sys-Raw, an information-matched raw-action ablation
(53.0\% versus 65.0\%).
% 在用于协议开发的三个完整公开 workload 上，AgentPProf 细化 benchmark-native direct diagnostic 的并列，并将 MAP 分别提高 0.031、0.107 和 0.117。
% 在 TraceElephant 上，同一固定层次也作为阅读索引：强 reader 达到统计持平的排名质量，同时打开的 source evidence 更少（53.0\% 对 65.0\%）。
In a ToolSandbox case study, a repair guided by a single profile reduces
agent-side model token volume by 19.0\% across 69 confirmation pairs while
meeting a fixed official-similarity non-inferiority margin~\cite{toolsandbox}.
% 在 ToolSandbox 案例中，由单个 profile 指导的修复在 69 个确认 pair 上将 agent-side model token volume 降低 19.0%，同时满足预设的官方相似度非劣效界限。
On 287 OSWorld-Human sessions~\cite{osworldhuman}, label-free
recurrence reaches 0.680 boundary F1 and 0.786 B$^3$ F1. On the AgentBoard and
ASE populations, task-family and action backends reach 0.695 and 0.498
macro-F1, respectively~\cite{agentboard,bouzenia-pradel-2025-trajectories}.
% 在 287 个 OSWorld-Human development session 上，无标签 recurrence 的 boundary F1 与 B$^3$ F1 为 0.680 和 0.786；在 AgentBoard 与 ASE population 上，task-family 与 action backend 分别达到 0.695 和 0.498 macro-F1。
On 32 confirmation exact \texttt{task\_name} clusters, selective annotation
uses 20.4\% fewer provider tokens than full-session annotation with complete
operation coverage and non-inferior B$^3$/boundary quality; after marks are
fixed, \sys constructs a 27{,}765-operation profile in 1.16\,s.
% 在 32 个确认 exact task_name cluster 上，选择性标注相对完整 session 标注少用 20.4% provider token，保持 operation 全覆盖且 B$^3$/boundary 质量非劣；固定 mark 后，\sys 用 1.16 秒 profile 27,765 个 operation。

\section{Background and Motivation}
\label{sec:background}

\subsection{LLMs and AI Agents}
% AI 智能体

A typical agent trajectory interleaves intent-layer activity (prompts, LLM
calls, and tool invocations for code execution, search, and file editing) with
lower-layer process, file, and network
effects~\cite{sweagent,codex,claudecode,agentsight}.
% 典型的智能体轨迹把意图层活动（提示词、LLM 调用以及代码执行、搜索、文件编辑等工具调用）与下层进程、文件和网络副作用交织在一起。
Trajectories repeat this cycle, and production teams accumulate many
trajectories~\cite{agentsight}.
% 单条轨迹会重复这一意图--副作用循环，生产团队也会积累大量轨迹。

\subsection{System Profiling}
% 系统 Profiling

Unlike single-execution debugging, profiling aggregates measurements to
attribute resources to responsible entities: traditional profilers sample
execution, attach each sample to its call stack, and fold identical
stacks~\cite{pprof,flamegraphs}.
% Profiling 通过聚合将资源消耗归因到负责实体，区别于单次执行调试：传统 profiler 采样执行、把每个样本附加到调用栈、并折叠相同栈。
Flame graphs~\cite{flamegraphs} and pprof~\cite{pprof} call graphs visualize
aggregate cost by width or node size, Pivot Tracing~\cite{pivottracing} groups
causally related measurements, and these tools start from stable code
identifiers and runtime stacks, although pprof can also promote
\texttt{tagroot}/\texttt{tagleaf} values to pseudo-frames~\cite{pprof}.
% 火焰图和 pprof 调用图以宽度或节点大小表示聚合开销，Pivot Tracing 对因果测量分组；这些工具从稳定代码标识符与运行时栈出发，pprof 也可将 \texttt{tagroot}/\texttt{tagleaf} 提升为伪帧。
Agent profiles must instead derive stable semantic fields and connect them to
downstream effects.
% 智能体 profile 则必须先推导稳定语义字段并连接到下游副作用。

\subsection{A Motivating Case: Two Flame Graphs}
% 动机案例：两张火焰图

\Description{Two flame graphs in the same visual style. The upper graph
descends from the Go HTTP server's connection handler into the request

Figure~\ref{fig:motivating} draws two standard pprof profiles with one
renderer. The upper profile is a Go HTTP service under load, captured by stock
\texttt{runtime/pprof}. The lower profile aggregates three independent agent
executions of one Git-deployment task, run by two agent frameworks over two
models.
% 图~\ref{fig:motivating} 用同一个渲染器绘制两个标准 pprof profile：上方是压测下的 Go HTTP 服务，由 stock \texttt{runtime/pprof} 采集；下方聚合了同一个 Git 部署任务的三次独立智能体执行，来自两个 agent framework 与两个模型。

Both panels are read by the same rules: a frame's width is its aggregate cost,
a parent's cost contains its children's, and identical stacks recorded at
different moments fold into one frame. The upper panel folds repeated
executions of \texttt{main.handleIngest} across thousands of requests; the
lower panel folds one \texttt{diagnose authentication} responsibility across
three separate runs. What differs is where the frame names come from. A call
stack supplies \texttt{net/http.(*conn).serve} for free at every sample.
Nothing in an agent trajectory supplies \texttt{diagnose authentication}: the
three runs express that intent through different prompts and different shell
commands, and the name exists only because the profiler constructed it.
% 两张图的读法完全相同：frame 宽度是聚合开销，父 frame 的开销包含其子 frame，不同时刻记录的相同栈折叠为同一个 frame。上图把数千次请求中重复执行的 \texttt{main.handleIngest} 折叠在一起，下图把一个 \texttt{diagnose authentication} 责任跨三次独立执行折叠在一起。差别在于 frame 名字从哪里来：调用栈在每个样本上免费提供 \texttt{net/http.(*conn).serve}，而智能体轨迹不会提供 \texttt{diagnose authentication}——三次执行用不同的提示词和不同的 shell 命令表达同一意图，这个名字只因为 profiler 构造了它才存在。

That constructed name is what makes the lower panel answerable. The three runs
spend 4.56 million tokens, and nearly half of that mass falls under one shared
authentication responsibility that both OpenHands executions return to after
control and fallback attempts, although none of the three runs ever
establishes the password-authenticated \texttt{git@localhost} path the task
asked for. Read as raw trace records, the same work is 105 separate calls
spread over six action kinds, 102 of them merely \texttt{run}, interleaved
with 97 unrelated operations. The Evaluation section measures this case, its
same-input organization controls, and whether the effect holds at population
scale.
% 正是这个构造出来的名字让下图变得可回答：三次执行共消耗 456 万 token，其中接近一半落在同一个共享的认证责任下，两次 OpenHands 执行在 control 与 fallback 尝试之后都回到该责任，但三次执行都没有建立任务要求的密码认证 \texttt{git@localhost} 路径。若按 raw trace record 阅读，同一批工作是散落在六种 action kind 中的 105 个独立 call（其中 102 个仅为 \texttt{run}），并与 97 个无关 operation 交织。评估章节测量该案例、其同输入组织对照，以及该效应是否在 population 规模上成立。

\subsection{Challenges for Agent Profiling}
% 智能体 Profiling 的挑战

Existing tools~\cite{langsmith,langfuse,otel} record agent events as
per-execution span trees for single-run debugging; AgentSight~\cite{agentsight}
bridges intent and system-effect layers by correlating extended Berkeley Packet
Filter (eBPF) system events with intercepted LLM traffic, but the resulting
recordings still lack aggregate profiling.
% 现有工具~\cite{langsmith,langfuse,otel}将智能体事件记录为按执行划分的 span 树以调试单次运行；AgentSight~\cite{agentsight} 通过关联 eBPF 捕获的系统事件与拦截的 LLM 流量来桥接意图层和系统副作用层，但生成的记录仍缺乏聚合分析能力。


Agent profiling faces two challenges. First, responsibility lies in semantic
categories such as task intent and workflow phase, not code paths.
% 在传统软件中，profiling 将开销归因到代码路径，但在智能体轨迹中，相关实体是语义类别（如任务意图和工作流阶段）。
Standards represent application-supplied span attributes~\cite{otel,
openinference}, but natural-language histories lack stable categories because
different prompts or tools can express the same intent.
% 现有标准可以在 span 中表示应用提供的属性，但自然语言历史不会自动提供稳定的责任类别：表达相同意图的两个提示词和工具调用可能使用不同字符串。

Second, agent trajectories lack a runtime call hierarchy for semantic attribution.
% 第二个挑战是智能体轨迹没有能够自动提供语义归因的运行时调用层次。
In CPU profiling, the stack attributes \texttt{malloc}'s cost simultaneously
to \texttt{parse}, \texttt{process}, and \texttt{main}~\cite{pprof,flamegraphs}.
% 在 CPU 分析中，调用栈决定了每个层级的归因：\texttt{malloc} 的开销同时属于 \texttt{parse}、\texttt{process} 和 \texttt{main}。
A prompt sequence may contain one or several tasks within a larger workflow,
yet no runtime mechanism marks its boundaries or attribution granularity.
% 一串提示词可能构成一个任务也可能是多个任务，一个任务可能是更大工作流的一部分，但没有运行时机制标记这些边界或决定在哪个粒度归因开销。
RQ1 evaluates how this missing hierarchy affects attribution, while RQ3
evaluates constructed groups and boundaries.
% RQ1 评估其归因后果，RQ3 评估构造出的 group 与 boundary。

\subsection{Design Requirements for Agent Profiling}
% 智能体 Profiling 的设计需求

Traditional profiling relies on three mechanisms that the call stack supplies automatically.
% 传统 profiling 依赖调用栈自动提供的三种机制。
Agent profiling requires all three without a call stack:
% 智能体 profiling 需要这三种机制，但必须在没有调用栈的情况下实现：

\begin{description}
\item[D1: Conserved multi-resource attribution.]
Each atomic source record must retain additive resource measures, such as
tokens, time, file effects, and network effects, so regrouping never changes
their total mass.
% 每个原子 source record 都必须保留 token、time、file effect 和 network effect 等可加资源度量，使重新分组不会改变资源总量。
\item[D2: Shared semantic identity.]
Responsibilities that recur in different sessions need the same short semantic
name so that their costs fold together rather than remaining session-local.
% 在不同 session 中重复出现的责任需要共享短小的语义名称，使其开销能够折叠，而不是停留在 session-local 视图中。
\item[D3: Hierarchy without evidence loss.]
The profiler must derive variable-depth semantic responsibility from the native
trace while retaining covered LLM/tool evidence as leaf frames and raw
session/prompt identities as drilldown labels.
% 分析器必须从原生 trace 推导可变深度语义责任层次，同时将被覆盖的 LLM/tool evidence 保留为叶节点 frame，并将 raw session/prompt identity 保留为下钻 label。
\end{description}

\section{Design}
% 设计
\label{sec:design}

\begin{figure*}[t]
\centering
\input{figures/fig-architecture.tex}
\caption{\sys pipeline. A source adapter preserves the native trace tree. An
Agent, LLM, or non-LLM backend writes the same small annotation contract. The
CLI validates and composes semantic paths with source evidence, folds one
additive resource measure, and emits only a standard pprof profile.}
\Description{A source adapter builds a session, prompt, LLM-call, and tool-call
tree. An interchangeable backend produces semantic annotations. The CLI
validates, composes, folds, and exports a pprof protobuf profile.}
\label{fig:architecture}
\end{figure*}

The design has three explicit objects: an ordered source tree, nested semantic
annotations, and a weighted pprof stack. A source adapter constructs the first
without discarding content or native parent relations; any annotation backend
constructs the second without rewriting source nodes; the deterministic
profiler validates both, emits agent and semantic-operation frames followed by
covered LLM/tool evidence, and folds equal paths into the third.
% 设计包含三个显式对象：有序 source tree、嵌套 semantic annotation 和加权 pprof stack。Source adapter 在不丢弃内容和原生 parent relation 的情况下构造第一个；任意 annotation backend 在不改写 source node 的情况下构造第二个；确定性的 profiler 校验两者，依次输出 agent、semantic-operation frame 与被覆盖的 LLM/tool evidence，并把相同 path 折叠成第三个。

This separation addresses D1--D3 directly: additive measures stay on source
nodes, shared semantic names create cross-session identity, and unique session,
prompt, call, and event IDs remain pprof labels. Switching from operation count
to tokens, time, file effects, or network effects replays the same annotation
and changes only stack width.
% 这种分离直接满足 D1--D3：可加度量保留在 source node 上，共享语义名称提供跨 session identity，唯一的 session、prompt、call 与 event ID 保留为 pprof label；从 operation count 切换到 token、time、file effect 或 network effect 时只重放同一 annotation 并改变 stack 宽度。

\subsection{Semantic Operation Stack Model}
% 语义 Operation Stack 模型
\label{sec:ops}

Let a source node be $n=(id,parent,kind,data,m)$ in an ordered forest.
The \textit{kind} is a session, prompt, LLM call, tool call, effect, or an
adapter-defined atomic event. The \textit{data} retains the source content
needed to interpret the event, and $m$ maps resource names to nonnegative
additive measures. Source-parent links encode observed execution structure;
they never encode an inferred semantic operation.
% Source node 是有序森林中的 $n=(id,parent,kind,data,m)$。kind 表示 session、prompt、LLM call、tool call、effect 或 adapter 定义的原子事件；data 保留解释事件所需的 source content；$m$ 将资源名称映射到非负可加度量。Source-parent link 编码观察到的执行结构，而不编码推断出的语义 operation。

Recursive annotation covers every source node with exactly one active semantic
leaf and its enclosing operation ancestors; let this path be $A(n)$, $g(n)$ the
agent identity inherited from the source root, and $E(n)$ the retained evidence
ancestry after removing raw session and prompt containers---normally the covered
LLM call, tool call, and effect. The emitted operation stack is
$\sigma(n)=\langle\textit{agent}:g(n)\rangle\mathbin{\|}A(n)\mathbin{\|}E(n)$
($\|$ denotes concatenation), with raw session and prompt IDs as labels
$\lambda(n)$ rather than visible frames, so equal prefixes aggregate across
sessions without losing the evidence to locate a contributing call or tool event.
% 递归 annotation 使用唯一 active semantic leaf 及其外层 operation ancestor 覆盖每个 source node，形成 $A(n)$；$g(n)$ 是从 source root 继承的 agent identity；$E(n)$ 是去除 raw session 与 prompt container 后保留的 evidence ancestry，通常包含被覆盖的 LLM call、tool call 与 effect。输出 operation stack 为 $\sigma(n)=\langle\textit{agent}:g(n)\rangle\mathbin{\|}A(n)\mathbin{\|}E(n)$（$\|$ 表示连接），raw session 与 prompt ID 作为 label $\lambda(n)$ 保留而不是可见 frame，因此相同前缀可跨 session 聚合，同时仍能定位贡献权重的 call 或 tool event。

\label{sec:stacks}
We formalize a resource profile as $(\varphi,\sigma,w_r)$: predicate
$\varphi(n)$ selects source nodes, $\sigma(n)$ supplies the composed stack, and
$w_r(n)=m_n[r]\geq0$ selects one additive resource. Folding merges equal stacks
and sums $w_r$. The default operation-count view assigns one unit to each
adapter-defined atomic operation; token, time, file-effect, and network-effect
views select their corresponding measures. Because $A$ and $E$ remain fixed,
changing $r$ changes only widths, not boundaries or semantic names.
% 资源 profile 是 $(\varphi,\sigma,w_r)$：谓词 $\varphi(n)$ 选择 source node，$\sigma(n)$ 给出组合后的 stack，$w_r(n)=m_n[r]\geq0$ 选择一种可加资源。折叠合并相同 stack 并累加 $w_r$。默认 operation-count view 为每个 adapter-defined atomic operation 赋一个单位；token、time、file-effect 和 network-effect view 选择相应度量。由于 $A$ 与 $E$ 固定，改变 $r$ 只改变宽度，而不改变 boundary 或语义名称。

\subsection{Recursive Operation Annotation}
% 递归 Operation 标注
\label{sec:intent}

The source adapter preserves an ordered tree of sessions, prompts, LLM calls,
and tool calls. Semantic operations are nested intervals over this tree rather
than replacements for its nodes.
% Source adapter 保留由 session、prompt、LLM call 和 tool call 构成的有序树；语义 operation 是该树上的嵌套区间，而不是对 source node 的替换。
An annotation at source node $s$ contains a semantic name, the start node of
its enclosing annotation, and the first source node after its interval.
The exclusive end may be omitted when the interval reaches its parent's end.
% 位于 source node $s$ 的 annotation 包含语义名称、其外层 annotation 的起始 node，以及该区间之后的第一个 source node；区间延伸到 parent 末尾时可以省略 exclusive end。
Every source root must begin a session-level operation, and every prompt must
begin a prompt-level operation. Further nested intervals define the
variable-depth suffix of the operation path. Equal path prefixes fold across
sessions; covered LLM/tool nodes remain below the path, while raw session and
prompt IDs remain labels for evidence drilldown.
% 每个 source root 必须开始一个 session-level operation，每个 prompt 必须开始一个 prompt-level operation；更深的 nested interval 定义 variable-depth operation suffix。相同 path prefix 跨 session 折叠，被覆盖的 LLM/tool node 保留在 path 下方，而 raw session 与 prompt ID 作为 label 保留供 evidence drilldown。

Annotation proceeds coarse to fine. A backend first names the complete session
and each user-prompt scope, then selects one interval whose current name hides
a useful responsibility change, marks source-visible boundaries, names the
resulting child intervals, and repeats only where another distinction helps; a
later iteration may rename, merge, or remove an earlier split.
% 标注从粗到细进行：backend 先命名完整 session 与每个 user-prompt scope，再选择当前名称掩盖有用责任变化的区间，标记 source-visible boundary，命名得到的 child interval，并只在另一层区分确有帮助时继续；后续迭代可重命名、合并或删除已有 split。
The default Agent-assisted backend reads source content and existing paths to
make these decisions. A plain language model, deterministic rules, change-point
methods, and the label-free recurrence constructor use the same annotation
contract, so the profiler does not depend on one model or inference service.
% 默认的 Agent-assisted backend 读取 source content 与当前 path 做出这些决策；普通语言模型、确定性规则、change-point 方法和无标签 recurrence constructor 使用相同 annotation contract，因此 profiler 不依赖单一模型或推理服务。

The evaluated Agent backend reads each trajectory's complete source-only packet
once and directly emits sparse complete-path marks at the transition points it
identifies, naming every enclosing responsibility. It chooses depth freely per
branch, with no cap or threshold. One ordinary format retry is allowed, after
which the deterministic root-prefix repair and canonicalization replay remain
unchanged downstream.
% 评测的 Agent backend 对每条轨迹只读取一次完整的 source-only packet，并在它识别出的 transition point 直接发出 sparse complete-path mark，同时命名每一层 enclosing responsibility。每个 branch 的深度可自由选择，不设上限或阈值。协议允许一次普通 format retry，之后的确定性 root-prefix repair 与 canonicalization replay 保持不变。
The complete backend interface is this input/output contract:
% 完整的 backend 接口就是如下输入/输出契约：
\begin{quote}\small
\emph{Input:} one trajectory's source-only packet---each turn's visible
prompt, command, and output summary; no labels.\\
\emph{Action:} read once; emit a mark wherever the responsibility changes.\\
\emph{Output:} sparse complete-path marks, e.g.\\
{\ttfamily turn 1: [deploy git server]\\
turn 4: [deploy git server, diagnose SSH access]\\
turn 9: [deploy git server, diagnose SSH access, test PAM]\\
turn 15: [deploy git server, verify web endpoint]}\\
---one line only where the path changes; free depth; names are one to
three action-first words.
\end{quote}
% 输入：一条轨迹的 source-only packet——每个 turn 的可见 prompt、命令与输出摘要，无任何标签。动作：通读一遍，在责任变化处发出标记。输出：稀疏 complete-path mark（仅在路径变化处一行；深度自由；名字为 1--3 个动词优先的词）。

The complete CodeTraceBench direct-backend run uses independent Codex Agent
workers under one fixed source-only annotation instruction. Each worker reads
its trajectory once, with official stages and outcomes unavailable until all
405 trajectories are materialized; recurrence assignments and scores are
likewise hidden. Validation is followed by the unchanged deterministic
root-prefix representation repair (the appendix (\emph{Operation-Identity Canonicalization})) and
source-only canonicalization replay before folding.
% 完整 CodeTraceBench direct-backend 运行由多个独立 Codex Agent worker 按同一份固定 source-only annotation instruction 执行。每个 worker 只读取一次自己的轨迹；全部 405 条轨迹物化前，官方 stage 与 outcome 均不可见，recurrence assignment 与 score 同样隐藏。验证后沿用不变的确定性 root-prefix 表示修复（附录）与 source-only canonicalization replay，再进行折叠。

For the RQ4 input-cost comparison, a selective adapter keeps the complete
turn skeleton but attaches full visible results only to a deterministic
source-selected subset; the same one-call output contract, validation,
canonicalization, and downstream folding then apply
(the appendix (\emph{Selective Annotation Protocol})).
% 在 RQ4 输入成本对比中，选择性 adapter 保留完整 turn skeleton，但只为确定性 source-selected 子集附加完整可见结果；随后沿用相同的一次调用输出契约、校验、规范化与下游折叠（附录“选择性标注协议”）。

\section{Implementation}
% 实现
\label{sec:impl}

\paragraph{Input reconstruction.}
% 输入重建。\sys 是实现该模型的离线 Rust CLI（Figure~\ref{fig:architecture}）。
\sys is an offline Rust CLI implementing this model
(Figure~\ref{fig:architecture}). Source-specific adapters reconstruct an
ordered tree from local Codex and Claude Code histories,
AgentSight~\cite{agentsight} recordings, or public trajectory datasets,
preserving replay-stable node IDs, source content or readable references,
native parent links, input order, and additive measures. Structured operation
JSONL is materialized as adapter-defined atomic source nodes without inventing
missing prompt or call relations.
% \sys 是实现该模型的离线 Rust CLI（Figure~\ref{fig:architecture}）。Source-specific adapter 从 Codex 与 Claude Code 本地 history、AgentSight recording 或公开 trajectory dataset 重建有序树，保留 replay-stable node ID、source content 或可读引用、原生 parent link、输入顺序及可加度量；结构化 operation JSONL 被物化为 adapter-defined atomic source node，不虚构缺失的 prompt 或 call relation。

\paragraph{Annotation workspace.}
% Annotation workspace。
The backend reads \texttt{trace.jsonl} and writes only \texttt{annotation.json}:
the former retains source content, source-parent links, additive measures, and
the current derived path; the latter maps source start IDs to \texttt{tag},
semantic \texttt{parent}, and exclusive \texttt{next}. \sys validates that
references exist and intervals are nested, noncrossing, and collectively cover
every source node, then atomically updates derived paths and the folded
aggregate.
% Backend 读取 \texttt{trace.jsonl} 且只写 \texttt{annotation.json}：前者保留 source content、source-parent link、可加度量和当前派生 path，后者将 source start ID 映射到 \texttt{tag}、语义 \texttt{parent} 与 exclusive \texttt{next}；\sys 校验引用存在、区间嵌套不交叉且共同覆盖每个 source node，再原子更新派生 path 与 folded aggregate。
Nonblocking hierarchy warnings flag a recursive operation with only one
explicit semantic child, a large flat fan-out with little recursive refinement,
or an optional semantic leaf spanning at least eight tool calls---exposing
redundant, prematurely flat, or coarse annotations without forcing artificial
depth or blocking generation.
% 非阻塞 hierarchy warning 标记只有一个显式 semantic child 的递归 operation、几乎没有进一步递归的大型 flat fan-out，以及覆盖至少八个 tool call 的可选 semantic leaf；这些诊断暴露冗余、过早扁平化或过粗的 annotation，但不强制虚假深度，也不阻塞生成。

\paragraph{Non-LLM recurrence backend.}
% 非 LLM recurrence backend。
The inducer scores adjacent action transitions by normalized pointwise mutual
information~\cite{bouma2009npmi} and calibrates a label-free cutoff with
occurrence-weighted two-means~\cite{macqueen1967}, treating detailed recurrence
as continuity that can remove but never add a coarse boundary; an optional
reference-calibrated mode fits one scalar cutoff on disjoint reference groups
(the appendix (\emph{Recurrence Backend Details})).
% inducer 用 NPMI 为相邻 action 转移评分，并用按出现次数加权的二均值校准无标签阈值；detail 连续性只能删除而不能新增粗边界；可选的 reference-calibrated 模式在不重叠参考分组上拟合单一阈值（附录）。

\paragraph{Profile export.}
% Profile 导出。
\sys emits one pprof protobuf profile for existing tools such as
\texttt{go tool pprof}; it does not add a visualization frontend or a second
export format.
% \sys 只输出一个供 \texttt{go tool pprof} 等现有工具读取的 pprof protobuf profile；它不增加可视化前端或第二种导出格式。

\paragraph{Privacy.}
% 隐私。
Workspace construction, validation, folding, materialization, and replay
run entirely on the local machine, and profiles carry only short semantic
names, bounded text previews, and numeric measures as labels. Automatic
annotation with a hosted model backend sends the preview-truncated packets
to that provider; annotation with the local recurrence backend or a local
model keeps every byte on the machine. Nothing else leaves the machine
unless the user shares the profile.
% Workspace 构建、校验、折叠、物化与重放完全在本机运行；profile 仅携带短语义名称、有限文本预览与数值度量作为 label。使用托管模型 backend 做自动标注时，截断后的 packet 会发送给该提供方；使用本地 recurrence backend 或本地模型则全程不出本机。除非用户主动分享 profile，任何其他内容都不离开本机。

\paragraph{Research questions.}
% 研究问题。
The evaluation addresses four research questions:
% 评估回答四个固定的论文级研究问题：

\subsection{RQ1: Does Semantic Profiling Improve Resource Attribution?}
% RQ1：多资源归因。

RQ1 asks whether semantic profiling improves resource attribution. We test one
necessary consequence: whether a fixed semantic hierarchy reveals materially
different bottlenecks when the additive resource measure changes. The source
population contains 41 real long-horizon agent trajectories, 3{,}146
source-native turns, and 5{,}750 operations, including three independent
executions of one Git-deployment task whose 735 source nodes receive 96
recursive annotations; the resulting hierarchy reaches semantic depth five
without a fixed limit, and the CLI reports no unary or flat-fan-out warning and
27 advisory coarse-leaf warnings.
% RQ1 问 semantic profiling 是否改善资源归因。这里测试一个必要后果：固定语义层次在切换可加资源度量时是否暴露实质不同的瓶颈；source population 含 41 条真实 long-horizon agent 轨迹、3,146 个 source-native turn 和 5,750 个 operation，其中包含同一 Git 部署任务的三次独立执行（其 735 个 source node 获得 96 个递归 annotation）；所得层次在无固定上限下达到 semantic depth 5，CLI 不报告 unary 或 flat-fan-out warning，并给出 27 个 coarse-leaf warning。
This establishes the multi-resource attribution capability on a repeated
real task.
% 该实验在一个重复真实任务上建立了多资源 attribution 能力。
\paragraph{Case Study 1: Long-Horizon Agent Diagnosis.}
This is the case previewed in the Background and Motivation section. A stock-pprof focus
query retains all three executions of the repeated Git-deployment task rather
than selecting one trace, and Figure~\ref{fig:flamegraph} replays that one
fixed hierarchy under both additive measures.
% 这是背景与动机章节预览的案例。stock pprof focus query 保留该重复 Git 部署任务的全部三次执行而非挑选单条轨迹，图~\ref{fig:flamegraph} 在两种可加度量下重放同一个固定层次。

The focused task contains 489 operations and 4{,}558{,}192 provider-reported

mainly to Terminus2, while the token view attributes nearly half of it to the
authentication responsibility described in the Background and Motivation section, which
source drilldown resolves to specific unfinished work.
% 该聚焦任务包含来自 OpenHands/Claude、OpenHands/DeepSeek 与 Terminus2/DeepSeek 的 489 个 operation 和 4,558,192 个 provider-reported token：按数量 Terminus2 占 56.24%、OpenHands 占 43.76%，按 token OpenHands 占 86.62%。重复的 \texttt{diagnose authentication} operation 直接包含 97 个 operation 和 1,936,828 个 token，其完整递归子树包含 105 个 operation 和 2,103,587 个 token（占聚焦任务的 21.47\% 和 46.15%）。同一未变层次还把全部 489 条 evidence row 映射到定义的 elapsed-time 宽度并精确保守 3,982 秒；该子树持有 1,492 秒，即 elapsed time 的 37.47%。其归因份额因此从 count 的 21.47% 经 time 的 37.47% 上升至 token 的 46.15%；仅改变度量就使该份额变化超过两倍。因此度量的选择改变了主导责任：count 视图把该任务主要归因于 Terminus2，而 token 视图把接近一半归因于背景与动机章节描述的认证责任，source drilldown 可将其定位到具体的未完成工作。
As a post-hoc organization control, we replay the same 489 source operations and
both weights over common \texttt{project, agent} prefixes and \texttt{call, tool}
leaves with three middle organizations---native (\texttt{session, prompt}), coarse (\texttt{action kind, raw action}), or semantic---so all six profiles conserve
exact mass and open in stock pprof. The SSH members scatter across 105 native
calls and span six coarse action kinds (largest branch 39.42\% of their tokens),
with 102 of 105 merely \texttt{run} alongside 97 unrelated operations. Only the
semantic organization yields one focusable cross-run responsibility that an
operation-count view understates; fixed from the case above, this control
measures organization.
% 作为 post-hoc 同输入组织对照，我们用相同 489 个 operation 与权重，在固定 project/agent prefix 与 call/tool leaf 下重放 native、coarse、semantic 三种中间组织，所得六个 profile 均精确保守质量。SSH responsibility 在 native 中分散到 105 个 call，在 coarse 中跨六个 action kind（最大分支仅 39.42%），且 102/105 仅为 run 并混入 97 个无关 operation；只有 semantic 组织给出单一可聚焦的跨运行责任，暴露 operation count 明显低估的瓶颈。该 responsibility 取自前一案例，故此对照衡量组织差异。
This repeated real task supports RQ1's multi-resource attribution hypothesis:
one shared responsibility path reunites the SSH work across executions, while
the selected additive measure changes its attributed importance.
% 这个重复的真实任务支持 RQ1 的多资源归因假设：一个共享 responsibility path 跨执行重聚 SSH 工作，而所选可加度量会改变其归因重要性；我们不声称某一种资源度量普遍支配其他度量。
Separately, real AgentSight eBPF recordings replay the same way: the R114
population folds all 1{,}520 process/file effects under task responsibilities
through the recorded wrapper tool with exact conservation, demonstrating the
system-effect layer end to end.
% 另外，真实 AgentSight eBPF recording 以相同方式重放：R114 population 通过记录的 wrapper tool，把全部 1,520 个 process/file effect 折叠到 task responsibility 下并精确保守，从而端到端展示 system-effect 层。

The same population-scale behavior holds on the frozen 440-session
AgentRewardBench hierarchy (7{,}229 operations and 51{,}904{,}621
provider-reported tokens, both conserved exactly): replaying it ranks the same
operations once by operation count and once by tokens. Over the 77 of 125 tasks
with at least three distinct operations, mean per-task Kendall's
tau-b~\cite{kendall1938} is 0.886 (10{,}000-draw task-cluster bootstrap 95\%
interval [0.857, 0.915]) and Spearman's rho~\cite{spearman1904} is 0.935
[0.917, 0.953]; the pooled population ranking agrees at tau-b 0.929. One fixed
hierarchy therefore replays across measures with exact conservation and stable
dominant responsibilities for most web-scale tasks, though 10 of the 77
rankable tasks fall below tau-b 0.7 and the long-horizon Git case above shifts
attributed importance by more than a factor of two. Multi-measure replay is
thus stable in the common case and decision-changing in a material
minority---exactly the regimes where selecting the measure changes the
engineering decision.
% 在 frozen 的 440-session AgentRewardBench 层次（7,229 个 operation 与 51,904,621 个 provider-reported token，两者均精确保守）上，同一固定层次在两种度量下重放：分别按 operation count 与 token 对相同 operation 排序。在 125 个 task 中至少有三个不同 operation 的 77 个上，mean per-task Kendall's tau-b 为 0.886（10,000 次 task-cluster bootstrap 95% 区间 [0.857, 0.915]），Spearman's rho 为 0.935 [0.917, 0.953]；pooled population ranking 的 tau-b 为 0.929。因此一个固定层次可跨度量重放且精确保守，多数 web-scale task 的主导职责保持稳定，但 77 个可排序 task 中有 10 个 tau-b 低于 0.7，且上述 long-horizon Git case 的归因重要性变化超过两倍——度量选择会改变工程决策的情形，正是 multi-measure replay 的价值所在。

\subsection{RQ2: Does Profiler Output Correspond to Real Problems?}
% RQ2：分析器输出是否对应真实问题？

RQ2 asks whether target-blind profiler output corresponds to independently
annotated real problems. We answer at four levels: a population-scale
differential case whose recovery signal matches expert looping labels, a
supplement test over three complete localization benchmarks, a reading-index
study measuring how much source evidence a reader must open, and a repair case
with held-out before/after executions.
% RQ2 问 target-blind profiler 输出是否对应独立标注的真实问题。我们在四个层次上回答：population 尺度的差分案例（其 recovery 信号对应专家 looping 标注）、三个完整 localization benchmark 上的补充测试、测量 reader 需要打开多少 source evidence 的阅读索引研究，以及包含隔离前后执行的修复案例。

\paragraph{Case Study 2: Differential Profiling at Scale.}
% 案例研究 2：大规模差分 profiling。

We aggregate AgentRewardBench's~\cite{agentrewardbench} complete mixed-outcome population,
not one favorable trace pair: 440 real trajectories over 125 tasks yield 338 bad--good
pairs (24/102/144/68 from AssistantBench, VisualWebArena, WebArena, WorkArena), with the
202 successful and 238 unsuccessful sessions reusing across pairs (pair-occurrence weighted).
% 我们聚合 AgentRewardBench 的完整 mixed-outcome population（而非单个有利 trace pair）：125 个任务的 440 条真实轨迹产生 338 个 bad--good pair（AssistantBench/VisualWebArena/WebArena/WorkArena 分别贡献 24/102/144/68），202 条成功与 238 条失败 session 跨 pair 复用，profile 按 pair occurrence 加权。

Before opening outcomes or expert annotations, three automatic Agent workers
produce 2{,}131 sparse recursive annotations over all 7{,}229 source
operations. The resulting hierarchy reaches semantic depth four before its
LLM-call and tool-call evidence leaves. We then fold all 338 bad members and
all 338 good members into one signed operation-count pprof, preserving the same
source occurrences on both the recursive and fixed-chain projections.
% 在读取 outcome 或专家 annotation 之前，三个 automatic Agent worker 为全部 7,229 个 source operation 生成 2,131 个稀疏递归 annotation；所得层次在 LLM-call 与 tool-call evidence leaf 之前达到 semantic depth 4。随后我们将全部 338 个 bad member 和 338 个 good member 折叠进一个 signed operation-count pprof，并保证递归投影与 fixed-chain 投影使用完全相同的 source occurrence。

Formally, the signed profile is the difference of two nonnegative profiles,
$(\varphi,\sigma,w_r)_{\mathrm{bad}}-(\varphi,\sigma,w_r)_{\mathrm{good}}$;
each side satisfies the model's nonnegative additive-measure definition, and
pprof renders the subtraction as positive and negative sample values.
% 形式上，signed profile 是两个非负 profile 之差 $(\varphi,\sigma,w_r)_{bad}-(\varphi,\sigma,w_r)_{good}$：两侧各自满足模型的非负可加度量定义，pprof 将该差渲染为正负 sample 值。

The aggregate contains 7{,}366 bad-side and 3{,}780 good-side operation

We test whether this visible recovery structure corresponds to an independent
problem rather than merely reflecting more steps. For each trajectory, recovery
exposure is the fraction of source operations whose path contains the shared
recovery responsibility. Among 435 trajectories with consensus expert looping
labels, this score---computed per unique trajectory after deduplicating
pair reuse, and therefore unaffected by pair-occurrence multiplicity---obtains AP .634 at prevalence .398; a 10{,}000-draw
task-cluster bootstrap places AP minus prevalence in [.181,.293]. A registered
fixed-chain repeated/error projection obtains AP .656, and the
recursive-minus-fixed interval [-.107,.061] does not establish detector
superiority. The two projections answer different questions: the fixed
indicator only flags where repeated/error steps occur, whereas the recursive
profile decomposes the same responsibility into verification, search,
navigation, retry, and inspection with session/call drilldown---a
source-drillable explanation of \emph{where} recovery accumulates that
independently corresponds to expert-identified looping.
% 我们进一步检验该可见 recovery 结构是否对应独立问题，而不仅仅反映更多 step。每条轨迹的 recovery exposure 定义为路径中包含共享 recovery responsibility 的 source operation 比例。在 435 条具有一致专家 looping label 的轨迹上，该 score 的 AP 为 .634，prevalence 为 .398；10,000 次 task-cluster bootstrap 给出的 AP-minus-prevalence 区间为 [.181,.293]。注册的 fixed-chain repeated/error 投影 AP 为 .656，recursive-minus-fixed 区间 [-.107,.061] 不支持 detector superiority。因此递归 profile 的价值是可下钻地解释 recovery 在何处累积，并且该 exposure 独立对应专家识别的 looping。

This case answers RQ2 at collection scale: a target-blind recursive profile
exposes failed-side recovery and successful-side completion under shared
responsibilities, and its recovery signal corresponds to an independently
annotated real problem.
% 该案例在集合尺度上回答 RQ2：target-blind 递归 profile 在共享职责下暴露失败侧 recovery 与成功侧 completion，且 recovery signal 对应独立标注的真实问题。

\paragraph{Supplementing benchmark-native diagnostics.}
% 补充 benchmark 原生诊断。
We next test whether target-blind profiles supplement per-trajectory fault
localization, a debugging-native task, on the complete AgentProcessBench,
HINTBench (the complete released test snapshot, 536 of the paper-reported 629
trajectories), and TraceElephant
workloads~\cite{agentprocessbench,hintbench,traceelephant}.
% 我们接着测试 target-blind profile 是否补充逐轨迹故障定位这一 debugging 原生任务，运行完整的 AgentProcessBench、HINTBench（完整的 released test snapshot，629 个论文报告轨迹中的 536 个）与 TraceElephant workload。
Within each workload, operations, target-blind paths, benchmark predictions,
and scoring are fixed before loading test targets
(the appendix (\emph{RQ2 Scoring Details})).
% 各 workload 中，operation、target-blind path、benchmark 预测与评分规则均在加载 test target 前固定（细节见附录~the appendix (\emph{RQ2 Scoring Details})）。

\emph{direct diagnostic}---the per-operation output of a benchmark-native
process judge (AgentProcessBench risk units) or trajectory localizer (HINTBench,

before naming the responsible agent and decisive step. The candidate
(Direct+AgentPProf) ranks operations lexicographically by (\emph{direct

from MAP because AP is undefined without a relevant item.

\paragraph{Profile-guided reading on TraceElephant.}
On the complete 220 target-bearing TraceElephant queries, a fixed external
Grok~4.5~\cite{grok45} CLI reader (the CLI default model, invoked
single-turn with tools and subagents disabled) receives target-blind packets---task text, operation
IDs, and source-visible content---with unranked operations appended in
original order deterministically and one single-turn call per stage; full-trace
reading reaches MAP .502 versus .209 for the benchmark's Direct-only diagnostic
and .326 for Direct+AgentPProf at a mean 12{,}615 input tokens per query.
% 在完整的 220 个带 target 的 TraceElephant query 上，固定的外部 Grok 家族 CLI reader 接收 target-blind packet（任务文本、operation ID、source-visible 内容），未排名 operation 按原始顺序确定性附加、每个 stage 单轮调用；全 trace 阅读达到 MAP .502，而 benchmark 的 Direct-only 诊断为 .209、Direct+AgentPProf 为 .326，平均每个 query 12,615 输入 token。
A two-stage profile-guided variant first shows only the semantic operation
skeleton, with no source content, and the reader selects at most five groups;
stage two then opens only the selected groups' evidence.
% 两阶段 profile-guided 变体首先只展示 semantic operation 骨架（无 source 内容），reader 最多选择 5 个 group；第二阶段只打开所选 group 的 evidence。

stage-one selections never fell back to a default; the five-group budget
saturated on 99.5\% of queries, and every selection miss was an absence from
the reader's ordered choices rather than a budget cutoff---re-parsing the
uncapped stage-one responses shows the reader proposed more than five groups
on zero of 220 queries, and every missed target group was entirely absent
from its ordered selection.
% 它达到 MAP .455，同时只打开 53.0\% 的 source 内容，且第一阶段选择从未回退到默认值；五组预算在 99.5\% 的 query 上被用满，且所有选择遗漏都是 reader 排序中的整体缺席而非预算截断——重新解析未截断的第一阶段响应显示，reader 在 220 个 query 中的 0 个上提出超过五组，且每个遗漏的 target group 都完全缺席于其有序选择。
Under the information-matched \sys-Raw skeleton, ranking quality is
statistically unchanged (MAP .465; paired delta $+.010$ [$-.021$, $+.042$]).
% 在信息匹配的 \sys-Raw 骨架下，排名质量在统计上不变（MAP .465；配对差异 +.010 [-.021, +.042]）。
But the reader opens significantly more content: 65.0\% versus 53.0\%, paired
delta $+.120$ [$+.103$, $+.137$], and $2.80$ [$1.96$, $3.60$] more evidence
operations.
% 但 reader 打开显著更多的内容：65.0\% 对 53.0\%，配对差异 +.120 [+.103, +.137]，且多 2.80 [1.96, 3.60] 个 evidence operation。
Semantic naming's measured contribution in this regime is attention
concentration at equal quality.
% 在此机制下 semantic naming 测得的贡献是同等质量下的注意力集中。
A per-query full read is bounded by the model context window: populations
such as the 4{,}558{,}192-token repeated Git task cannot be read whole,
whereas skeleton-guided reading stays available at any trace length once
the profile exists (construction itself proceeds per trajectory over
preview-bounded packets).
% 单 query 全量阅读受限于模型上下文窗口：诸如 4,558,192-token 的重复 Git 任务这类种群无法整体阅读，而骨架引导的下钻在任何 trace 长度下都可用。

question---whereas the hierarchy is constructed once and replayed across
queries and measures.
% reader 是 query-specific——每个问题都重新阅读整条轨迹——而层次结构只构造一次，跨 query 与 measure 复用。

\paragraph{Case Study 3: Guiding a Real Repair.}
% 案例研究 3：指导实际修复。
The preceding experiments establish correspondence and inspection value; this
case tests whether a profile finding can guide an effective repair.
A standard \sys profile over eight ToolSandbox scenarios isolates a recurring
call-ID syntax failure (5/21 tool operations).
A profile-only analyst---receiving only the pprof output, not raw
traces---identifies the compatibility-layer boundary as the repair target.
The derived one-line fix removes all syntax failures and, on 23 held-out
confirmation scenarios (69 BEFORE/repair pairs), reduces agent-model tokens
by 19.0\% while passing a fixed $-.05$ non-inferiority margin on official
similarity (details in Appendix~\ref{app:rq2-repair}).
% 前述实验建立对应关系和检查价值；本案例检验 profile 发现能否指导有效修复。
% 一个覆盖 8 个 ToolSandbox 场景的标准 \sys profile 隔离出重复的 call-ID 语法失败（5/21 tool operation）。
% 一个只接收 pprof 输出、不接触原始 trace 的 profile-only analyst 将 compatibility-layer 边界定为修复目标。
% 导出的单行修复消除所有语法失败，并在 23 个 held-out 确认场景（69 个 BEFORE/repair pair）上将 agent-model token 降低 19.0%，同时通过预设的 -0.05 官方 similarity 非劣效界限（详见附录）。

\section{Conclusion}
% 结论

Agent observability needs profiling, not only debugging. \sys recursively
annotates semantic responsibility over source-native traces, folding covered
evidence under shared cross-run operation stacks. Its profiles expose
resource-dependent bottlenecks and success--failure differences, improve
CodeTraceBench stage-partition agreement, supplement benchmark-native direct
diagnostics on all three localization workloads, and recover OSWorld-Human
groups at 0.680 boundary F1 and 0.786 B$^3$ F1. A profile-derived ToolSandbox
repair reduces later agent-side model token volume by 19.0\% with
non-inferior official similarity, while selective evidence reduces annotation
provider tokens by 20.4\% with complete coverage and non-inferior structural
quality. After a one-time annotation pass, \sys builds a 27{,}765-operation
profile in 1.16 seconds and replays it across measures, making population
profiling practical alongside per-run debugging.
% 智能体可观测性需要 profiling，而不仅仅是 debugging。\sys 在 source-native 轨迹上递归标注语义责任，把被覆盖 evidence 折叠到跨运行共享的 operation stack 下。其 profile 暴露依赖资源的瓶颈与成功--失败差异，改进 CodeTraceBench stage-partition agreement，在三个完整 localization workload 上补充 benchmark-native direct diagnostic，并在 OSWorld-Human 上恢复 0.680 boundary F1 与 0.786 B$^3$ F1。由 profile 导出的 ToolSandbox 修复在官方 similarity 非劣下减少后续 agent-side model token volume 19.0%，选择性 evidence 在完整覆盖和结构质量非劣下减少 annotation provider token 20.4%；固定 mark 后，\sys 用 1.16 秒构建 27,765-operation profile，使群体级 profiling 与逐次调试并存。

\subsection{Recurrence Backend Details}
\label{app:recurrence}

The Rust inducer counts adjacent action transitions in reference sessions and
scores each transition by normalized pointwise mutual information (NPMI),
$\mathrm{NPMI}(a,b)=
\ln[p(a,b)/(p_L(a)p_R(b))]/-\ln p(a,b)$, with all three probabilities defined
over the same transition sample space~\cite{bouma2009npmi}.

Occurrence-weighted one-dimensional $k$-means with $k=2$~\cite{macqueen1967}
initializes at the minimum and maximum scores, assigns distance ties to the
lower center, and uses the converged midpoint as a global cutoff. The inducer
applies the same procedure to action-changing transitions for a second cutoff.
Same-action pairs use the global cutoff, whereas different-action pairs use the
smaller cutoff, which can remove a boundary produced by the global rule but
cannot add one. When every reference and target operation also has a nonempty
\texttt{action\_detail}, the inducer fits the same recurrence model to the
compound signature. Detailed continuity may remove a coarse boundary but can
never add one. Missing, unseen, or weak detail falls back exactly to the coarse
decision. Segment names remain coarse run-length-compressed action sequences.
The inducer reads only session identity, input order, action, and optional
action detail, not target annotations or resource weights.
% Rust inducer 统计参考 session 中的相邻 action 转移，并用 NPMI 评分；所有概率来自同一转移样本空间。按出现次数加权的一维 k-means（k=2）从最小和最大分数初始化，将距离相同的点分到较低中心，并用收敛后两个中心的中点作为全局阈值；在 action-changing occurrence 上进行同样校准得到 cross-action 阈值。相同 action 使用全局阈值，不同 action 使用两者中较小者。reference 与 target 均有完整 action_detail 时，构造器对复合 signature 使用相同 recurrence 模型；detail continuity 只能删除粗边界而不能新增，缺失、未见或弱 detail 精确回退到粗决策。segment 名称仍只使用粗 action。评分标签与资源权重不参与构造。

An optional reference-calibrated recurrence mode uses the same NPMI score but
selects one scalar cutoff that maximizes per-operation B$^3$ F1 on disjoint
reference groups. The mode enumerates score intervals, resolves exact ties
toward the smallest cutoff, and never reads target groups. Label-free
$k$-means remains the default.
% 可选的 reference-calibrated recurrence 模式保持同一 NPMI score，并在与目标不重叠的参考分组上选择使每个 operation 等权的 B$^3$ F1 最大的单一阈值。它枚举有限 score interval，在完全平局时选择最小阈值，且不读取目标分组；无标签 k-means 规则仍是默认模式。

\subsection{Operation-Identity Canonicalization}
\label{app:canonicalization}

Before folding, one fixed source-only action--object map canonicalizes the
Agent annotation's display identity. A boundary-safe refinement retains a canonical action and
the minimum source words needed whenever two adjacent paths would otherwise
become equal; unresolved collisions fail closed. Equal canonical names receive
one stable operation ID across sessions. The complete replay reduces 3{,}895
open-vocabulary names to 783 two- or three-word identities with zero
adjacent path collision, while preserving every temporal mark occurrence.
% 折叠前，一个固定且仅使用 source 的 action--object 映射规范化 Agent 标注的显示 identity；若相邻路径将变成相同，boundary-safe refinement 保留 canonical action 与最少的 source 区分词，无法区分则 fail closed；相同 canonical 名称在跨 session 共享稳定 operation ID。完整重放将 3,895 个开放名称压缩为 783 个二到三词 identity，且不删除任何时间边界。

The adopted-mark representation repair attaches a one-turn root-only prefix to its first
nested responsibility: when such a mark is immediately followed by its first
responsibility, the first turn receives the complete root--responsibility path,
eliminating artificial leaf groups without reading a stage label.
% adopted-mark 表示修复把 one-turn root-only prefix 归入其首个嵌套 responsibility：当该 mark 紧邻其第一个 responsibility 时，首 turn 直接采用完整 root--responsibility path，从而在不读取 stage label 的情况下消除伪 leaf group。

\subsection{RQ2 Scoring Details}
\label{app:rq2-scoring}

Within each workload, we fix operations, target-blind paths, benchmark
judge/localizer predictions, and scoring rules before loading test targets.
Group scores aggregate frozen benchmark-judge predictions per operation group
(Wilson lower bound for HINTBench/TraceElephant; vote averaging for
AgentProcessBench)~\cite{wilson1927}.
% 各 workload 中，operation、target-blind path、benchmark judge/localizer 预测与评分规则均在加载 test target 前固定；group score 在每个 operation group 上聚合冻结的 benchmark-judge 预测（HINTBench/TraceElephant 用 Wilson 下界，AgentProcessBench 用投票平均）。

Of HINTBench's reported 629 trajectories, the released test snapshot used here
contains 536. A separate 80-trajectory validation snapshot selects one of 24
field orders before all 536 tests are scored.

AgentProcessBench averages judge votes within a group. HINTBench and
TraceElephant assign each root-to-frame prefix the 95\% Wilson lower
bound~\cite{wilson1927} of its frozen positive-prediction fraction; an
operation receives the maximum score over prefixes containing it.

\subsection{Selective Annotation Protocol}

operation count---and, for every turn, its index, first operation ID, intent,

deterministic subset of turns.
% FULL 暴露每个 turn 的全部 source-visible field；SELECTIVE 暴露完整 session-level skeleton（session、framework、task、turn count、operation count），以及每个 turn 的 index、first operation ID、intent、planned action 与 progress，只为一个确定性 turn 子集补充完整 visible result。

% 仅使用 source 的 selector 根据 result 长度、显式 error/pass/timeout 词、verification/build/test action 及 source progress change 对 turn 排序；对含 $T$ 个 turn 的 session 选择 $\min(10,\lceil0.15T\rceil)$ 个 turn，最少两个。Selector 不读取 stage、annotation、reward、score、outcome 或先前 model result；两种条件均按同一 sparse complete-path schema 调用一次标注，并允许一次计入成本的 format retry。

\subsection{Extended Scope and Limitations}
\label{app:scope}

Results apply to the named populations and annotation protocols.
RQ4 measures fixed-input replay, direct-backend wall time and token use, and
the source-packet and deterministic downstream paths from normalized
operations plus released raw archives. It excludes capture, raw-to-normalized
conversion, and live-agent overhead; automatic annotation cost is instrumented
on the complete CodeTraceBench, AgentRewardBench, and Git populations.
% 结果适用于声明的 population 与 annotation protocol。RQ4 测量 fixed-input replay、direct backend 的 wall time 与 token 用量，以及从 normalized operation 和 released raw archive 开始的 source-packet 与 deterministic downstream path；它不包含 capture、raw-to-normalized conversion 与 live-agent overhead，并在完整 CodeTraceBench、AgentRewardBench 和 Git population 上插桩 automatic annotation cost。

The direct annotation instruction was fixed before the CodeTraceBench run,
the backend reads only source-visible content, and every stage label is
loaded exclusively by the scorer after all 405 annotations materialize; no
method component changed after scoring began. OSWorld-Human separately
evaluates recurrence and supervised boundary backends. RQ2 targets are
loaded only after profiles and predictions are fixed; RQ2 does not measure
end-user diagnosis time. AgentRewardBench has no gold nested semantic
hierarchy, so the differential case does not measure topology accuracy or
causality.
% direct annotation 指令在 CodeTraceBench 运行前即已固定，backend 只读 source-visible 内容，全部 405 条 annotation 物化后 stage label 才由 scorer 独占加载；打分开始后没有任何方法组件被修改。OSWorld-Human 独立评估 recurrence 与监督 boundary backend。RQ2 target 在 profile 与 prediction 固定后才加载；RQ2 不衡量 end-user diagnosis time。AgentRewardBench 没有 gold nested semantic hierarchy，因此差分案例不衡量 topology accuracy 或因果关系。

The selective-annotation confirmation units are 32 exact
\texttt{task\_name} clusters,
not independent software projects, with one paired generation per cluster and
one model/backend on a historically studied benchmark. Provider token volume
is not price-weighted dollar cost; SELECTIVE's aggregate wall time is higher
than FULL's, and its complete per-turn skeleton means it does not read only
15\% of a trace. B$^3$ and adjacent-boundary F1 evaluate flat stage structure,
not nested topology, cross-session equivalence, or end-user utility.
% 选择性标注的确认单位是 32 个 exact task-name cluster，而非独立 software project；每个 cluster 只有一次 paired generation，并且只覆盖一个 model/backend 与一个历史上已研究的 benchmark。Provider token volume 不是按价格加权的美元成本；SELECTIVE 的聚合 wall time 高于 FULL，且它保留每个 turn 的完整 skeleton，不能描述为只读取 trace 的 15%。B$^3$ 与 adjacent-boundary F1 评估 flat stage structure，而非 nested topology、跨 session 等价或 end-user utility。

The ToolSandbox result covers one compatibility-layer repair, one model, and
one benchmark. Its opaque-ID allocator is not controlled by the request seed,
so raw fault exposure differs between arms (28 versus 19) and the reported
19.0\% is the complete intention-to-treat token effect rather than a fixed
saving per invalid ID. Similarity and exact-success intervals cross zero;
the result establishes non-inferiority, not significant outcome improvement.
The exact-state replay isolates the converter mechanism only, and no human

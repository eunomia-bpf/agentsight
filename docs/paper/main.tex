\begin{abstract}
AI agents produce growing populations of execution histories, and developers
need population-level answers about where failures concentrate, which workflows
trigger unsafe effects, and which task categories consume the most budget.
% AI 智能体产生不断增长的执行历史集合，开发者需要群体级答案：故障集中在哪里、哪些工作流触发不安全副作用、哪类任务消耗最多预算。
Unlike stable code paths, natural-language intent lacks shared identity and
native execution nesting provides no reusable cross-run hierarchy of semantic
responsibility; existing tools trace runs, group metadata, and aggregate
metrics but do not recursively construct such responsibility while retaining
LLM/tool evidence and conserved measures in a standard profile.
% 与稳定代码路径不同，自然语言意图缺少共享身份，原生执行嵌套也不提供可跨运行复用的语义责任层次；现有工具追踪运行、分组 metadata 并聚合指标，但不递归构造这种责任，同时在标准 profile 中保留 LLM/tool evidence 与守恒度量。
Agent observability needs profiling, not only debugging.
% 智能体可观测性需要 profiling，而不仅仅是 debugging。
\sys realizes this insight through a \emph{semantic operation stack model}:
backend-neutral recursive annotations identify shared responsibilities over an
ordered source tree, operation stacks compose them with native evidence, and
additive resource views emit pprof-compatible profiles.
% \sys 通过语义 operation stack 模型实现这一洞见：backend-neutral 递归 annotation 在有序 source tree 上识别共享责任，operation stack 将其与原生证据组合，可加资源视图输出 pprof-compatible profile。
We evaluate \sys on 405 human-staged CodeTraceBench trajectories, three
complete public localization benchmarks, 287 OSWorld-Human sessions, two
population case studies, and four public cost workloads.
% 我们在 405 条带人工 stage 的 CodeTraceBench 轨迹、三个完整公开 localization benchmark、287 个 OSWorld-Human session、两个 population case study 和四个公开成本 workload 上评估 \sys。
Automatic Agent annotation raises ordinary B$^3$ F1 against human stages from
0.541 for raw action and 0.663 for recurrence to 0.704. On three complete
localization workloads, AgentProf raises MAP over benchmark-native direct
diagnostics by 0.031, 0.107, and 0.117. As a reading index on TraceElephant,
the semantic hierarchy guides a strong trajectory reader to equal ranking
quality while opening 53.0\% of the source evidence, versus 65.0\% under an
information-matched raw-action grouping, and skeleton-guided drilldown remains
available beyond the context window where whole-trace reading fails.
% 自动 Agent 标注将相对人工 stage 的普通 B$^3$ F1 从 raw action 的 0.541 和 recurrence 的 0.663 提升到 0.704。在三个完整 localization workload 上，AgentProf 相对 benchmark-native direct diagnostic 将 MAP 分别提高 0.031、0.107 和 0.117。在 TraceElephant 上作为阅读索引时，语义层次引导强 trajectory reader 达到同等排名质量，只打开 53.0\% 的 source evidence，而信息匹配的 raw-action 分组需打开 65.0\%；骨架引导的下钻可超越整条轨迹阅读失效的上下文窗口边界。
Evaluated task-family and action backends reach 0.695 and 0.498 macro-F1,
label-free recurrence reaches 0.680 boundary F1 and 0.786 B$^3$ F1 on
OSWorld-Human, and, after marks are fixed, \sys constructs a
27{,}765-operation profile in 1.16\,s.
% 评估的 task-family 与 action backend 分别达到 0.695 和 0.498 macro-F1；在 OSWorld-Human 上，无标签 recurrence 达到 0.680 boundary F1 和 0.786 B$^3$ F1；固定 mark 后，\sys 在 1.16 秒内构建包含 27,765 个 operation 的 profile。
\end{abstract}

% AI agents increasingly orchestrate long-running, multi-step
% activities involving thousands to millions of interactions with
% users, tools, and system resources.
% To optimize the quality, safety, and cost of agents, developers must 
% analyze behaviors across thousands of runs to 
% find where failures concentrate, 
% locate the workflow phases triggering unsafe effects, 
% and identify the tasks that consumes most budget. 

% While performance profiling traditionally answers these questions 
% for classic software by aggregating resource consumption, 
% traditional profilers fail for agents.
% unlike traditional software where code paths provide a natural hierarchy for profiling, 
% agent behaviors are driven by unstructured natural language prompts 
% and lack deterministic execution stacks. 
% To bridge this gap, we propose the Semantic Operation Stack model. 
% First, we unify all heterogeneous agent activities (prompts, tool calls, 
% and system I/O) into a single structured record called an operation. 
% Second, we construct dynamic call stacks at query time by projecting 
% these operations onto user-defined semantic fields (e.g., intent $\rightarrow$ phase $\rightarrow$ action), merging identical sequences to generate flame graphs.

% We implement this model in AgentProf, an offline profiler 
% with pluggable algorithms for intent attribution and stack construction, 
% compiling local agent trajectories into standard, pprof-compatible profiles.

\section{Introduction}
\label{sec:intro}

%% ¶1: Background + context
AI agents~\cite{sweagent,codex,claudecode,osworld} orchestrate multi-step
activities across a high-level intent layer (prompts, LLM calls, and tool
invocations) and a low-level system-effects layer (process spawns and file and
network I/O), and production teams accumulate many such trajectories.
% AI 智能体~\cite{sweagent,codex,claudecode,osworld}编排跨越两层的多步骤活动（高层意图：提示词、LLM 调用、工具调用；低层系统副作用：进程创建、文件与网络 I/O），生产团队会积累大量此类轨迹。

%% ¶2: Problem
Developers lack population-level answers about agent quality, safety, and cost:
which task categories consume the most token budget, where failures concentrate
across workflows, and which behavioral patterns trigger unsafe system effects.
% 开发者缺少关于智能体质量、安全与成本的群体级答案：哪类任务消耗最多 token 预算、故障跨工作流集中在哪里、哪些行为模式触发不安全系统副作用。
Manual trajectory inspection is slow and expensive~\cite{agentrewardbench},
and LLM judging requires a separate evaluator pass per
trajectory~\cite{agentrewardbench,llm-as-judge}.
% 人工轨迹检查缓慢且昂贵，而逐轨迹 LLM judging 需要为每次运行单独执行一次 evaluator。

%% ¶3: Structural cause
Agent trajectories lack two structures needed for cross-run profiling.
% 智能体轨迹缺乏跨运行 profiling 所需的两个结构。
Responsibility lies in semantic categories such as task intent and tool
operation rather than stable function names, and natural-language prompts
provide no common identifier for shared intent.
% 负责实体是任务意图和工具操作等语义类别而非稳定函数名，且自然语言提示词不为共享意图提供共同标识符。
Native execution nesting may exist but provides no reusable cross-run hierarchy
of semantic responsibility: one prompt sequence may represent multiple tasks,
and one task may belong to a larger one.
% 原生执行嵌套可以存在，但不提供可跨运行复用的语义责任层次：一段提示序列可能表示多个任务，一个任务又可能属于更大任务。

%% ¶4: Existing solutions
Existing agent observability lacks this profiling abstraction.
Tools provide rich tracing, metadata aggregation, and population
dashboards~\cite{langsmith,langfuse,otel,datadog-llmobs};
some derive hierarchical categories across traces and aggregate latency, cost,
or evaluation metrics~\cite{langsmith-insights,datadog-patterns}, and recent
research canonicalizes actions into process profiles or cross-run graphs for
monitoring and recovery~\cite{traceprobe2026,graphectory2026,hodoscope2026,
tracegraph2026,actonomy2026,chief2026}. None combines recursively annotated
semantic responsibility, source-linked LLM/tool evidence, conserved additive
measures, and standard profiler output over the same histories.
% 现有工具提供 tracing、metadata 聚合与群体 dashboard，部分跨 trace 派生分层类别并聚合指标，近期工作把动作规范化为 process profile 或跨运行图；但没有同时结合递归标注的语义责任、source-linked LLM/tool evidence、守恒的可加度量和标准 profiler 输出。

%% ¶5: Model
Agent observability needs profiling, not only debugging.
% 智能体可观测性需要 profiling，而不仅仅是 debugging。
Profiling applies to agents once a profiler projects resource measures onto
stable semantic tags in an attribution hierarchy.
% 一旦 profiler 把资源度量投影到归因层次中的稳定语义标签上，profiling 即可迁移到智能体。
Our \emph{semantic operation stack model} provides this structure: source nodes
retain native session, prompt, LLM-call, and tool-call relations and additive
measures; an interchangeable backend names the session scope, each user-prompt
scope, and recursively refined intervals as operations; an \emph{operation
stack} emits the agent, those semantic operations, and the covered LLM/tool
evidence. Raw session and prompt IDs remain labels rather than visible frames
that fragment aggregation (Figure~\ref{fig:flamegraph}).
% 我们的语义 operation stack 模型提供该结构：source node 保留原生 session、prompt、LLM call、tool call relation 与可加度量；可替换 backend 将 session scope、每个 user-prompt scope 与递归细分区间命名为 operation；operation stack 输出 agent、这些语义 operation 及其覆盖的 LLM/tool evidence，raw session/prompt ID 仅作为 label，不作为打碎聚合的可见 frame。

%% ¶6: System
We implement this model in \sys, an offline profiler compiling local agent
trajectories into pprof-compatible profiles~\cite{pprof}
(Figure~\ref{fig:architecture}).
% 我们在 \sys 中实现此模型，这是一个把本地智能体轨迹编译为 pprof 兼容 profile 的离线 profiler（Figure~\ref{fig:architecture}）。
\emph{Operation annotation} lets an Agent, language model, or non-LLM backend
mark nested source intervals with shared semantic names.
% Operation annotation 允许 Agent、语言模型或非 LLM backend 用共享语义名称标记嵌套的 source interval。
\emph{Stack construction} deterministically emits
\texttt{agent}$\rightarrow$session-level operation$\rightarrow$prompt-level
operation$\rightarrow$recursive operations$\rightarrow$LLM call$\rightarrow$tool
call, with raw session and prompt identities retained as pprof labels for
drilldown.
% 栈构造确定性地输出 agent→session-level operation→prompt-level operation→recursive operations→LLM call→tool call，raw session 与 prompt identity 作为 pprof label 保留供下钻。

%% ¶7: Results
Across 405 released CodeTraceBench trajectories reconstructable from
source~\cite{li2026codetracer},
automatic Agent annotation reaches 0.704 ordinary B$^3$ F1 against human
stages, compared with 0.663 for multi-resolution recurrence and 0.541 for raw
action.
% 在 released source 能生成官方 operation sequence 的全部 405 条 CodeTraceBench 轨迹上，自动 Agent 标注相对人工 stage 的普通 B$^3$ F1 为 0.704，高于 multi-resolution recurrence 的 0.663 和 raw action 的 0.541。
Across three complete public workloads, AgentProf refines benchmark-native
direct diagnostic ties and raises MAP by 0.031, 0.107, and 0.117,
respectively~\cite{agentprocessbench,hintbench,traceelephant}.
On TraceElephant, the same fixed hierarchy serves as a reading index:
a strong reader reaches statistically equal ranking quality while opening
less source evidence (53.0\% versus 65.0\%) than with an information-matched
raw-action grouping.
% 在用于协议开发的三个完整公开 workload 上，AgentProf 细化 benchmark-native direct diagnostic 的并列，并将 MAP 分别提高 0.031、0.107 和 0.117。
% 在 TraceElephant 上，同一固定层次也作为阅读索引：强 reader 达到统计持平的排名质量，同时打开的 source evidence 更少（53.0\% 对 65.0\%）。
On 287 OSWorld-Human development sessions~\cite{osworldhuman}, label-free
recurrence reaches 0.680 boundary F1 and 0.786 B$^3$ F1. On the AgentBoard and
ASE populations, task-family and action backends reach 0.695 and 0.498
macro-F1, respectively~\cite{agentboard,bouzenia-pradel-2025-trajectories}.
% 在 287 个 OSWorld-Human development session 上，无标签 recurrence 的 boundary F1 与 B$^3$ F1 为 0.680 和 0.786；在 AgentBoard 与 ASE population 上，task-family 与 action backend 分别达到 0.695 和 0.498 macro-F1。
On four public workloads, after marks are fixed, \sys constructs a
27{,}765-operation profile in 1.16\,s.
% 在四个公开 workload 上，固定 mark 后，\sys 用 1.16 秒和 465.2 MiB profile 27,765 个 operation，比 raw action 增加 19.6\% 时间和 1.14\% 内存。

\section{Background and Motivation}
\label{sec:background}

\subsection{LLMs and AI Agents}
% AI 智能体

A typical agent trajectory interleaves intent-layer activity (prompts, LLM
calls, and tool invocations for code execution, search, and file editing) with
lower-layer process, file, and network
effects~\cite{sweagent,codex,claudecode,agentsight}.
% 典型的智能体轨迹把意图层活动（提示词、LLM 调用以及代码执行、搜索、文件编辑等工具调用）与下层进程、文件和网络副作用交织在一起。
Trajectories repeat this cycle, and production teams accumulate many
trajectories~\cite{agentsight}.
% 单条轨迹会重复这一意图--副作用循环，生产团队也会积累大量轨迹。

\subsection{System Profiling}
% 系统 Profiling

Unlike single-execution debugging, profiling aggregates measurements to
attribute resources to responsible entities.
% Profiling 通过聚合将资源消耗归因到负责实体，区别于单次执行调试和 tracing。
Traditional profilers sample execution, attach each sample to its call stack,
and fold identical stacks~\cite{pprof,flamegraphs}.
% 在传统软件中，profiling 管线如下工作：profiler 周期性采样执行状态，将每个样本附加到当前调用栈，合并具有相同栈的样本。
Flame graphs~\cite{flamegraphs} and pprof~\cite{pprof} call graphs visualize
aggregate cost by width or node size, and Pivot Tracing~\cite{pivottracing}
groups causally related measurements.
% 火焰图~\cite{flamegraphs}和 pprof~\cite{pprof} 调用图以宽度或节点大小表示聚合开销，Pivot Tracing~\cite{pivottracing} 则对有因果关系的测量分组。
These tools start from stable code identifiers and runtime stacks, although
pprof can also promote \texttt{tagroot}/\texttt{tagleaf} values to
pseudo-frames~\cite{pprof}.
% 这些工具通常从稳定的代码标识符和运行时栈开始；pprof 也可以聚合标签，并将 \texttt{tagroot}/\texttt{tagleaf} 值提升为伪帧。
Agent profiles must instead derive stable semantic fields and connect them to
downstream effects.
% 智能体轨迹则必须先获得稳定的语义责任字段，并将其连接到下游副作用，之后才能形成这类 profile 视图。

\subsection{Challenges for Agent Profiling}
% 智能体 Profiling 的挑战

Existing tools~\cite{langsmith,langfuse,otel} record agent events as
per-execution span trees for single-run debugging.
% 现有工具~\cite{langsmith,langfuse,otel}将智能体事件记录为按执行划分的 span 树，有效调试单次运行。
AgentSight~\cite{agentsight} bridges intent and system-effect layers by
correlating extended Berkeley Packet Filter (eBPF) system events with intercepted LLM
traffic, but the resulting recordings still lack aggregate profiling.
% AgentSight~\cite{agentsight} 通过关联 eBPF 捕获的系统事件与拦截的 LLM 流量来桥接意图层和系统副作用层，但生成的记录仍缺乏聚合分析能力。


Agent profiling faces two challenges. First, responsibility lies in semantic
categories such as task intent and workflow phase, not code paths.
% 在传统软件中，profiling 将开销归因到代码路径，但在智能体轨迹中，相关实体是语义类别（如任务意图和工作流阶段）。
Standards represent application-supplied span attributes~\cite{otel,
openinference}, but natural-language histories lack stable categories because
different prompts or tools can express the same intent.
% 现有标准可以在 span 中表示应用提供的属性，但自然语言历史不会自动提供稳定的责任类别：表达相同意图的两个提示词和工具调用可能使用不同字符串。

Second, agent trajectories lack a runtime call hierarchy for semantic attribution.
% 第二个挑战是智能体轨迹没有能够自动提供语义归因的运行时调用层次。
In CPU profiling, the stack attributes \texttt{malloc}'s cost simultaneously
to \texttt{parse}, \texttt{process}, and \texttt{main}~\cite{pprof,flamegraphs}.
% 在 CPU 分析中，调用栈决定了每个层级的归因：\texttt{malloc} 的开销同时属于 \texttt{parse}、\texttt{process} 和 \texttt{main}。
A prompt sequence may contain one or several tasks within a larger workflow,
yet no runtime mechanism marks its boundaries or attribution granularity.
% 一串提示词可能构成一个任务也可能是多个任务，一个任务可能是更大工作流的一部分，但没有运行时机制标记这些边界或决定在哪个粒度归因开销。
RQ1 evaluates how this missing hierarchy affects attribution, while RQ3
evaluates constructed groups and boundaries.
% RQ1 评估其归因后果，RQ3 评估构造出的 group 与 boundary。

\subsection{Design Requirements for Agent Profiling}
% 智能体 Profiling 的设计需求

Traditional profiling relies on three mechanisms that the call stack supplies automatically.
% 传统 profiling 依赖调用栈自动提供的三种机制。
Agent profiling requires all three without a call stack:
% 智能体 profiling 需要这三种机制，但必须在没有调用栈的情况下实现：

\begin{description}
\item[D1: Conserved multi-resource attribution.]
Each atomic source record must retain additive resource measures, such as
tokens, time, file effects, and network effects, so regrouping never changes
their total mass.
% 每个原子 source record 都必须保留 token、time、file effect 和 network effect 等可加资源度量，使重新分组不会改变资源总量。
\item[D2: Shared semantic identity.]
Responsibilities that recur in different sessions need the same short semantic
name so that their costs fold together rather than remaining session-local.
% 在不同 session 中重复出现的责任需要共享短小的语义名称，使其开销能够折叠，而不是停留在 session-local 视图中。
\item[D3: Hierarchy without evidence loss.]
The profiler must derive variable-depth semantic responsibility from the native
trace while retaining covered LLM/tool evidence as leaf frames and raw
session/prompt identities as drilldown labels.
% 分析器必须从原生 trace 推导可变深度语义责任层次，同时将被覆盖的 LLM/tool evidence 保留为叶节点 frame，并将 raw session/prompt identity 保留为下钻 label。
\end{description}

\section{Design}
% 设计
\label{sec:design}

\begin{figure*}[t]
\centering
\input{figures/fig-architecture.tex}
\caption{\sys pipeline. A source adapter preserves the native trace tree. An
Agent, LLM, or non-LLM backend writes the same small annotation contract. The
CLI validates and composes semantic paths with source evidence, folds one
additive resource measure, and emits only a standard pprof profile.}
\Description{A source adapter builds a session, prompt, LLM-call, and tool-call
tree. An interchangeable backend produces semantic annotations. The CLI
validates, composes, folds, and exports a pprof protobuf profile.}
\label{fig:architecture}
\end{figure*}

The design has three explicit objects: an ordered source tree, nested semantic
annotations, and a weighted pprof stack. A source adapter constructs the first
without discarding content or native parent relations; any annotation backend
constructs the second without rewriting source nodes; the deterministic
profiler validates both, emits agent and semantic-operation frames followed by
covered LLM/tool evidence, and folds equal paths into the third.
% 设计包含三个显式对象：有序 source tree、嵌套 semantic annotation 和加权 pprof stack。Source adapter 在不丢弃内容和原生 parent relation 的情况下构造第一个；任意 annotation backend 在不改写 source node 的情况下构造第二个；确定性的 profiler 校验两者，依次输出 agent、semantic-operation frame 与被覆盖的 LLM/tool evidence，并把相同 path 折叠成第三个。

This separation addresses D1--D3 directly: additive measures stay on source
nodes, shared semantic names create cross-session identity, and unique session,
prompt, call, and event IDs remain pprof labels. Switching from operation count
to tokens, time, file effects, or network effects replays the same annotation
and changes only stack width.
% 这种分离直接满足 D1--D3：可加度量保留在 source node 上，共享语义名称提供跨 session identity，唯一的 session、prompt、call 与 event ID 保留为 pprof label；从 operation count 切换到 token、time、file effect 或 network effect 时只重放同一 annotation 并改变 stack 宽度。

\subsection{Semantic Operation Stack Model}
% 语义 Operation Stack 模型
\label{sec:ops}

Let a source node be $n=(id,parent,kind,data,m)$ in an ordered forest.
The \textit{kind} is a session, prompt, LLM call, tool call, effect, or an
adapter-defined atomic event. The \textit{data} retains the source content
needed to interpret the event, and $m$ maps resource names to nonnegative
additive measures. Source-parent links encode observed execution structure;
they never encode an inferred semantic operation.
% Source node 是有序森林中的 $n=(id,parent,kind,data,m)$。kind 表示 session、prompt、LLM call、tool call、effect 或 adapter 定义的原子事件；data 保留解释事件所需的 source content；$m$ 将资源名称映射到非负可加度量。Source-parent link 编码观察到的执行结构，而不编码推断出的语义 operation。

Recursive annotation covers every source node with exactly one active semantic
leaf and its enclosing operation ancestors; let this path be $A(n)$. Let
$g(n)$ be the agent identity inherited from the source root, and let $E(n)$ be
the retained evidence ancestry after removing raw session and prompt
containers---normally the covered LLM call, tool call, and effect. The emitted
operation stack is
$\sigma(n)=\langle\textit{agent}:g(n)\rangle\mathbin{\|}A(n)\mathbin{\|}E(n)$,
where $\|$ denotes concatenation. Raw session and prompt IDs are attached as
labels $\lambda(n)$ rather than visible frames. Equal semantic prefixes can
therefore aggregate across sessions without losing the evidence needed to
locate a contributing call or tool event.
% 递归 annotation 使用唯一 active semantic leaf 及其外层 operation ancestor 覆盖每个 source node，形成 $A(n)$；$g(n)$ 是从 source root 继承的 agent identity；$E(n)$ 是去除 raw session 与 prompt container 后保留的 evidence ancestry，通常包含被覆盖的 LLM call、tool call 与 effect。输出 operation stack 为 $\sigma(n)=\langle\textit{agent}:g(n)\rangle\mathbin{\|}A(n)\mathbin{\|}E(n)$；raw session 与 prompt ID 作为 label $\lambda(n)$ 保留，而不是可见 frame。相同语义前缀因此可以跨 session 聚合，同时仍能定位贡献权重的 call 或 tool event。

\label{sec:stacks}
We formalize a resource profile as $(\varphi,\sigma,w_r)$: predicate
$\varphi(n)$ selects source nodes, $\sigma(n)$ supplies the composed stack, and
$w_r(n)=m_n[r]\geq0$ selects one additive resource. Folding merges equal stacks
and sums $w_r$. The default operation-count view assigns one unit to each
adapter-defined atomic operation; token, time, file-effect, and network-effect
views select their corresponding measures. Because $A$ and $E$ remain fixed,
changing $r$ changes only widths, not boundaries or semantic names.
% 资源 profile 是 $(\varphi,\sigma,w_r)$：谓词 $\varphi(n)$ 选择 source node，$\sigma(n)$ 给出组合后的 stack，$w_r(n)=m_n[r]\geq0$ 选择一种可加资源。折叠合并相同 stack 并累加 $w_r$。默认 operation-count view 为每个 adapter-defined atomic operation 赋一个单位；token、time、file-effect 和 network-effect view 选择相应度量。由于 $A$ 与 $E$ 固定，改变 $r$ 只改变宽度，而不改变 boundary 或语义名称。

\subsection{Recursive Operation Annotation}
% 递归 Operation 标注
\label{sec:intent}

The source adapter preserves an ordered tree of sessions, prompts, LLM calls,
and tool calls. Semantic operations are nested intervals over this tree rather
than replacements for its nodes.
% Source adapter 保留由 session、prompt、LLM call 和 tool call 构成的有序树；语义 operation 是该树上的嵌套区间，而不是对 source node 的替换。
An annotation at source node $s$ contains a semantic name, the start node of
its enclosing annotation, and the first source node after its interval.
The exclusive end may be omitted when the interval reaches its parent's end.
% 位于 source node $s$ 的 annotation 包含语义名称、其外层 annotation 的起始 node，以及该区间之后的第一个 source node；区间延伸到 parent 末尾时可以省略 exclusive end。
Every source root must begin a session-level operation, and every prompt must
begin a prompt-level operation. Further nested intervals define the
variable-depth suffix of the operation path. Equal path prefixes fold across
sessions; covered LLM/tool nodes remain below the path, while raw session and
prompt IDs remain labels for evidence drilldown.
% 每个 source root 必须开始一个 session-level operation，每个 prompt 必须开始一个 prompt-level operation；更深的 nested interval 定义 variable-depth operation suffix。相同 path prefix 跨 session 折叠，被覆盖的 LLM/tool node 保留在 path 下方，而 raw session 与 prompt ID 作为 label 保留供 evidence drilldown。

Annotation proceeds coarse to fine. A backend first names the complete session
and each user-prompt scope, then selects one interval whose current name hides
a useful responsibility change, marks source-visible boundaries, names the
resulting child intervals, and repeats only where another distinction helps; a
later iteration may rename, merge, or remove an earlier split.
% 标注从粗到细进行：backend 先命名完整 session 与每个 user-prompt scope，再选择当前名称掩盖有用责任变化的区间，标记 source-visible boundary，命名得到的 child interval，并只在另一层区分确有帮助时继续；后续迭代可重命名、合并或删除已有 split。
The default Agent-assisted backend reads source content and existing paths to
make these decisions. A plain language model, deterministic rules, change-point
methods, and the label-free recurrence constructor use the same annotation
contract, so the profiler does not depend on one model or inference service.
% 默认的 Agent-assisted backend 读取 source content 与当前 path 做出这些决策；普通语言模型、确定性规则、change-point 方法和无标签 recurrence constructor 使用相同 annotation contract，因此 profiler 不依赖单一模型或推理服务。

The evaluated Agent backend instantiates this contract with a fixed binary
recursive policy. For an interval, it receives target-blind task text, the
active ancestor path, and every source-visible turn summary in that interval,
then returns either \textsc{Stop} or
\textsc{Split}(\emph{non-first turn}, \emph{left name}, \emph{right name}).
A child name equal to the current frame stays, one equal to an ancestor pops
to that frame, and a new name pushes one frame; equal resolved children fail
closed. A one-turn interval, \textsc{Stop}, or a split whose sides both
resolve to the unchanged path terminates the branch; otherwise nonempty
children recurse independently. There is no depth cap, leaf cap, length
threshold, or score-tuned contraction, and after recursion the materializer
emits a sparse mark only when the complete path changes, merging adjacent
identical paths but never nonadjacent or unequal ones.
% 评测的 Agent backend 使用固定二元递归策略实例化该 contract：对每个 interval，它只读取 target-blind task text、active ancestor path 及 interval 内全部 source-visible turn summary，并输出 Stop 或 Split(非首 turn、左右名称)；名称匹配当前 frame 时 stay，匹配 ancestor 时 pop，新名称时 push；两侧解析成同一路径则 fail closed。one-turn、Stop 或两侧均解析成未变路径时终止分支，否则非空子区间独立递归。算法没有深度、叶子数、长度阈值或 score-tuned contraction；materializer 仅在完整 path 改变时发出 sparse mark，合并相邻相同 path 但不合并非相邻或不等者。

The complete CodeTraceBench A2 run uses independent Codex Agent workers under
one fixed source-only annotation instruction, followed by root merge,
validation, and one deterministic source-only representation repair
(Appendix~\ref{app:canonicalization}). Official stages, outcomes, recurrence
assignments, and scores remain hidden until all 405 trajectories are
materialized. Before folding, a fixed source-only action--object map
canonicalizes display identities (5{,}537 open-vocabulary names to 1{,}434
two- or three-word IDs with zero adjacent collision) while preserving every
temporal mark.
% 完整 CodeTraceBench A2 运行由多个独立 Codex Agent worker 按同一份固定 source-only annotation instruction 执行，再由 root merge、验证与一个确定性 source-only 表示修复完成（附录）；全部 405 条轨迹物化前不读取官方 stage、outcome、recurrence assignment 或 score。折叠前，固定的 source-only action--object 映射规范化显示 identity（5,537 个开放名称压缩为 1,434 个二到三词 ID，零相邻碰撞），并保留全部时间 mark。

\section{Implementation}
% 实现
\label{sec:impl}

\paragraph{Input reconstruction.}
% 输入重建。\sys 是实现该模型的离线 Rust CLI（Figure~\ref{fig:architecture}）。
\sys is an offline Rust CLI implementing this model
(Figure~\ref{fig:architecture}). Source-specific adapters reconstruct an
ordered tree from local Codex and Claude Code histories,
AgentSight~\cite{agentsight} recordings, or public trajectory datasets,
preserving replay-stable node IDs, source content or readable references,
native parent links, input order, and additive measures. Structured operation
JSONL is materialized as adapter-defined atomic source nodes without inventing
missing prompt or call relations.
% \sys 是实现该模型的离线 Rust CLI（Figure~\ref{fig:architecture}）。Source-specific adapter 从 Codex 与 Claude Code 本地 history、AgentSight recording 或公开 trajectory dataset 重建有序树，保留 replay-stable node ID、source content 或可读引用、原生 parent link、输入顺序及可加度量；结构化 operation JSONL 被物化为 adapter-defined atomic source node，不虚构缺失的 prompt 或 call relation。

\paragraph{Annotation workspace.}
% Annotation workspace。
The backend reads \texttt{trace.jsonl} and writes only \texttt{annotation.json}:
the former retains source content, source-parent links, additive measures, and
the current derived path; the latter maps source start IDs to \texttt{tag},
semantic \texttt{parent}, and exclusive \texttt{next}. \sys validates that
references exist and intervals are nested, noncrossing, and collectively cover
every source node, then atomically updates derived paths and the folded
aggregate.
% Backend 读取 \texttt{trace.jsonl} 且只写 \texttt{annotation.json}：前者保留 source content、source-parent link、可加度量和当前派生 path，后者将 source start ID 映射到 \texttt{tag}、语义 \texttt{parent} 与 exclusive \texttt{next}；\sys 校验引用存在、区间嵌套不交叉且共同覆盖每个 source node，再原子更新派生 path 与 folded aggregate。
Nonblocking hierarchy warnings flag a recursive operation with only one
explicit semantic child, a large flat fan-out with little recursive refinement,
or an optional semantic leaf spanning at least eight tool calls---exposing
redundant, prematurely flat, or coarse annotations without forcing artificial
depth or blocking generation.
% 非阻塞 hierarchy warning 标记只有一个显式 semantic child 的递归 operation、几乎没有进一步递归的大型 flat fan-out，以及覆盖至少八个 tool call 的可选 semantic leaf；这些诊断暴露冗余、过早扁平化或过粗的 annotation，但不强制虚假深度，也不阻塞生成。

\paragraph{Non-LLM recurrence backend.}
% 非 LLM recurrence backend。
The inducer scores adjacent action transitions by normalized pointwise mutual
information~\cite{bouma2009npmi} and calibrates a label-free cutoff with
occurrence-weighted two-means~\cite{macqueen1967}, treating detailed recurrence
as continuity that can remove but never add a coarse boundary; an optional
reference-calibrated mode fits one scalar cutoff on disjoint reference groups
(Appendix~\ref{app:recurrence}).
% inducer 用 NPMI 为相邻 action 转移评分，并用按出现次数加权的二均值校准无标签阈值；detail 连续性只能删除而不能新增粗边界；可选的 reference-calibrated 模式在不重叠参考分组上拟合单一阈值（附录）。

\paragraph{Profile export.}
% Profile 导出。
\sys emits one pprof protobuf profile for existing tools such as
\texttt{go tool pprof}; it does not add a visualization frontend or a second
export format.
% \sys 只输出一个供 \texttt{go tool pprof} 等现有工具读取的 pprof protobuf profile；它不增加可视化前端或第二种导出格式。

\subsection{RQ1: Multi-Resource Attribution}
% RQ1：多资源归因。

RQ1 asks whether semantic profiling improves resource attribution. We test one
necessary consequence: whether a fixed semantic hierarchy reveals materially
different bottlenecks when the additive resource measure changes. The source
population contains 41 real long-horizon agent trajectories, 3{,}146
source-native turns, and 5{,}750 operations. Within it, three independent
executions repeat the same Git-deployment task. The automatic Agent backend
assigns 96 recursive annotations to their 735 source nodes. The resulting
hierarchy reaches semantic depth five without a fixed limit. The CLI reports no
unary or flat-fan-out warning and 27 advisory coarse-leaf warnings.
% RQ1 问 semantic profiling 是否改善资源归因。这里测试一个必要后果：固定语义层次在切换可加资源度量时是否暴露实质不同的瓶颈；source population 含 41 条真实 long-horizon agent 轨迹、3,146 个 source-native turn 和 5,750 个 operation，其中三条独立执行重复同一个 Git 部署任务。Automatic Agent backend 为其 735 个 source node 生成 96 个递归 annotation；层次在没有固定上限的情况下达到 semantic depth 5，CLI 不再报告 unary 或 flat-fan-out warning，并给出 27 个仅供诊断的 coarse-leaf warning。
This establishes the necessary multi-resource attribution capability on a
repeated real task; it does not claim superiority over every attribution
interface or generalize the measured ratios beyond this population.
% 该实验在一个重复真实任务上建立多资源 attribution 的必要能力，但不声称优于所有 attribution interface，也不把测得比例推广到该 population 之外。

\subsection{RQ2: Problem Correspondence}
% RQ2：分析器输出是否对应真实问题？

RQ2 asks whether target-blind profiles place independently annotated problems
in groups a developer can inspect early. We run complete AgentProcessBench,
HINTBench, and TraceElephant workloads~\cite{agentprocessbench,hintbench,traceelephant}.

Within each workload, we fix operations, target-blind paths, benchmark
judge/localizer predictions, and scoring rules before loading test targets.
Group scores aggregate frozen benchmark-judge predictions per operation group
(Wilson lower bound for HINTBench/TraceElephant; vote averaging for
AgentProcessBench)~\cite{wilson1927}, with snapshot details in the appendix.
% group score 在每个 operation group 上聚合冻结的 benchmark-judge 预测（HINTBench/TraceElephant 用 Wilson 下界，AgentProcessBench 用投票平均），snapshot 细节见附录。

The main test asks whether the profile adds information beyond the
\emph{direct diagnostic}---the per-operation output of a benchmark-native
process judge (AgentProcessBench risk units) or trajectory localizer (HINTBench,
TraceElephant), which for TraceElephant reads the full trace and reference answer
before naming the responsible agent and decisive step. The candidate
(Direct+AgentProf) ranks operations lexicographically by (\emph{direct
diagnostic}, \emph{Agent+Evidence group score}), so it can only refine exact
diagnostic-score ties. The other conditions are Direct-only, AgentProf-only
(profile without the direct diagnostic), and Direct+Raw+Evidence (raw-action
prefix; identical source-kind, tool/call, and outcome suffix and aggregation).

Each query is one trajectory containing an annotated target. We report
non-interpolated per-query AP and arithmetic-mean MAP across 614, 400, and 220
target-bearing queries, respectively~\cite{robertson2008ap}. All 522
zero-positive trajectories are consumed for population coverage but excluded
from MAP because AP is undefined without a relevant item.

The semantic prefix's distinct, separately measured roles are cross-run

populations, this is adaptive mechanism evidence rather than untouched backend
generalization.
% Direct+AgentProf 相对 Direct-only trajectory judge/localizer 在三个完整 workload 上分别提高 MAP .031、.107 与 .117，区间均为正；与保留相同 source evidence 的 raw-action refinement 统计上不可区分。因此该实验支持 profiling 补充 direct trajectory diagnosis，但不声称 semantic prefix 在这三个已观察 population 上具有额外的 target-ranking 优势。

\paragraph{Profile-guided reading on TraceElephant.}

Grok-family CLI reader receives target-blind packets---task text, operation
IDs, and source-visible content---with unranked operations appended in
original order deterministically and one single-turn call per stage.
% 在完整的 220 个带 target 的 TraceElephant query 上，一个固定的外部 Grok 家族 CLI reader 接收 target-blind packet——任务文本、operation ID 与 source-visible 内容——未排名 operation 按原始顺序确定性附加，每个 stage 单轮调用。
Full-trace reading reaches MAP .502 versus .209 for the benchmark's

input tokens per query.
% 全 trace 阅读达到 MAP .502，而 benchmark 的 Direct-only 诊断为 .209、Direct+AgentProf 为 .326，平均每个 query 12,615 输入 token。

skeleton, with no source content, and the reader selects at most five groups;
stage two then opens only the selected groups' evidence.
% 两阶段 profile-guided 变体首先只展示 semantic operation 骨架（无 source 内容），reader 最多选择 5 个 group；第二阶段只打开所选 group 的 evidence。
It reaches MAP .455 while opening 53.0\% of the source content, and its
stage-one selections never fell back to a default.
% 它达到 MAP .455，同时只打开 53.0\% 的 source 内容，且第一阶段选择从未回退到默认值。
Under an information-matched raw-action skeleton, ranking quality is
statistically unchanged (MAP .465; paired delta $+.010$ [$-.021$, $+.042$]).
% 在信息匹配的 raw-action 骨架下，排名质量在统计上不变（MAP .465；配对差异 +.010 [-.021, +.042]）。

Semantic naming's measured contribution in this regime is attention
concentration at equal quality.
% 在此机制下 semantic naming 测得的贡献是同等质量下的注意力集中。
A per-query full read is bounded by the model context window: populations

queries and measures.
% reader 是 query-specific——每个问题都重新阅读整条轨迹——而层次结构只构造一次，跨 query 与 measure 复用。

\subsection{Case Study 2: Differential Profiling at Scale}
% 案例研究 2：大规模差分 profiling。

We aggregate AgentRewardBench's~\cite{agentrewardbench} complete mixed-outcome population,
not one favorable trace pair: 440 real trajectories over 125 tasks yield 338 bad--good
pairs (24/102/144/68 from AssistantBench, VisualWebArena, WebArena, WorkArena); the 202
successful and 238 unsuccessful sessions reuse across pairs (pair-occurrence weighted).
% 我们聚合 AgentRewardBench 的完整 mixed-outcome population（而非单个有利 trace pair）：125 个任务的 440 条真实轨迹产生 338 个 bad--good pair（AssistantBench/VisualWebArena/WebArena/WorkArena 分别贡献 24/102/144/68）；202 条成功与 238 条失败 session 跨 pair 复用，因此 profile 按 pair occurrence 加权。

Before opening outcomes or expert annotations, three automatic Agent workers
produce 2{,}131 sparse recursive annotations over all 7{,}229 source
operations. The resulting hierarchy reaches semantic depth four before its
LLM-call and tool-call evidence leaves. We then fold all 338 bad members and
all 338 good members into one signed operation-count pprof, preserving the same
source occurrences on both the recursive and fixed-chain projections.
% 在读取 outcome 或专家 annotation 之前，三个 automatic Agent worker 为全部 7,229 个 source operation 生成 2,131 个稀疏递归 annotation；所得层次在 LLM-call 与 tool-call evidence leaf 之前达到 semantic depth 4。随后我们将全部 338 个 bad member 和 338 个 good member 折叠进一个 signed operation-count pprof，并保证递归投影与 fixed-chain 投影使用完全相同的 source occurrence。

The aggregate contains 7{,}366 bad-side and 3{,}780 good-side operation
occurrences. Recovery accounts for 44.6\% of bad-side occurrences but only
12.0\% of good-side occurrences; completion accounts for 1.8\% and 5.1\%,
respectively. The recursive recovery focus separates verification challenges,
repeated searches, mistaken navigation, product or record retries, and
repository inspection beneath the same responsibility, while source labels
identify the contributing session and call.
% 聚合 profile 包含 7,366 个 bad-side 与 3,780 个 good-side operation occurrence。Recovery 占 bad side 的 44.6\%，而仅占 good side 的 12.0\%；completion 分别占 1.8\% 与 5.1\%。递归 recovery focus 在同一职责下区分 verification challenge、重复搜索、误导航、产品或记录重试以及 repository inspection，并通过 source label 定位贡献这些宽度的 session 与 call。

We test whether this visible recovery structure corresponds to an independent
problem rather than merely reflecting more steps. For each trajectory, recovery
exposure is the fraction of source operations whose path contains the shared
recovery responsibility. Among 435 trajectories with consensus expert looping
labels, this score obtains AP .634 at prevalence .398; a 10{,}000-draw
task-cluster bootstrap places AP minus prevalence in [.181,.293]. A registered
fixed-chain repeated/error projection obtains AP .656, and the
recursive-minus-fixed interval [-.107,.061] does not establish detector
superiority. The recursive profile therefore contributes a source-drillable
explanation of \emph{where} recovery accumulates while independently
corresponding to expert-identified looping.
% 我们进一步检验该可见 recovery 结构是否对应独立问题，而不仅仅反映更多 step。每条轨迹的 recovery exposure 定义为路径中包含共享 recovery responsibility 的 source operation 比例。在 435 条具有一致专家 looping label 的轨迹上，该 score 的 AP 为 .634，prevalence 为 .398；10,000 次 task-cluster bootstrap 给出的 AP-minus-prevalence 区间为 [.181,.293]。注册的 fixed-chain repeated/error 投影 AP 为 .656，recursive-minus-fixed 区间 [-.107,.061] 不支持 detector superiority。因此递归 profile 的价值是可下钻地解释 recovery 在何处累积，并且该 exposure 独立对应专家识别的 looping。

This case answers RQ2 at collection scale: a target-blind recursive profile
exposes failed-side recovery and successful-side completion under shared
responsibilities, and its recovery signal corresponds to an independently
annotated real problem. AgentRewardBench has no gold nested semantic
hierarchy, so this result does not measure topology accuracy or causality.
% 该案例在集合尺度上回答 RQ2：target-blind 递归 profile 在共享职责下暴露失败侧 recovery 与成功侧 completion，且 recovery signal 对应独立标注的真实问题。AgentRewardBench 没有 gold nested semantic hierarchy，因此该结果不衡量 topology accuracy 或因果关系。

\subsection{RQ3: Automatic Operation Structure}
% RQ3：自动 operation 结构。

RQ3 evaluates automatic backend outputs against independent annotations under
each protocol's stated input boundary. Literal task and action fields use
accuracy and macro-F1 (the unweighted mean of per-class F1)~\cite{lewis2004rcv1}.
Partition-valued task,
phase, and group fields use V-measure~\cite{rosenberg-hirschberg-2007-v-measure}
or ordinary B$^3$, and adjacent group
boundaries use exact precision, recall, and F1~\cite{ruokolainen2016segmentation}.
Literal labels, permutation-invariant partitions, and adjacent boundaries are
distinct outputs.
A backend output is evaluated at the level it predicts: literal names,
permutation-invariant leaf partitions, or adjacent interval boundaries. For
legacy field-valued datasets, a mechanical adapter converts each predicted
group into the same interval-annotation contract before \sys folds the
original additive weights.
% RQ3 按各 protocol 明确声明的输入边界评估自动 backend 是否恢复独立标注；字面标签使用 macro-F1 与 accuracy，partition 使用 V-measure 或普通 B$^3$，相邻 boundary 使用精确 precision、recall 与 F1。

We first evaluate the default Agent-assisted backend on all 405 reconstructable
CodeTraceBench trajectories~\cite{li2026codetracer}: 20{,}866 operations and
2{,}948 human-verified contiguous stages across four agent frameworks. Automatic
Agents receive source-only packets and emit sparse complete-path marks over
17{,}148 source-native turns. A deterministic representation repair attaches a
one-turn task-root-only prefix to its first nested responsibility, eliminating
149 artificial leaf groups without reading a stage label. The final 5{,}752
marks have semantic depth one (51 marks), two (5{,}608), or three (93); no
prompt requests a depth.
% Automatic Agent 仅接收 source packet；确定性的表示修复把一步长的 task-root-only prefix 归入首个嵌套 responsibility，在不读取 stage label 的情况下消除 149 个伪 leaf，得到 5,752 个可变深度 mark。
The current name replay then maps 5{,}537 open-vocabulary operation IDs to
1{,}434 action-first two- or three-word canonical IDs. It independently
re-expands all operations from the unchanged marks, preserves the temporal
occurrence and adjacent-boundary vectors exactly, and leaves no adjacent
display-path collision. Nonadjacent and cross-session equal names intentionally
merge so recurring work folds in pprof.
% 当前名称重放把 5,537 个开放 operation ID 映射为 1,434 个 action-first、二到三词 canonical ID；它从未改变的 mark 独立展开全部 operation，精确保留 temporal occurrence 与相邻 boundary，并有意合并非相邻及跨 session 的同名工作。

\subsection{Scope and Limitations}

Results apply to the named populations and annotation protocols.
RQ4 measures fixed-input replay and the deterministic A2 path from normalized
operations plus released raw archives. It excludes capture, raw-to-normalized
conversion, and live-agent overhead; automatic annotation cost is instrumented
on the complete AgentRewardBench and Git populations, while the reported
54.36-minute artifact envelope is not model latency.
% 结果适用于声明的 population 与 annotation protocol。RQ4 测量 fixed-input replay 与 deterministic A2 path，不包含 capture、raw-to-normalized conversion 与 live-agent overhead；automatic annotation 成本已在完整的 AgentRewardBench 与 Git population 上插桩测量，54.36 分钟的 artifact envelope 并非模型时延。

\section{Related Work}
% 相关工作

\textbf{Agent observability.}
Platforms aggregate spans, metadata, and evaluations~\cite{langsmith,langfuse,
otel,datadog-llmobs}; Datadog Patterns and LangSmith Insights derive
cross-trace hierarchies and roll up metrics, NeMo profiles instrumented
workflows, and OpenTelemetry Profiles links profiles to traces~\cite{datadog-patterns,
langsmith-insights,nemo-agent-toolkit-profiler,otel-profiles}. \sys complements
these grouping, rollup, and trace-linkage systems by recursively assigning
shared semantic responsibility over a preserved source-call tree and folding
conserved resource measures into standard pprof profiles.
% Agent observability 平台聚合 span、metadata 与 evaluation；\sys 在保留的 source-call tree 上递归分配共享语义责任，并把守恒的资源度量折叠为标准 pprof profile，补充这些 grouping/rollup/trace-linkage 系统。

\textbf{Cross-run agent analysis.}
TraceProbe normalizes coding traces into canonical actions and process
diagnostics, Graphectory builds cyclic action/navigation graphs and aggregates
phase patterns~\cite{traceprobe2026,graphectory2026}, Act$\cdot$onomy supplies
a fixed three-level behavior taxonomy, CHIEF builds task/subtask causal graphs
for oracle-guided failure attribution~\cite{actonomy2026,chief2026}, Hodoscope
compares behavior distributions to human review, and TraceGraph builds shared
decision landscapes that guide recovery~\cite{hodoscope2026,tracegraph2026}.
\sys complements these canonical-action, recurring-structure, and
analysis-to-decision systems with shared variable-depth responsibility
annotations that cover native call evidence, fold across runs, and replay the
same boundaries under different additive measures in a standard profiler.
% TraceProbe、Graphectory、Actonomy、CHIEF、Hodoscope 与 TraceGraph 建立了 canonical action、跨运行结构与 decision 导向分析；\sys 用覆盖原生 call evidence、跨运行折叠、可跨度量重放的共享变深 responsibility annotation 补充它们。

\textbf{Profiling and diagnosis.}
pprof and flame graphs fold runtime stacks, whereas Pivot Tracing dynamically
groups measurements across causally related events~\cite{pprof,
flamegraphs,pivottracing}. AgentRx diagnoses failures, CodeTracer reconstructs
per-run states, and localization benchmarks score faulty steps, agents, or
expert-supported perspectives~\cite{agentrx,li2026codetracer,agentprocessbench,
hintbench,traceelephant,mpbench2026}. \sys applies the profiler's
population-level principle to agents by annotating recurring semantic
responsibility over completed trajectories without requiring code identity or
treating runtime nesting as semantic truth.
% pprof/flame graphs 折叠运行时栈，Pivot Tracing 跨因果事件分组；AgentRx、CodeTracer 与 localization benchmark 关注单次诊断；\sys 把 profiler 的群体级原则用于智能体：在完整轨迹上标注重复语义责任并折叠，不要求代码 identity，也不把运行时嵌套当作语义真相。

Agent observability needs profiling, not only debugging. \sys recursively

\subsection{Recurrence Backend Details}
\label{app:recurrence}

The Rust inducer counts adjacent action transitions in reference sessions and
scores each transition by normalized pointwise mutual information (NPMI),
$\mathrm{NPMI}(a,b)=
\ln[p(a,b)/(p_L(a)p_R(b))]/-\ln p(a,b)$, with all three probabilities defined
over the same transition sample space~\cite{bouma2009npmi}.

Occurrence-weighted one-dimensional $k$-means with $k=2$~\cite{macqueen1967}
initializes at the minimum and maximum scores, assigns distance ties to the
lower center, and uses the converged midpoint as a global cutoff. The inducer
applies the same procedure to action-changing transitions for a second cutoff.
Same-action pairs use the global cutoff, whereas different-action pairs use the
smaller cutoff, which can remove a boundary produced by the global rule but
cannot add one. When every reference and target operation also has a nonempty
\texttt{action\_detail}, the inducer fits the same recurrence model to the
compound signature. Detailed continuity may remove a coarse boundary but can
never add one. Missing, unseen, or weak detail falls back exactly to the coarse
decision. Segment names remain coarse run-length-compressed action sequences.
The inducer reads only session identity, input order, action, and optional
action detail, not target annotations or resource weights.
% Rust inducer 统计参考 session 中的相邻 action 转移，并用 NPMI 评分；所有概率来自同一转移样本空间。按出现次数加权的一维 k-means（k=2）从最小和最大分数初始化，将距离相同的点分到较低中心，并用收敛后两个中心的中点作为全局阈值；在 action-changing occurrence 上进行同样校准得到 cross-action 阈值。相同 action 使用全局阈值，不同 action 使用两者中较小者。reference 与 target 均有完整 action_detail 时，构造器对复合 signature 使用相同 recurrence 模型；detail continuity 只能删除粗边界而不能新增，缺失、未见或弱 detail 精确回退到粗决策。segment 名称仍只使用粗 action。评分标签与资源权重不参与构造。

An optional reference-calibrated recurrence mode uses the same NPMI score but
selects one scalar cutoff that maximizes per-operation B$^3$ F1 on disjoint
reference groups. The mode enumerates score intervals, resolves exact ties
toward the smallest cutoff, and never reads target groups. Label-free
$k$-means remains the default.
% 可选的 reference-calibrated recurrence 模式保持同一 NPMI score，并在与目标不重叠的参考分组上选择使每个 operation 等权的 B$^3$ F1 最大的单一阈值。它枚举有限 score interval，在完全平局时选择最小阈值，且不读取目标分组；无标签 k-means 规则仍是默认模式。

\subsection{Operation-Identity Canonicalization}
\label{app:canonicalization}

Before folding, one fixed source-only action--object map canonicalizes the A2
display identity. A boundary-safe refinement retains a canonical action and
the minimum source words needed whenever two adjacent paths would otherwise
become equal; unresolved collisions fail closed. Equal canonical names receive
one stable operation ID across sessions. The complete replay reduces 5{,}537
open-vocabulary names to 1{,}434 two- or three-word identities with zero
adjacent path collision, while preserving every temporal mark occurrence.
% 折叠前，一个固定且仅使用 source 的 action--object 映射规范化 A2 的显示 identity；若相邻路径将变成相同，boundary-safe refinement 保留 canonical action 与最少的 source 区分词，无法区分则 fail closed；相同 canonical 名称在跨 session 共享稳定 operation ID。完整重放将 5,537 个开放名称压缩为 1,434 个二到三词 identity，且不删除任何时间边界。

The A2 representation repair attaches a one-turn root-only prefix to its first
nested responsibility: when such a mark is immediately followed by its first
responsibility, the first turn receives the complete root--responsibility path,
eliminating artificial leaf groups without reading a stage label.
% A2 的表示修复把 one-turn root-only prefix 归入其首个嵌套 responsibility：当该 mark 紧邻其第一个 responsibility 时，首 turn 直接采用完整 root--responsibility path，从而在不读取 stage label 的情况下消除伪 leaf group。

\subsection{RQ2 Scoring Details}
\label{app:rq2-scoring}

Of HINTBench's reported 629 trajectories, the released test snapshot used here
contains 536. A separate 80-trajectory validation snapshot selects one of 24
field orders before all 536 tests are scored.

AgentProcessBench averages judge votes within a group. HINTBench and

bound~\cite{wilson1927} of its frozen positive-prediction fraction; an
operation receives the maximum score over prefixes containing it.

\subsection{A2 Reconstruction Cost Detail}
\label{app:a2-reconstruction}

We then reconstruct the adopted A2 path three times on all 405 CodeTrace
sessions (17{,}148 source-native turns and 20{,}866 operations). Joining the
fixed target operations to released raw archives and constructing source-only
Agent packets takes 501.64\,s median. Deterministic annotation assembly,
root-prefix repair, validation, and name canonicalization take 3.54\,s.
Afterward, the current source-preserving stack constructs either the
operation-count or 494{,}862{,}929-token profile in 1.17\,s median. Every

% 在全部 405 条 CodeTrace session 上，A2 source-packet reconstruction 的中位时间为 501.64 秒，deterministic assembly/root repair/name canonicalization 为 3.54 秒；随后 operation 与 token profile 均以 1.17 秒中位重放，并精确保守质量。

\subsection{OSWorld-Human Boundary Study Detail}
\label{app:osworld}

threshold on training sessions and predicts every held-out session once.
% 我们评估一个监督式 Bernoulli Naive Bayes 相邻边界预测器。模型家族、用于构造相邻对特征的九个可见 operation 字段、特征构造和训练流程在评估前固定；每个 session-held-out cross-validation fold 只使用训练 session 拟合参数和选择阈值，并恰好预测每个 held-out session 一次。

coarse arm. Because we designed the recurrence rule after inspecting earlier
results on this corpus, these results are development evidence rather than
independent cross-family confirmation.
% 我们还用相同的五个 session fold 运行内置 recurrence inducer：每个 held-out fold 仅使用其他 session 的可见 action 转移作为无标签参考。OSWorld-Human 不提供非冗余 action detail，因此 multi-resolution constructor 精确回退到粗粒度分支。由于 recurrence 原理是在查看该语料的早期结果后选定的，我们将其作为机制开发证据，而非独立的跨 family 验证。

annotations to fit one NPMI cutoff, while held-out folds contribute only visible

% 可选的 reference-calibrated recurrence 模式使用同一训练 fold 的 operation 及其 group 标注拟合一个 NPMI cutoff；held-out fold 在预测固定前只提供可见 action。
Controls place a boundary after every operation, visible action change, or

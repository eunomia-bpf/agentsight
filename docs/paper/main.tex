\section{Introduction}
\label{sec:intro}

%% ¶1: Background + context
AI agents~\cite{sweagent,codex,claudecode,osworld} orchestrate multi-step activities
across a high-level intent layer (prompts, LLM calls, and tool invocations) and
a low-level system-effects layer (process spawns and file and network I/O).
% AI 智能体~\cite{sweagent,codex,claudecode,osworld}编排跨越两层的多步骤活动：高层意图（提示词、LLM 调用、工具调用）和低层系统副作用（进程创建、文件和网络 I/O）。
As agents evolve from short scripts into complex systems, production teams
accumulate many trajectories over weeks or months.
% 随着智能体从短小脚本发展为复杂系统，生产团队会在数周或数月内积累大量轨迹。

%% ¶2: Problem
To improve agent quality, safety, and cost efficiency, developers
need to analyze operational behavior across trajectories and
interactions.
Which categories of tasks consume the most token budget? Where do
failures concentrate across workflows? Which behavioral patterns
trigger unsafe system effects?
% 为了提高智能体质量、安全性和成本效率，开发者需要跨轨迹和交互分析运维行为。哪类任务消耗最多 token 预算？故障跨工作流集中在哪里？哪些行为模式触发不安全系统副作用？
At scale, manual trajectory inspection is slow and expensive~\cite{agentrewardbench},
while per-trajectory LLM judging requires a separate evaluator pass for every
run~\cite{agentatlas,llm-as-judge}.
% 在规模化时，人工轨迹检查缓慢且昂贵，而逐轨迹 LLM judging 需要为每次运行单独执行一次 evaluator。
Profiling provides the aggregation method these questions require.
Traditional systems profilers attribute resource consumption to responsible
entities rather than debug or trace individual executions.
% 在传统系统软件中，profiling 通过聚合将资源消耗归因到负责实体来回答这些问题，区别于单次执行调试和 tracing。

%% ¶3: Existing solutions
Existing agent tools provide rich tracing, metadata aggregation, and population
dashboards~\cite{langsmith,langfuse,phoenix,otel,datadog-llmobs,laminar-signals}.
Some now derive hierarchical categories across traces and aggregate latency,
cost, or evaluation metrics~\cite{langsmith-insights,datadog-patterns}.
They do not provide source-linked, additive cross-layer effects as selectable
pprof-compatible operation-stack projections.
% 现有智能体工具提供 tracing、tag/metadata 聚合和群体级 dashboard；部分工具也会跨 trace 派生分层类别并聚合 latency、cost 或 evaluation metric，但不提供带源谱连接的可加跨层副作用及可选择的 pprof 兼容 operation-stack 投影。

%% ¶4: Challenge — why traditional profiling doesn't transfer directly
Adapting profiling to agent trajectories creates two challenges, detailed in
Background and Motivation.
% 将 profiling 适配到智能体轨迹具有两个挑战，详见 Background and Motivation。
Traditional profilers use stable function names to identify responsible code
paths and runtime call nesting to provide the attribution
hierarchy~\cite{pprof,flamegraphs}.
% 在传统软件中，负责实体是代码路径。Profiling 是直接的，因为函数名是稳定的，运行时调用嵌套提供归因层次。
Agent responsibility instead lies in semantic categories such as task intent
and tool operation.
% 智能体行为有根本不同。要回答上述问题，负责实体需要是语义类别（如任务意图和工具操作），而非代码路径。
Agent trajectories lack both properties.
% 智能体轨迹缺乏使传统 profiling 成为可能的两个特性。
Natural-language prompts provide no stable identifiers for shared intent.
% 提示词是自然语言，表达相同意图的两个提示词没有共同字符串。
Agent events also do not nest like function calls. A prompt sequence may
represent one or multiple tasks, and one task may belong to a larger task.
% 智能体事件没有运行时调用栈层次，因为提示词、工具调用和系统副作用不像函数调用那样通过执行嵌套产生栈帧。

%% ¶5: Model
Agent observability needs profiling, not only debugging.
% 智能体可观测性需要 profiling，而不仅仅是 debugging。
Despite these differences, the fundamental profiling methodology transfers to
agent trajectories by projecting resources onto responsible entities,
assigning stable tags, and attributing resources hierarchically.
% 尽管有这些差异，基本的 profiling 方法论可以迁移到智能体轨迹：将资源投影到负责实体、赋予稳定标签、分层归因。
We propose a \emph{semantic operation stack model} with two
components.
% 我们提出一个包含两个组件的语义 operation stack 模型。
\emph{Operations} are uniform records with string fields and
additive measures that represent all agent activities (prompts, LLM
calls, tool invocations, and system effects) without type-specific
objects.
% Operation 是带有字符串字段和可加度量的统一记录，表示所有智能体活动（提示词、LLM 调用、工具调用和系统副作用），无需特定类型对象。
\emph{Operation stacks} provide hierarchical attribution, replacing the runtime call stack.
% Operation stack 提供分层归因，替代运行时调用栈。
Different field choices change the attribution granularity.
The same operations can be attributed by task category, execution phase,
session, or action type (Figure~\ref{fig:flamegraph}).
% 选择不同字段改变归因粒度：同一组 operation 可按任务类别、执行阶段、会话或操作类型归因（Figure~\ref{fig:flamegraph}）。

%% ¶6: This paper + system + results
We implement this model in \sys, an offline profiler that compiles
local agent trajectories into pprof-compatible profiles~\cite{pprof}
(Figure~\ref{fig:architecture}).
% 我们在 \sys 中实现此模型，这是一个离线 profiler，将本地智能体轨迹编译为 pprof 兼容的 profile（Figure~\ref{fig:architecture}）。
Two pluggable mechanisms instantiate the model.
% 两个可插拔机制实例化此模型。
\emph{Intent attribution} derives stable, low-cardinality tags from natural-language fields via regex rules, a local LLM tagger, or unsupervised clustering.
% 意图归因通过正则规则、本地 LLM 标注器或无监督聚类从自然语言字段派生稳定、低基数的标签。
This gives agents the stable tags that traditional profiling gets
for free from function names.
% 这为智能体提供了传统 profiling 从函数名免费获得的稳定标签。
\emph{Stack construction} builds the attribution hierarchy, either from a user-specified field list or by automatically detecting boundaries between distinct work phases.
% 栈构造构建归因层次，可通过用户指定的字段列表或自动检测不同工作阶段之间的边界。
On a fixed suite of 20 real Codex tasks, the existing scoped source-lineage
path reaches 100.0\% precision and 96.6\% recall while rejecting all 1{,}629
concurrent-control effects. Current \sys then folds all 1{,}520 attributed
effects and exactly preserves the total weight of all five manifest-defined
task categories.
% 在固定的 20 个真实 Codex 任务上，既有范围化源谱路径达到 100.0\% precision 和 96.6\% recall，并拒绝全部 1,629 个并发对照副作用；当前 AgentProf 随后折叠全部 1,520 个已归因副作用，并精确保留五个 manifest 定义任务类别的总权重。
On 325 real Codex and Claude trajectories (183{,}714 system observations),
prompt tags reduce mixed system-effect weight from 90.4\% to 36.7\%, while a
session-only view leaves 84.4\% mixed.
% 在 325 个真实 Codex 和 Claude 轨迹（183,714 个系统观测）上，prompt tag 将混合 system-effect 权重从 90.4% 降至 36.7%，而 session-only 视图仍有 84.4% 混合。
Across three complete public benchmarks totaling 27{,}346 labeled
steps~\cite{agentprocessbench,hintbench,traceelephant},
target-blind semantic profiles improve problem concentration over raw action.
Average precision (AP) rises from 0.556 to 0.588 on AgentProcessBench, while inspection work falls
from 46.29\% to 41.57\% at 80\% recall on HINTBench and from 46.64\% to
19.55\% at 50\% recall on TraceElephant.
% 在三个完整公开基准共 27,346 个带标签步骤上，目标盲语义 profile 相比 raw action 提高了问题集中度：AgentProcessBench 的 AP 从 0.556 提升到 0.588；HINTBench 在 80% 召回率下的检查工作量从 46.29% 降至 41.57%；TraceElephant 在 50% 召回率下从 46.64% 降至 19.55%。
On 287 session-held-out OSWorld-Human task instances~\cite{osworldhuman}, a pre-specified supervised
boundary predictor evaluated out of fold reaches
0.739 F1 versus 0.645 for the strongest simple control and preserves human
groups at 0.816 operation-weighted B$^3$ partition F1 versus 0.678.
% 在 287 个 session-held-out OSWorld-Human 任务实例上，预先指定的监督式边界预测器经折外评估达到 0.739 F1，最强简单对照为 0.645；其人工分组保持度达到 0.816 的 operation-weighted B$^3$ partition F1，对照为 0.678。
On the exact union of four public operation workloads, \sys builds a
27{,}765-operation semantic profile in 1.17\,s with 464.5\,MiB maximum
resident set size (RSS),
adding 18.2\% time and 1.3\% memory over a raw-action cost control.
% 在四个公开 operation workload 的精确并集上，\sys 用 1.17 秒构建包含 27,765 个 operation 的语义 profile，最大 RSS 为 464.5 MiB；相比 raw-action 成本对照，时间和内存分别增加 18.2% 和 1.3%。

\section{Background and Motivation}
\label{sec:background}

\subsection{LLMs and AI Agents}
% AI 智能体

A typical agent trajectory interleaves two layers of
activity~\cite{sweagent,codex,claudecode,agentsight}.
% 典型的智能体轨迹交织两层活动。
At the intent layer, the agent receives a user prompt, issues LLM calls, and
invokes tools for code execution, web search, and file editing.
% 在意图层，智能体接收用户提示词、发出 LLM 调用并调用工具（代码执行、网络搜索、文件编辑）。
Each tool invocation triggers lower-layer system effects, including process
spawns, file reads and writes, and network requests~\cite{agentsight}.
% 每次工具调用在下层触发系统副作用：进程创建、文件读写和网络请求。
A single trajectory may contain hundreds of such intent-effect
cycles, and a production team accumulates many trajectories over
time.
% 单条轨迹可能包含数百个这样的意图-副作用循环，生产团队随时间积累许多轨迹。

\subsection{System Profiling}
% 系统 Profiling

Profiling aggregates measurements to attribute resource consumption to
responsible entities, in contrast to single-execution debugging and tracing.
% Profiling 通过聚合将资源消耗归因到负责实体，区别于单次执行调试和 tracing。
In traditional software, the profiling pipeline uses three steps: (1)~a
profiler periodically samples execution state, (2)~it attaches each sample to
the current call stack, and (3)~it merges samples with identical
stacks~\cite{pprof,flamegraphs}.
% 在传统软件中，profiling 管线如下工作：profiler 周期性采样执行状态，将每个样本附加到当前调用栈，合并具有相同栈的样本。
Flame graphs~\cite{flamegraphs} and pprof~\cite{pprof} call graphs visualize
aggregate cost as width or node size.
% 火焰图~\cite{flamegraphs}和 pprof~\cite{pprof} 调用图可视化其结果，宽度或节点大小代表聚合开销。
Perfetto~\cite{perfetto} generalizes this with SQL-based analysis
and derived events.
% Perfetto~\cite{perfetto} 通过基于 SQL 的分析和衍生事件进行泛化。
These tools commonly begin with stable code identifiers and runtime stacks.
Pprof can also aggregate labels and promote \texttt{tagroot}/\texttt{tagleaf}
values to pseudo-frames.
% 这些工具通常从稳定的代码标识符和运行时栈开始；pprof 也可以聚合标签，并将 \texttt{tagroot}/\texttt{tagleaf} 值提升为伪帧。
Agent trajectories instead must first obtain stable semantic responsibility
fields and connect them to downstream effects before such profile views exist.
% 智能体轨迹则必须先获得稳定的语义责任字段，并将其连接到下游副作用，之后才能形成这类 profile 视图。

\subsection{Challenges for Agent Profiling}
% 智能体 Profiling 的挑战

Existing tools~\cite{langsmith,langfuse,phoenix,otel} record agent events as
per-execution span trees that support single-run debugging.
% 现有工具~\cite{langsmith,langfuse,phoenix,otel}将智能体事件记录为按执行划分的 span 树，有效调试单次运行。
AgentSight~\cite{agentsight} bridges intent and system-effect layers
by correlating eBPF-captured system events with intercepted LLM
traffic, but the resulting recordings still lack aggregate profiling.
% AgentSight~\cite{agentsight} 通过关联 eBPF 捕获的系统事件与拦截的 LLM 流量来桥接意图层和系统副作用层，但生成的记录仍缺乏聚合分析能力。


Adapting profiling to agent trajectories faces two core challenges.
% 将 profiling 适配到智能体轨迹面临两个核心挑战。
The first is that the responsible entities differ.
% 第一个挑战是负责实体不同。
In traditional software, profiling attributes cost to code paths, but
in agent trajectories the relevant entities are semantic categories
such as task intent and workflow phase.
% 在传统软件中，profiling 将开销归因到代码路径，但在智能体轨迹中，相关实体是语义类别（如任务意图和工作流阶段）。
Existing standards~\cite{otel,openinference} represent application-supplied
attributes in spans, but
natural-language histories do not automatically provide stable responsibility
categories because prompts or tool invocations expressing the same intent may
use different strings.
% 现有标准可以在 span 中表示应用提供的属性，但自然语言历史不会自动提供稳定的责任类别：表达相同意图的两个提示词和工具调用可能使用不同字符串。

The second challenge is that agent trajectories have no runtime call hierarchy
that automatically supplies semantic attribution.
% 第二个挑战是智能体轨迹没有能够自动提供语义归因的运行时调用层次。
In CPU profiling, the call stack determines attribution at every level.
For example, \texttt{malloc}'s cost belongs simultaneously to \texttt{parse},
\texttt{process}, and \texttt{main}.
% 在 CPU 分析中，调用栈决定了每个层级的归因：\texttt{malloc} 的开销同时属于 \texttt{parse}、\texttt{process} 和 \texttt{main}。
A prompt sequence may constitute one task or several. A task may also belong to
a larger workflow, yet no runtime mechanism marks these boundaries or
determines the appropriate attribution granularity.
% 一串提示词可能构成一个任务也可能是多个任务，一个任务可能是更大工作流的一部分，但没有运行时机制标记这些边界或决定在哪个粒度归因开销。
We quantify this in RQ1 in Evaluation.
% 我们在 Evaluation 的 RQ1 中量化这一点。

\subsection{Design Requirements for Agent Profiling}
% 智能体 Profiling 的设计需求

Traditional profiling relies on three mechanisms that the call stack provides automatically.
% 传统 profiling 依赖调用栈自动提供的三种机制。
Agent profiling needs all three but must achieve them without a call stack:
% 智能体 profiling 需要这三种机制，但必须在没有调用栈的情况下实现：

\begin{description}
\item[D1: Cross-layer resource projection.]
In traditional profiling, each sample is taken inside a call context, so resource consumption is automatically attributed to the code path that caused it.
% 在传统 profiling 中，每个采样在调用上下文内完成，因此资源消耗自动归因到造成它的代码路径。
Agent activities span an intent layer of prompts and LLM calls and a
system-effects layer of file I/O and process spawns.
% 智能体活动跨越两层：意图（提示词、LLM 调用）和系统副作用（文件 I/O、进程创建）。
The profiler must connect system-layer resource consumption to intent-layer semantic categories.
% 分析器必须将系统层的资源消耗连接到意图层的语义类别。
\item[D2: Stable tags for folding.]
In traditional profiling, function names are stable identifiers that enable folding identical stacks.
% 在传统 profiling 中，函数名是稳定标识符，能够折叠相同的栈。
Agent prompts are natural language, so the profiler must derive short, stable, repeatable tags before folding.
% 智能体提示词是自然语言，因此分析器必须在折叠前派生短小、稳定、可重复的标签。
\item[D3: Hierarchical attribution.]
In traditional profiling, the runtime call stack provides the attribution
hierarchy. Function calls nest, and folding identical stacks produces the tree
that profiles visualize.
% 在传统 profiling 中，运行时调用栈提供归因层次：函数调用嵌套，折叠相同的栈产生 profile 可视化的树。
Agent span trees do not encode semantic responsibility through function-call
nesting, so the profiler must construct attribution hierarchies from the data.
% 智能体 span 树不通过函数调用嵌套编码语义责任，因此分析器必须从数据中构造归因层次。
\end{description}

\section{Design}
% 设计
\label{sec:design}

Cross-layer resource projection, stable tags, and hierarchical attribution
drive the design.
% 三个需求（跨层资源投影、稳定标签和分层归因）驱动了设计。
Operations, defined in the Semantic Operation Stack Model, satisfy D1 by representing intent and system-effect activities in a single record with tag inheritance, so intent-layer tags propagate to the system effects they trigger.
% Semantic Operation Stack Model 中定义的 operation 通过将意图和系统副作用活动表示在带标签继承的单一记录中满足 D1，使意图层标签传播到其触发的系统副作用。
\emph{Intent attribution}, described under Algorithms, satisfies D2 by deriving stable tags from natural-language fields.
% Algorithms 中的意图归因通过从自然语言字段派生稳定标签满足 D2。
\emph{Operation stacks} satisfy D3. They replace the
runtime call stack with query-time field projections that attribute resources
at multiple granularities, allowing the same data to support multiple views
without rebuilding the input.
% Operation stack 通过以查询时字段投影替代运行时调用栈，在多个粒度层级归因资源来满足 D3，使同一数据支持多种视图而无需重建输入。

The profiling pipeline has four stages: (1)~parse raw trajectories into operations, (2)~enrich operations via intent attribution or mapping rules, (3)~project each operation onto a stack frame sequence chosen at query time, and (4)~fold operations with identical stacks, summing their weights.
% 分析管线有四个阶段：(1) 将原始轨迹解析为 operation，(2) 通过意图归因或映射规则丰富 operation，(3) 将每个 operation 投影到查询时选择的栈帧序列上，(4) 折叠具有相同栈的 operation 并求和权重。

\subsection{Semantic Operation Stack Model}
% 语义 Operation Stack 模型
\label{sec:ops}

%% ¶1: Operations
Because agent activities span both the intent and system-effect
layers described in Background and Motivation, a profiler should not
distinguish between them in the data representation.
% 由于智能体活动跨越 Background and Motivation 中描述的意图层和系统副作用层，分析器不应在数据表示层面区分它们。
\sys therefore represents every activity as an \operation, a weighted record
with string fields and additive measures.
% 因此 \sys 将每个活动表示为单一抽象——operation，一个带有字符串字段和可加度量的加权记录。
Each operation carries string fields (\texttt{project},
\texttt{agent}, \texttt{session}, \texttt{prompt\_tag},
\texttt{kind}, \texttt{model}, \texttt{path}, \texttt{domain},
\texttt{status}, \ldots) and additive measures (token count,
duration, event count).
% 每个 operation 携带字符串字段（\texttt{project}、\texttt{agent}、\texttt{session}、\texttt{prompt\_tag}、\texttt{kind}、\texttt{model}、\texttt{path}、\texttt{domain}、\texttt{status} 等）和可加度量（token 数、持续时间、事件数）。
A prompt, an LLM call, a tool invocation, a file read, a GUI click,
and a process event are all operations with the same schema, distinguished only by which fields carry values.
% 提示词、LLM 调用、工具调用、文件读取、GUI 点击和进程事件都是具有相同 schema 的 operation，仅通过哪些字段有值来区分。
When a tool invocation triggers system effects, ingestion propagates its
semantic fields to the resulting operations, allowing downstream resource
weights to fold under the responsible intent.
% 当工具调用触发系统副作用时，输入处理将其语义字段传播到生成的 operation，使下游资源权重能够折叠到负责的意图之下。

%% ¶2: Operation Stacks
\label{sec:stacks}
An \opstack provides hierarchical attribution for agent trajectories, replacing the runtime call stack.
% 一个 operation stack 为智能体轨迹提供分层归因，替代运行时调用栈。
In CPU profiling, the call stack determines which code paths
share responsibility for a resource cost.
% 在 CPU 分析中，调用栈决定哪些代码路径共同承担资源开销。
An operation stack serves the same role. An ordered list of fields
$[f_1, f_2, \ldots, f_k]$ projects each operation $o$ to a frame
sequence $\langle o.f_1, o.f_2, \ldots, o.f_k \rangle$, and
operations with identical sequences are merged, summing their
weights.
% Operation stack 承担相同角色：有序字段列表 $[f_1, f_2, \ldots, f_k]$ 将每个 operation $o$ 投影到帧序列 $\langle o.f_1, o.f_2, \ldots, o.f_k \rangle$，具有相同序列的 operation 被合并，权重求和。
Unlike a call stack, the fields are chosen at query time, not
determined by execution.
% 与调用栈不同，字段在查询时选择，而非由执行决定。
The same operations can therefore support a flat task summary, a per-session
tree, a semantic phase/action hierarchy, or a trajectory organized by the
dataset's own annotations. Changing the fields changes attribution without
changing the data.
% 因此同一组 operation 可归因为扁平任务摘要、固定会话树、语义阶段/操作层次或使用数据集自身标注的轨迹，改变字段即改变归因方式而无需改变数据。
Sessions and spans are optional fields, not hierarchy levels. The same data
supports debugging views with \texttt{session} and aggregate profiling views
without that field.
% 会话和 span 是可选的 operation 字段而非固定层次级别，因此同一数据既支持调试视图（包含 \texttt{session}）也支持聚合 profiling 视图（排除它）。
A view is a triple $(\varphi, \sigma, w)$. The predicate $\varphi$ selects
participating operations, the stack function $\sigma = [f_1, \ldots, f_k]$
maps each operation to its frame sequence, and the weight function $w$ assigns
a nonnegative measure.
% 一个视图是三元组 $(\varphi, \sigma, w)$：谓词 $\varphi$ 选择参与的 operation，栈函数 $\sigma = [f_1, \ldots, f_k]$ 将每个 operation 映射到其帧序列，权重函数 $w$ 赋予非负度量。
Four built-in views cover common questions: (1)~\texttt{tokens} weights LLM
calls by token count, (2)~\texttt{time} weights timed operations by duration,
(3)~\texttt{files} weights file operations by event count, and
(4)~\texttt{network} weights network operations by event count.
% 四个内置视图覆盖常见问题：\texttt{tokens}（LLM 调用按 token 数加权）、\texttt{time}（所有计时操作按时长加权）、\texttt{files}（文件操作按事件数加权）和 \texttt{network}（网络操作按事件数加权）。

\subsection{Algorithms}
% 算法
\label{sec:intent}

\paragraph{Intent attribution.}
% 意图归因。
Intent attribution maps natural-language prompts to short, stable,
repeatable tags, giving agent trajectories the stable identifiers that traditional
profiling gets for free from function names, as discussed in Background and
Motivation.
% 意图归因将自然语言的提示词映射为短小、稳定、可重复的标签，为智能体轨迹提供传统 profiling 从函数名免费获得的稳定标识符，详见 Background and Motivation。
The framework supports three pluggable backends.
% 该框架支持三种可插拔后端。
Explicit rules provide repeatable user control, a local model tags
natural-language fields, and unsupervised grouping helps discover candidate
categories for later rule authoring.
% 显式规则提供可重复的用户控制，本地模型标注自然语言字段，无监督分组帮助发现供后续规则编写使用的候选类别。
Structured trajectories use the same interface to derive fields from existing
action and quality attributes.
% 结构化轨迹使用同一接口从现有 action 和质量属性派生字段。
All backends emit ordinary operation fields, keeping the stack model
independent of how a tag was obtained.
% 所有 backend 都输出普通 operation 字段，使 stack 模型独立于标签的获取方式。

\paragraph{Stack construction.}
% 栈构造。
Stack construction builds attribution hierarchies from
available fields.
% 栈构造从可用字段构建归因层次。
When users supply an ordered list of fields, the projection is direct.
% 当用户提供有序字段列表时，投影是直接的。
When no field list is supplied, \sys induces operation stacks automatically.
It detects boundaries from visible differences between adjacent operations and
uses them to form variable-depth groups, while a configurable depth cap
controls stack granularity.
% 它从相邻 operation 之间的可见差异中检测边界，并使用这些边界形成可变深度的分组。
% 诱导的栈具有可变深度，可配置的深度上限控制粒度。
This mode produces coarser groups than hand-specified stacks but
requires no domain knowledge, making it useful for initial
exploration, as evaluated in RQ1.
% 此模式产生比手动指定栈更粗的分组，但不需要领域知识，适用于初始探索，并在 RQ1 中评估。

\section{Implementation}
% 实现
\label{sec:impl}

\sys implements the semantic operation stack model as an offline Rust CLI
({$\sim$}9.8K LOC, Figure~\ref{fig:architecture}).
% \sys 将 operation 和 stack 模型实现为离线 Rust CLI（约 9.8K 行代码，Figure~\ref{fig:architecture}）。

\paragraph{Input reconstruction.}
% 输入重建。
\sys reads Codex and Claude Code local JSONL histories and operation JSONL.
AgentSight~\cite{agentsight} recordings first pass through a source-specific
adapter that emits supported operations; the current CLI does not read those
recordings directly. It then reconstructs prompts, LLM calls, tool invocations,
and their linked file and network effects.
% \sys 读取 Codex 和 Claude Code 本地 JSONL 历史及 operation JSONL。AgentSight~\cite{agentsight} 记录先经过源特定 adapter 转换为受支持的 operation；当前 CLI 不直接读取这些记录，随后重建 prompt、LLM 调用、工具调用及其连接的文件和网络副作用。

\paragraph{Field derivation and boundaries.}
% 字段派生和边界。
Regex rules are the production default. Each rule has the form
\texttt{KIND:TAG=REGEX}, and rules use first-match semantics. Agents can refine
the rules through repeated \sys runs until the unmatched rate falls below 5\%,
typically after 5--10 rounds.
% 正则规则是生产环境默认：规则格式为 \texttt{KIND:TAG=REGEX}，按顺序求值（首个匹配胜出）；agent 可以通过重复运行 \sys 细化规则，直到未匹配率降至 5\% 以下，通常需要 5--10 轮。
A local LLM tagger, such as a quantized 3B-parameter model through
llama.cpp~\cite{llamacpp},
generates a single-word tag per prompt with grammar-constrained decoding and
caching.
% 本地 LLM tagger（例如通过 llama.cpp~\cite{llamacpp} 运行的量化 3B 参数模型）使用语法约束解码和缓存为每个 prompt 生成单词标签。
TF-IDF~\cite{salton-buckley-1988} and
K-Means~\cite{macqueen1967} discover candidate prompt groups without predefined rules,
while mapping rules derive fields for structured trajectories, for example
\texttt{phase:navigate=type:(click|scroll|key)}.
% TF-IDF~\cite{salton-buckley-1988} 和 K-Means~\cite{macqueen1967} 在没有预定义规则时发现候选 prompt 分组，而 mapping rule 为结构化轨迹派生字段，例如 \texttt{phase:navigate=type:(click|scroll|key)}。

\paragraph{Boundary construction.}
% 边界构建。
The built-in Rust stack inducer scores adjacent operations using visible
token-set Jaccard distance, structured-field changes, segment balance, and
query-term overlap before placing boundaries. This path is distinct from the
optional Python TF-IDF/K-Means backend used to propose tagging rules.
% 内置 Rust stack inducer 使用可见 token 集合的 Jaccard 距离、结构化字段变化、segment balance 和 query-term overlap 对相邻 operation 评分后放置边界；该路径不同于用于提出 tagging rule 的可选 Python TF-IDF/K-Means backend。

\paragraph{Profile export.}
% Profile 导出。
Output formats are pprof protobuf for \texttt{go tool pprof -http}, folded
stacks for \texttt{flamegraph.pl}, standalone SVG flame graphs, and JSON.
% 输出格式包括 pprof protobuf（兼容 \texttt{go tool pprof -http}）、折叠栈文本（兼容 \texttt{flamegraph.pl}）、独立 SVG 火焰图和 JSON 摘要。

\section{Evaluation}
% 评估
\label{sec:eval}

\paragraph{Research questions.}
% 研究问题。
The evaluation answers four fixed paper-level questions:
% 评估回答四个固定的论文级研究问题：
\textbf{RQ1:} Does semantic profiling improve resource attribution?
\textbf{RQ2:} Does profiler output correspond to real problems?
\textbf{RQ3:} How accurate are the tags?
\textbf{RQ4:} What is the profiling cost?
Each following subsection states its protocol, reports the corresponding
evidence, and gives the strongest answer supported by that evidence.
% 后续每个小节都陈述其协议、报告相应证据，并给出该证据所支持的最强答案。

We use three classes of data.
% 我们使用三类数据。
The real-agent dataset comprises 325 readable trajectories (198~Codex,
50~Claude, and 77~Claude subagent) and 183{,}714 system observations from a
multi-month development project.
% 真实智能体会话：来自一个多月开发项目的 325 个可读本地会话（198 个 Codex、50 个 Claude、77 个 Claude 子智能体），包含 183,714 个系统观测。
The public annotated dataset comprises 15 real agent or human execution
families converted by mapping rules into 47{,}590 operations.
% 公开标注轨迹：15 个真实智能体或人类执行的家族，通过映射规则共计 47,590 个 operation。
These cover web agents (WebLINX~\cite{weblinx}, Mind2Web~\cite{mind2web}, AgentTrek~\cite{agenttrek}, WebShop~\cite{webshop}), API agents (API-Bank~\cite{apibank}, ToolBench~\cite{toolbench}, tau-bench~\cite{taubench}), coding agents (SWE-agent~\cite{sweagent}), and mobile/GUI agents (AndroidCtrl~\cite{androidcontrol}, GUI-Odyssey~\cite{guiodyssey}, ScaleCUA~\cite{scalecua}).
% 涵盖 web 智能体（WebLINX、Mind2Web、AgentTrek、WebShop）、API 智能体（API-Bank、ToolBench、tau-bench）、编码智能体（SWE-agent）和移动/GUI 智能体（AndroidCtrl、GUI-Odyssey、ScaleCUA）。
Four mapped families provide structured quality or boundary annotations,
including AgentRewardBench~\cite{agentrewardbench}, SATraj-OS~\cite{safactory},
AgentNet~\cite{agentnet}, and OSWorld-Human~\cite{osworldhuman}.
% 其中四个映射后的家族提供结构化质量或边界标注：AgentRewardBench、SATraj-OS、AgentNet 和 OSWorld-Human。
AgentProcessBench, HINTBench, and TraceElephant form the public
problem-localization set and provide the independent targets for
RQ2~\cite{agentprocessbench,hintbench,traceelephant}.
% 公开问题定位基准：AgentProcessBench、HINTBench 和 TraceElephant 为 RQ2 提供独立目标。
Of HINTBench's reported 629 trajectories, the current official test snapshot
enumerates 536. We use all 536 after selecting the field order on the separate
80-trajectory validation snapshot~\cite{hintbench}.
% HINTBench 报告 629 条基准轨迹；当前官方测试快照列出 536 条轨迹，我们在独立的 80 条验证轨迹上选择 field order 后使用了全部 536 条测试轨迹。

\subsection{RQ1: Resource Attribution}
% RQ1：语义分析能否改善资源归因？

RQ1 asks whether semantic profiling improves resource attribution beyond what
traditional tag-free tools provide.
% 我们测试语义标签是否能超越传统无标签工具改善资源归因。
We first test whether a source-linked path assigns system effects to a declared
agent process/tool lineage while rejecting concurrent controls. The fixed suite
runs 20 real Codex tasks and one concurrent negative control per task through
the existing R114-compatible AgentSight 0.2.37 capture path, then converts the
scoped joined effects to operation JSONL and folds them once with the current
\texttt{agentpprof 0.2.37} binary.
% 我们首先测试带源谱连接的路径能否将系统副作用归因到声明的 agent 进程/工具谱系，并拒绝并发对照。固定套件通过既有 R114 兼容 AgentSight 0.2.37 捕获路径运行 20 个真实 Codex 任务及每任务一个并发负对照，再将范围内连接的副作用转换为 operation JSONL，并用当前 \texttt{agentpprof 0.2.37} 二进制折叠一次。

All 20 tasks and controls complete. The scoped join recovers 1{,}520 of 1{,}574
in-scope effects with no false positive (100.0\% precision, 96.569\% recall),
and none of 1{,}629 control effects joins. \sys emits 1{,}520 samples in 152
stacks, exactly preserving the input total and all five manifest-category
weights.
% 20 个任务及对照全部完成。连接路径恢复 1,574 个范围内副作用中的 1,520 个，0 个 false positive（precision 100.0\%、recall 96.569\%），且 1,629 个对照副作用均未连接。AgentProf 在 152 个 stack 中输出 1,520 个 sample，并精确保留输入总量及全部五个 manifest 类别权重。

This result establishes source fidelity for the suite's declared process/tool
scope and lossless folding by \sys. The task categories come from the fixed
manifest rather than automatic task inference.
% 该结果在套件声明的进程/工具范围内确立源谱 fidelity 及 AgentProf 无损折叠；任务类别来自固定 manifest，而非自动任务推断。
We run a semantic-axis ablation on 325 real Codex/Claude trajectories (183{,}714 system observations).
% 我们在 325 个真实 Codex/Claude 轨迹（183,714 个系统观测）上进行语义轴消融。
The prompt tags were produced by the local 3B-model backend described in
Implementation and are treated here as declared categories, not as an
independent correctness oracle.
% Prompt tag 由 Implementation 所述本地 3B 模型 backend 产生；本实验将其视为已声明类别，而非独立正确性 oracle。
We progressively add four tag-axis configurations: (1)~no tags, (2)~session
only, (3)~prompt only, and (4)~both. We then measure mixed-weight percentage,
defined as the fraction of system-effect cost in groups containing observations
from multiple task categories.
% 我们逐步添加标签轴（无标签、仅会话、仅提示词、两者兼有），测量混合权重百分比——混合了多个任务类别观测的桶中的系统副作用权重比例。
A lower mixed-weight percentage means fewer effects from different prompt-tag
categories remain in the same responsibility group.
% 更低的 mixed-weight 百分比意味着来自不同 prompt-tag 类别的副作用更少地留在同一个责任分组中。
The residual percentage measures weight in groups where the majority category accounts for less than 90\% of the group, capturing partial mixing.
% 残余百分比测量多数类别占桶内不到 90\% 的权重，捕获部分混合。

Figure~\ref{fig:rq1-separation} shows the result.
% Figure~\ref{fig:rq1-separation} 展示了结果。
Without semantic tags, nearly all system-effect cost falls into mixed groups.
For example, a flat \texttt{cargo~test} counter shows 2{,}903 executions but
cannot distinguish whether they came from \texttt{review}, \texttt{debug},
\texttt{refactor}, or \texttt{test} prompts.
% 没有语义标签时，几乎所有系统副作用权重落入混合桶：扁平的 \texttt{cargo test} 计数器显示 2,903 次执行，但无法区分来源。
The prompt tag is the decisive axis because it reduces both mixed weight and
residual by more than half and nearly doubles the number of unique stacks. It
separates observations that share the same system call but originate from
different task intents.
% 提示词标签是决定性轴：它将混合权重和残余都降低一半以上，唯一栈数量几乎翻倍，因为它分离了共享相同系统调用但来自不同任务意图的观测。
The session tag alone barely helps because trajectories typically contain multiple intent phases.
% 仅会话标签几乎没有帮助，因为会话通常包含多个意图阶段。

A tag-permutation test (1{,}000 shuffles, $p = 0.001$) confirms the separation is not random.
% 标签置换测试（1,000 次洗牌，$p = 0.001$）确认分离不是随机的。
The RQ1 experiment measures attribution conditional on the declared prompt
tags. The independent RQ3 experiment evaluates group-boundary accuracy.
% 该实验测量给定声明 prompt tag 时的归因；RQ3 当前的独立准确性证据涉及边界标签。
These results show that prompt-level semantic fields materially refine
responsibility views beyond tag-free aggregation.
% 这些结果表明，prompt 级语义字段相比无标签聚合显著细化了责任视图。

\begin{figure}[t]
\centering
\includegraphics[width=\linewidth]{figures/fig-rq1-separation.pdf}
\caption{RQ1 semantic-axis ablation on 183{,}714 system observations
from 325 real trajectories.
Bars show mixed weight and residual percentages on the left axis, and the line
shows unique stacks on the right axis.
Adding prompt tags reduces mixed weight from 90.4\% to 36.7\%
while increasing unique stacks from 12k to 25k.
Session tags alone barely help (84.4\%).}
\Description{Grouped bar chart with dual y-axis showing mixed weight
percentage, residual percentage, and unique stack count under four
semantic-tag projection choices.}
\label{fig:rq1-separation}
\end{figure}

Beyond tag separation, five field selections fold the same 13{,}265 annotated
operations into 9~dataset, 57~phase, 226~semantic, 455~action, or
3{,}757~per-session groups.
% 除标签分离外，五种字段选择将同样 13,265 个带标注 operation 折叠为 9 个 dataset、57 个 phase、226 个 semantic、455 个 action 或 3,757 个 per-session 分组。
Unlike a single-tag GROUP BY, these depths answer task-budget,
action-duplication, and session-detail questions. The same model covers all 15
trajectory families without type-specific objects.
% 不同于单标签 GROUP BY，这些深度回答 task budget、action duplication 和 session detail 问题；同一模型无需特定类型对象即可覆盖全部 15 个轨迹 family。

The \texttt{time} and \texttt{tokens} views of the same 325 trajectories share
only 7/10 top prompt categories (Spearman $\rho = 0.623$), and
\texttt{network}-tagged prompts rank 8th by time but 93rd by tokens.
% 同一 325 个轨迹的 \texttt{time} 和 \texttt{tokens} 视图仅共享 7/10 个顶级 prompt 类别（Spearman $\rho = 0.623$），且 \texttt{network} 标签 prompt 按时间排第 8、按 token 排第 93。
Thus, multiple weights expose bottlenecks that one metric would miss.
% 因此，多种权重暴露了单一指标会遗漏的瓶颈。

Without user-specified fields, automatic induction on six annotation tasks
produces a median of 12 groups, compared with 285 for the per-session view and
one for the flat view, and yields variable-depth stacks on 4/6 tasks.
% 在没有用户指定字段时，六个标注任务上的自动诱导产生中位 12 个分组（per-session 为 285，flat 为 1），并在 4/6 个任务上产生可变深度 stack。
We use independent problem annotations to score each group's problem density.
AP measures ranking quality, and inspection work measures the operations
traversed in that ranking.
% 独立问题标注评估每个分组的密度：AP 测量其排序质量，inspection work 测量该排序中遍历的 operation。
Automatic induction achieves a median AP of 0.276 versus 0.312 for
hand-specified stacks, while reducing inspection work to 65.3\% of flat
summaries without user configuration.
% 自动诱导的 AP 中位数为 0.276，手动指定 stack 为 0.312；无需用户配置时，检查工作量降至 flat summary 的 65.3%。

Figure~\ref{fig:flamegraph} shows the resulting flame graphs for the \texttt{tokens} and \texttt{files} views, illustrating that changing only the stack fields and weight function produces different aggregates from the same operations.
% Figure~\ref{fig:flamegraph} 展示了 \texttt{tokens} 和 \texttt{files} 视图的火焰图，说明仅改变栈字段和权重函数即可从同一组 operation 产生不同聚合。
Together, these results answer RQ1. Scoped source lineage rejects concurrent
controls, \sys preserves attributed weight across runs, and semantic
profiling provides multi-resolution, multi-weight, and automatically induced
attribution views over the resulting operations.
% 这些结果共同回答 RQ1：范围化源谱拒绝并发对照，AgentProf 在跨运行折叠中保留已归因权重，语义 profiling 在所得 operation 上提供多分辨率、多权重和自动诱导的归因视图。

\subsection{RQ2: Problem Correspondence}
% RQ2：分析器输出是否对应真实问题？

RQ2 asks whether profiler output corresponds to real problems by testing
whether a target-blind profile concentrates independently annotated
failures or risky steps into groups that a developer can inspect early.
% RQ2 测试目标盲的 profile 是否能将独立标注的故障或风险步骤集中到开发者可优先检查的分组中。
We evaluate complete public workloads from AgentProcessBench~\cite{agentprocessbench},
HINTBench~\cite{hintbench}, and TraceElephant~\cite{traceelephant}.
HINTBench development labels select among 24 fixed field orders. Its reported
test labels and all AgentProcessBench and TraceElephant targets remain held out
from tag, stack, and ranking construction. Only the final scorer reads them to
compute inspection work or, for AgentProcessBench, operation-weighted average
precision (AP) within each family and its equal-family macro average.
% 我们在 AgentProcessBench、HINTBench 和 TraceElephant 的完整公开 workload 上评估。HINTBench 的开发集标签用于从 24 个固定 field order 中选择一个；其报告的测试集标签以及 AgentProcessBench 和 TraceElephant 的全部目标标签均不参与 tag、stack 或排序构造。最终 scorer 计算 inspection work；对 AgentProcessBench，它先计算 family 内 operation-weighted AP，再报告等权 family macro average。
AgentProcessBench uses 20 released judge votes as its step signal and ranks
groups by mean risk. For HINTBench and TraceElephant, released localization
predictions provide the step signal, and groups are ranked by the maximum 95\%
Wilson lower bound~\cite{wilson1927} on hit density over their profile prefixes.
% AgentProcessBench 使用 20 个发布 judge 预测中判为错误的比例作为逐步 risk，并按分组平均 risk 排序。HINTBench 和 TraceElephant 使用发布的定位预测作为 step signal，并按各 profile prefix 上 hit density 的最大 95% Wilson 下界排序分组。
The raw-action control changes only the grouping field to each workload's
released action while keeping the step signal, ranking rule, scorer, input, and
full execution path fixed.
% Raw-action 对照仅将分组字段改为各 workload 发布的 action，同时保持 step signal、排序规则、scorer、输入和完整执行路径不变。

AgentProcessBench contains 1{,}000 trajectories from BFCL, GAIA, HotpotQA, and

Using the released target-blind risk signal, the semantic stack raises

% 在 TraceElephant 的全部 220 个真实失败执行上，语义 profile 在早期区间显著领先 raw action；但该结果为描述性证据，因为末端大规模同分层使预先设定的 80% recall 点需要完整检查，且配对区间跨零。

Together, the complete workloads answer RQ2 positively without claiming
uniform dominance: AgentProcessBench isolates semantic-specific concentration,

% 三个完整 workload 共同对 RQ2 给出肯定回答但不声称统一支配：AgentProcessBench 隔离出语义特异性集中，HINTBench 展示完整 profile 流水线相对原生、session 和逐步组织的优势，TraceElephant 展示强早期定位；operation stack 因而能暴露富集独立问题标签的重复分组，并同时呈现其高召回边界。

\subsection{RQ3: Tag Accuracy}
% RQ3：标签有多准确？

RQ3 asks how accurately categorical operation fields recover independent
annotations.
% RQ3 询问类别型 operation 字段恢复独立标注构造的准确程度。
RQ3 covers task, phase, and action labels produced by intent attribution or
mappings, as well as group boundaries used to construct the hierarchy. We
evaluate task partitions and group boundaries; phase, action, and literal tag
names remain outside the current evidence.
% 这些字段包括由意图归因或 mapping 产生的 task、phase 和 action 标签，以及用于构造 profile 层次的分组边界；当前证据测试 task partition 和 group boundary，不测试 phase、action 或 tag 的字面命名。

We hypothesize that pre-specified target-blind taggers or mappings recover
accurate, stable task, phase, and action labels and group boundaries on unseen
agent and task families.
% 固定正向假设是：预先指定的目标盲 tagger 或 mapping 能在未见过的智能体和任务家族上恢复准确、稳定的 task、phase、action 标签和分组边界。
Each component is scored against its corresponding independent annotations and
then profiled with the original additive weights.
% 每个组成部分都与其对应的独立标注进行评分，得到的 operation 字段使用原始可加权重进行 profiling。

We test all 287 OSWorld-Human task-instance sessions~\cite{osworldhuman} with complete group
annotations, covering 3{,}978 operations, 3{,}691 adjacent pairs, and 2{,}042
groups.
% 我们首先测试所有具有完整人工分组标注的 OSWorld-Human session：287 个 task-instance session 中的 3,978 个 operation，共 3,691 个相邻对和 2,042 个人工独立标注的动作组。
For the supervised Bernoulli Naive Bayes predictor~\cite{mccallum-nigam-1998},
we fixed the model family, nine input fields, adjacent-pair feature construction,
and training procedure before evaluation. Each session-blocked fold fits parameters and a threshold
only on training sessions, then predicts every held-out session once.
% 我们评估一个监督式 Bernoulli Naive Bayes 相邻边界预测器。模型家族、用于构造相邻对特征的九个可见 operation 字段、特征构造和训练流程在评估前固定；每个 session-blocked fold 只使用训练 session 拟合参数和选择阈值，并恰好预测每个 held-out session 一次。
The predicted boundaries define an ordinary group field that \sys projects and
folds through its released profile-construction path. This test covers supervised boundary
prediction and field integration, not the built-in Rust stack inducer described
in Implementation.
% 预测边界成为普通分组字段，\sys 随后通过发布的 profile-construction 路径投影并折叠该字段；本实验不测试 Implementation 中的内置 Rust stack inducer。
The three simple controls place a boundary after every operation, whenever the
visible action field changes, or whenever the visible phase field changes.
% 简单对照分别在每个 operation 后放置边界，或仅在可见 action 或 phase 字段变化时放置边界。
We report boundary precision, recall, and F1, plus operation-weighted B$^3$
partition F1~\cite{bagga-baldwin-1998-entity-based}, whose per-operation
predicted--human group overlap captures merging and fragmentation.
% 我们报告边界 precision、recall、F1，以及 operation-weighted B$^3$ partition F1；后者对每个 operation 的预测分组与人工分组重叠度求平均，同时反映合并与碎片化。

The supervised predictor reaches 0.739 boundary F1, 0.094 above the strongest

% 监督式预测器的边界 F1 达到 0.739，比最强简单对照高 0.094，并在五个 held-out fold 上均取得最高边界 F1。

% 其分组相对人工分区达到 0.816 的 B$^3$ F1，而最强对照为 0.678；等价地，1-B$^3$ F1 从 0.322 降至 0.184。
\sys projects all 3{,}978 operations onto the predicted group field, producing

% \sys 将全部 3,978 个 operation 投影到预测分组字段，产生 2,249 个 stack，同时保持全部 operation 的总权重。

partitions from label-hidden text. On all nine available Mind2Web sessions

Together, these experiments provide positive RQ3 evidence across three public
families: target-blind task partitions and session-held-out operation groups.

\subsection{RQ4: Profiling Cost}
% RQ4：分析开销是多少？

RQ4 asks what it costs to construct profiles after a session ends.
% RQ4 询问会话结束后构建 profile 的开销。
Because \sys constructs profiles after execution, we measure post-session time
and resources, excluding capture.
% \sys 在执行后构造 profile，因此该阶段不增加在线 profile-construction 开销；测量不包括轨迹捕获。
We run \texttt{agentpprof 0.2.37} three times on four complete public workloads
and their union, comparing a fixed semantic hierarchy with an identical-input
raw-action control through the full parse, construct, fold, and serialize path.
% 我们在四个完整的现有公开 operation workload 及其精确并集上测量 release \texttt{agentpprof 0.2.37}。对每个输入，我们分别运行固定的语义层次和输入相同的 raw-action 成本对照三次；两者都执行完整的解析、栈构造、折叠和序列化路径。
The measurements run on a 24-core Intel Core Ultra 9 285K machine with

\subsection{Scope and Limitations}

The evaluation covers offline profiling on tested local and public trajectories;
it excludes live-agent overhead because \sys profiles after execution.
% 评估覆盖所测试本地轨迹和公开 workload 上的离线 profiling；由于 \sys 在执行后构建 profile，因此不测量在线 agent 运行时开销。

RQ1 covers the fixed 20-task suite, its declared process/tool scope, and the
R114-compatible AgentSight 0.2.37 path; manifest categories are fixed inputs,
not inferred tasks.
% RQ1 源谱结果覆盖固定的 20 任务套件、其声明的进程/工具范围及 R114 兼容 AgentSight 0.2.37 捕获路径；manifest 类别是固定输入，而非自动推断的任务。

RQ3 establishes task-partition fidelity on Mind2Web and ScienceWorld and
session-held-out group-boundary fidelity on OSWorld-Human. Its fixed phase and
action components require matched annotations and pre-specified mappings.
% RQ3 在 Mind2Web 和 ScienceWorld 上确立 task partition fidelity，并在 session-held-out OSWorld-Human task instance 上确立 group-boundary fidelity；更广泛固定 RQ3 假设中的 phase 和 action 组成部分仍需要在更多 agent family 上使用匹配标注及预先指定 mapping 的证据。

\section{Related Work}
% 相关工作

Agent observability tools combine per-execution traces with tag, metadata,
signal, and metric aggregation~\cite{langsmith,langfuse,phoenix,otel,openinference,agentops,agenttelemetry,agenttraces-trust,datadog-llmobs,laminar-signals}.
% 智能体可观测性工具将单次执行 trace 与 tag、metadata、signal 和 metric 聚合结合起来。
LangSmith Insights and Datadog Patterns add cross-trace category hierarchies
and aggregate metrics~\cite{langsmith-insights,datadog-patterns}. \sys adds
source-linked agent/system operations, conserved weights, and selectable
pprof-compatible operation-stack projections.
% LangSmith Insights 和 Datadog Patterns 已能跨 trace 形成分层类别并聚合多种 metric；\sys 以带源谱连接的 agent/system operation、守恒的可加权重，以及对同一证据的可选择 pprof 兼容 operation-stack 投影补充这些产品视图。

Traditional profilers aggregate stack samples and can incorporate supplied
labels into profile views~\cite{pprof,flamegraphs}. Trace systems such as
Perfetto support flexible event queries~\cite{perfetto}.
% 传统 profiler 聚合 stack sample，并可将已提供的 label 纳入 profile 视图；Perfetto 等 trace 系统支持灵活的事件查询。
\sys derives these fields from agent histories, connects them to downstream
effects, and constructs alternative hierarchies over the same operations.
% \sys 则从 agent 历史中派生重复语义责任字段，将其连接到下游副作用，并在同一组 operation 上构建可替换层次。

Recent agent-diagnosis work spans step- or span-level
localization~\cite{agentrx,telbench,trajad}, validation with root-cause
analysis~\cite{agentfixer}, and diagnostic taxonomies and audit
protocols~\cite{agentatlas}.
% 最近的 agent 诊断工作包括 step/span 级定位~\cite{agentrx,telbench,trajad}、带 root-cause analysis 的验证~\cite{agentfixer}，以及诊断 taxonomy 和 audit protocol~\cite{agentatlas}。
\sys complements these methods with category-level aggregate profiling across
trajectories, exposing recurring responsibility groups rather than only one
execution's fault location.
% \sys 以跨轨迹的类别级聚合 profiling 补充所有这些工具。

\section{Conclusion}
% 结论

Agent observability needs profiling, not only debugging. \sys builds semantic
operation stacks with pluggable intent attribution.
% 智能体可观测性需要性能分析，不仅仅是调试。\sys 通过语义 operation stack、可插拔意图归因和栈构造为智能体轨迹带来分层归因能力。
Across 20 real Codex tasks, lineage reaches 100.0\%/96.569\% precision/recall,
rejects 1{,}629 controls, and preserves 1{,}520 effects.
% 在 20 个真实 Codex 任务上，范围化源谱达到 100.0\% precision 和 96.569\% recall，拒绝全部 1,629 个并发对照副作用，并将 1,520 个已归因副作用送入 AgentProf 且不损失任何权重。
Across 325 real trajectories and three public benchmarks, semantic fields
separate mixed effects and target-blind stacks improve problem concentration at
evaluated points.
% 在 325 条真实轨迹上，语义字段将无标签和按会话视图仍混合的副作用分离为不同的责任视图。
% 在三个公开基准上，目标盲 operation stack 在所评估的 AP 和 recall 工作点上相比 raw action 提高问题集中度。
On 287 held-out OSWorld-Human tasks, a pre-specified predictor reaches 0.739 F1
and 0.816 operation-weighted B$^3$ F1.
% 在 287 个 held-out OSWorld-Human 任务实例上，预先指定的边界预测器达到 0.739 F1 和 0.816 operation-weighted B$^3$ F1。
\sys profiles 27{,}765 public operations in 1.17\,s. Together, the results
establish cross-trajectory semantic profiling alongside run-local debugging.
% 在 27,765 个公开 operation 上，\sys 用 1.17 秒构建完整语义 profile。
% 这些结果共同确立了跨轨迹语义 profiling 对单次运行 debugging 和 tracing 的补充价值。

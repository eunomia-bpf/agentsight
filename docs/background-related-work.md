## Claim-Oriented Novelty Map

| Claim | Closest prior work | Same-claim risk | Novelty delta | Baselines implied | Expansion opportunity |
|---|---|---|---|---|---|
| C1: AgentSight can profile agent behavior as operations and recursively folded operation stacks independent of prompt/session boundaries. | Mind2Web, WebLINX, GUI-Odyssey, AndroidControl, AITW, ToolBench, SATraj-OS, OSWorld-Human, AgentNet, pprof labels/tag frames | Medium | Prior datasets provide trajectories and labels, and classic profilers already support labels and pseudo tag frames. The delta is an agent-operation record model plus recursive multi-field stack projection over heterogeneous labeled agent traces. | Flat action list, fixed prompt/session stack, dataset-native hierarchy, flat/fixed/mapped operation-stack ablation. | Show the same profiler handles local Codex/Claude traces, web demos, mobile demos, desktop/computer-use episodes, human grouped-action references, step-quality labels, and tool-use traces by changing only operation fields and stack projection. |
| C2: Operation-stack folding can expose task/subtask/phase structure from linear event histories. | GUI-Odyssey step actions, WebLINX demos, Mind2Web action sequences, AndroidControl step instructions, ToolBench solution paths, SATraj computer-use actions, OSWorld-Human grouped actions, AgentNet step correctness/redundancy labels, TELBench/DRIFT semantic spans, Holistic span-level diagnosis | Medium-high | Prior work already provides labeled trajectories, grouped or semantic spans, and span-level failure localization. Our use is narrower and different: an observability/profile projection that folds recursive multi-field operation stacks, then scores profile groups with boundary, compression, work, fragmentation, and actionability metrics. | Gold demo/session boundaries, action-type phase oracle, grouped-action boundary oracle, step-instruction oracle, solution-path oracle, step-quality oracle, safety/outcome diagnostics, semantic-span or first-error baselines if AgentRx/TELBench-style traces are imported. | Add boundary adequacy metrics and compare deterministic operation mappings with inferred boundary rules; treat TELBench/DRIFT-style semantic-span localization as a future same-mechanism pressure test. |
| C3: Trace/session/span objects are input and exchange containers, not profiler abstractions. | OpenTelemetry GenAI semantic conventions, OpenInference, LangSmith, Langfuse, Phoenix, AgentOps, Chrome Trace Event / Perfetto-style traces | Medium | Prior systems standardize or display trace/span trees for an application run. AgentSight imports or exports trace containers, then normalizes them into operations and folds operation stacks over public labeled and local traces. R320 evaluates fixed-session drilldown as the current span-tree proxy, not real OTLP/OpenInference/Phoenix imports. | Fixed-session/span-tree proxy, fixed session/run tree, OpenTelemetry/Phoenix/Langfuse/LangSmith-style run inspection, Chrome Trace Event exchange smoke. | Import real OpenTelemetry GenAI/OpenInference traces as additional exchange tests while keeping operation/operation-stack as the only profiler objects. |
| C4: The value claim is the relationship between agent operation records, stack shape, and localization quality, not a single best hierarchy. | Flamegraph/pprof folded stacks and tag frames, Perfetto SQL trace analysis, LangSmith/Langfuse/Phoenix trace UIs, R313/R320 flat/fixed-session frontier counterpoints | Medium-low | Classic profilers already support tags/pseudo frames and Perfetto supports SQL-derived trace analysis. AgentSight's delta is that the same agent-operation records can be folded as flat, fixed-session, dataset-native, raw-action, semantic operation-stack, or label-drilldown views, and R320 scores those aggregates as hidden-label localization outputs across public agent trajectory datasets. | Flat summary, fixed session/span-tree proxy, dataset-native hierarchy, raw action stack, query-aware operation stack, label-drilldown/oracle upper bounds. | Extend R320 to additional oracle-rich tool/API and mobile families before making broader generality claims; use a controlled analyst study only for human-utility claims. |
| C5: Operation-stack profiling can localize, rank, and prioritize real labeled failures, quality problems, and boundaries. | AgentRewardBench, SATraj-OS, AgentNet, OSWorld-Human, AgentRx, Holistic Evaluation, TELBench/DRIFT, AgentAtlas, trace/eval platforms with span scores | Medium-high same-problem risk, medium same-claim risk | Newer 2026 work directly studies span/step failure localization and trajectory diagnosis, but the current closest sources still use span-level evaluators, LLM judges, taxonomies, or benchmark audits rather than evaluating profiler hot groups as cross-dataset operation-stack ranking/localization objects with AP, nDCG, recall@budget, work, fragmentation, and mechanism actionability metrics. | Flat:width, fixed-session:query-aware, dataset-native:query-aware, raw-action:query-aware, operation-stack:width/query-aware, oracle upper bounds, and future AgentRx/TELBench-style span-localization baselines if imported. | Use R335 to sharpen actionability tables now; evaluate AgentRx/TELBench-style traces only as future expansion, and do not claim analyst productivity or complete automatic boundary discovery until separately evaluated. |

## Novelty Verdict

- Overall same-claim risk: medium, with medium-high same-problem risk after the July 5 refresh. Public benchmarks already contain labeled trajectories; LLM observability systems already trace LLM calls, tool calls, runs, spans, sessions, goals, plans, and artifacts; pprof already supports sample tags and tag-derived pseudo frames; Perfetto already supports SQL/derived trace analysis; and 2026 work such as AgentRx, TELBench/DRIFT, and Holistic Evaluation now directly targets step/span failure localization. The defensible novelty is therefore not "agent observability," "agent traces," "failure localization," or "query-time aggregation" in general. It is the narrower profiler claim: an agent-operation record model, recursive multi-field operation-stack projection, and hidden-label evaluation of profile groups as ranking/localization outputs with work, fragmentation, and actionability metrics over real labeled trajectories.
- Confidence in scoped novelty: reasonably defensible, not absolute. The July 5 refresh found close span/step localization papers, but did not find a primary source that directly claims cross-dataset operation/operation-stack profiling with R320/R335-style AP/nDCG/work/fragmentation/actionability scoring on public labeled agent traces. This is a literature-audit result, not a proof that no unpublished or newly released system exists.
- Claims safe to keep: operation/operation-stack as a unifying profiling abstraction; trace/session/span as containers or fixed-session/span-tree proxy baselines; R320 profiler fidelity/localization/ranking with respect to dataset-provided hidden labels and R335 actionability on real labeled traces.
- Claims to narrow or drop: complete AgentOps/observability-platform novelty, full OpenTelemetry/Phoenix/LangSmith/Langfuse/Perfetto compatibility, human/agent analyst productivity, universal dominance over fixed sessions, and automatic discovery of all intent boundaries.
- Mandatory baselines: flat summary, dataset-native sequence/hierarchy, fixed prompt/session or demo/session stack, fixed-session/span-tree proxy, raw action stack, operation-stack width/query-aware ranking, label-drilldown/oracle upper bounds, simple sequence-derived baselines for any boundary-detector claim, and AgentRx/TELBench-style span-localization baselines if those traces are imported in a future expansion. A real OpenTelemetry/OpenInference/Phoenix span-tree import remains a future baseline before making ecosystem-specific span-tree claims.
- Current best paper candidates: OSWorld-Human for grouped boundaries, AgentNet for desktop step quality, AgentRewardBench/SATraj-OS for failure and safety diagnostics, and GUI-Odyssey/tau-bench/ToolBench for cross-domain breadth. ScaleCUA is a supplemental stream-sampling and history-depth source, not a main boundary oracle. TRAIL remains likely strong but gated.
- Next action: keep dataset expansion secondary. Use the existing oracle-rich sources to sharpen R320 accuracy/actionability tables, add one real OpenTelemetry/OpenInference/Perfetto import only as an exchange/baseline smoke if needed, and reserve controlled analyst studies for separate human-utility wording.

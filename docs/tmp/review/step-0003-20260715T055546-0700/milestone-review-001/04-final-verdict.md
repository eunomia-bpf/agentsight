# Cycle Audit, Final Verdict, and Routing

Timestamp: 2026-07-15T06:08:00-07:00

Objective: audit user intent and current changes, then issue a final route

## Cycle-change and capability audit

The implementation satisfies the user's artifact scope unusually well: a new
worktree/branch, all seven named families, more than ten additional views, real
multi-day native histories, Git/file-birth cross-checks, shared draggable
playback, reused JS libraries, screenshots, compatibility exports, browser
experiments, and a compiled paper. It did not silently substitute synthetic
data for the visible artifact.

Two scientific substitutions remain. First, the initial user narrative called
read-then-edit “causal coupling” and agent vendor “author.” The project
correctly rejected those claims after evidence review; this is principled scope
correction, not loss of intent. Second, the original research contract promised
behavioral replication and review utility. Those have not been executed; the
paper currently repackages descriptive experience and responsiveness as RQ2
and RQ3. That is a blocker for claiming the research program complete even
though the artifact deliverable is complete.

Recurring workflow risk: very large native-history files can accidentally enter
repository search output or commits. The nested private-data ignore, explicit
public projection, forbidden-key scan, frozen endpoint, and censored-cell record
are durable mitigations worth retaining.

## Final verdict

**Reject (full research paper); strong artifact/experience paper.**

- **Principle:** process, durable outcome, and endpoint are complementary
  evidence and must preserve disagreement.
- **Belief challenged:** commits or a single repository signal are sufficient
  to explain agent-produced software. The multi-method census and trajectory
  work show this belief is genuinely inadequate.
- **Strongest alternative explanation:** the interface is a polished
  integration of established visualizations; without a task study, apparent
  insight may come from added information or reviewer familiarity rather than
  coordinated visual design.
- **Taste classification:** simple-but-deep principle embedded in an
  incomplete-but-promising evaluation, not complicated-but-shallow. The many
  named views are implementation breadth; only the three-layer evidence
  contract carries scientific depth.
- **Terms that can be merged:** “theory recovery,” “perceptual units,” and
  “visual instrument” should be one construct unless separately measured;
  astronomy pattern names should remain UI labels, not paper-level concepts.

## Largest gaps

- **Scientific/evidence:** no human or in-situ comparison establishes review
  utility or theory recovery.
- **Writing-only:** the RQ numbering masks the unexecuted behavioral and human
  studies; an artifact submission should state this directly in the Evaluation
  opening rather than redefine them.

## Routing decision

Route to **EXPERIMENT_GATE** for a future full-paper cycle: multi-repository
continuous mature data plus the frozen four-condition review study. No local
technical action can manufacture participant evidence during this cycle. For
the current user deliverable, route to **WRITE_GATE** only to label the paper
as an artifact/experience report and restore explicit “unexecuted” status for
the original RQ2/RQ3. Submission completion is not scientifically justified.

The decisive next experiment is the evidence-requirement $\times$ interface
condition study described in `03-reread-assessment.md`. The largest claim it
could unlock is that disagreement-aware coordinated evidence improves review
exactly when questions span process, durable outcome, and endpoint state.

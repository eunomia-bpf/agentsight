# ToolSafe RQ2 Real Preflight Review

**Review method:** independent `research-experiment-design` REAL PREFLIGHT
review  
**Reviewed plan:** `experiment-plan.md`, Revision 3  
**Verdict:** **REVISE**  
**Full run authorized:** **NO**

## Decision

The real path is substantially working: released ToolSafe records reach the
runner, predictions are produced without held-out labels, the release AgentProf
binary is actually invoked, its folded counts agree with independent counters,
and the scorer completes both label mappings and paired cluster bootstraps.

The preflight nevertheless does not yet authorize the full run. Three exact
Revision 3 requirements are not implemented as approved, and the automatic
result verdict has a deeper latent scientific error. A successful rerun must
also remove a contradictory stale status artifact. These are local runner and
preflight repairs; they do not reopen RQ2, the four-RQ program, hypothesis,
thesis, canonical story, or paper.

## Evidence Checked Directly

### Source preparation and label isolation

- The source projection contains 7,182 rows: 6,786 declared operations and 396
  declared non-operations. Family counts are 731 AgentHarm, 5,231 ASB, and
  1,220 AgentDojo.
- Every projection row has one uniform allowlisted key set. It contains visible
  source fields, neutral identity fields, parsed tool identity, and published
  TS-Guard outputs; it contains no `score`, full `meta_sample`,
  `attack_success`, `aggressive`, or `attacker_tool` field.
- Labels are in three separate family files containing only `family`,
  `record_id`, and `score`.
- Each fold prediction file contains only its target family and has no target
  label field. The predictor CLI accepts exactly two reference-label paths and
  rejects a reference-family set that is not exactly the complement of the
  target family. It also rejects any overlap between target IDs and loaded
  reference labels.
- Bootstrap reference densities and label-blind target cluster draws are
  generated by `predict-fold`; held-out labels first enter `score-all` after
  all three ordinary prediction files exist. Their file times also place the
  prediction files before `metrics.json` and `execution-status.json`.

The implementation uses one final `score-all` process with all three held-out
family label files rather than three single-family scoring processes. This is
not the literal process layout described in Revision 3, but it preserves the
scientific isolation invariant because no prediction or reference-density
construction occurs in that process. Splitting it would add complexity without
strengthening the current boundary.

### Real AgentProf involvement

- Real profile JSON files exist for semantic, risk+tool, risk-only, exact-tool,
  causes-only, interaction, and flat/direct views, for target and reference
  sides of both populations in all three folds.
- The script invokes the supplied release binary with `--operation-file`,
  `--view operations`, explicit `--stack`, JSON output, and deterministic
  output.
- Across the inspected profile matrix, every AgentProf stack-value sum equals
  its operation-file row count and every unique-stack count equals the saved
  independent count. Representative semantic, risk+tool, and risk-only stack
  maps were also reconstructed directly from their operation JSONL and exactly
  equal the AgentProf output.
- The inspected binary reports `agentpprof 0.2.37` with `-V`.

### Baseline and fallback fairness

- Semantic and risk-conditioned raw-tool views use the same Laplace estimator
  and the same risk-only backoff. An independently checked ASB target row whose
  semantic and risk/tool keys were unseen received the same reference
  risk-level score, `(47+1)/(52+2) = 0.8888888889`, in all three main views.
- The preflight primary/strict fallback report contains semantic exact and
  risk-backoff rows, risk/tool risk-backoff rows, and risk exact rows. Exact
  tool remains a lower-bound control and does not affect the main verdict.
- Per-interaction and direct-detector views use only published target-visible
  risk output and remain descriptive controls.

### Bootstrap and metric path

- Each representative fold bootstrap artifact has one header and 200 attempts
  numbered 0--199, seed 4203, 32 target clusters, and target-draw
  multiplicities summing to 32 on every checked attempt.
- The code derives one deterministic family draw from `(seed, attempt,
  family)`. Consequently, the same family draw is used when that family is a
  target in one fold and a reference in the other folds, while all methods
  share the draw.
- Reference density, smoothing, semantic/raw risk fallback, target cluster
  draw, population, and strict/unsafe-only mapping are recomputed inside each
  bootstrap attempt before scoring.
- All four population/mapping cells reached 200 valid paired replicates.
- `conservative_metrics` implements the approved whole-score-block AP,
  complete-block R@30%, and whole-crossing-block work-to-50% definitions. An
  independent recomputation from saved predictions and labels exactly matched
  the reported primary/strict AP, R@30%, and work-to-50% values for semantic,
  risk+tool, and risk-only.

The diagnostic preflight result is not paper evidence and must not be used to
support, contradict, narrow, or rewrite any paper claim.

## Must-fix Before Re-review

1. **Preserve exact raw-tool identity as Revision 3 requires.**
   `parse_tool()` currently calls `canonical_agentprof_frame()`, which
   lowercases ASCII and replaces characters. Revision 3 permits trimming only
   surrounding whitespace/Markdown punctuation and explicitly requires case
   and the exact tool string to be preserved for the raw-tool view. On the
   released set, 380 of 522 unique operation tool strings are changed, although
   the audit found no collision among the 522 keys, so the current preflight
   numbers happen not to change. That accidental no-collision result does not
   authorize the deviation. Keep the exact parsed tool as the scientific
   density key and use a reversible AgentProf-safe encoding if the profiler
   stack representation requires normalization. Verify that the encoding is
   one-to-one and that AgentProf grouping is partition-equivalent to exact raw
   identity, then rerun preflight.

2. **Use the approved neutral-prefix preflight repair.**
   Revision 3 specifies the first 32 interaction clusters in neutral source
   order. The earlier independent review allowed enlarging that target-blind
   prefix if it was one-class. Instead, `selected_rows()` now takes 32
   equal-interval clusters across each entire family after the first-32 sample
   failed. This is label-blind once defined and has no bearing on the full-data
   experiment, but it is a different selection rule from the approved plan.
   Restore the neutral prefix and enlarge its recorded size only as needed to
   exercise both scoring paths, or obtain serial approval for an explicit plan
   revision. Do not treat either preflight sample as a scientific result.

3. **Record the AgentProf version in runner-produced artifacts.**
   The prose report asserts `agentpprof 0.2.37`, and direct inspection confirms
   that version, but the runner never invokes `-V` or writes the returned
   version into `predict-status`, `profile-counts`, `metrics`, or
   `execution-status`. Revision 3 requires the actual version to be recorded.
   Query the exact supplied binary, fail on an unreadable version, and include
   it in the ordinary execution report/status generated by the same run.

4. **Make automatic result classification exactly implement Revision 3.**
   The current `score_all()` verdict uses only the primary/strict support tests.
   If those pass, it returns `SUPPORTED` without checking whether unsafe-only
   reverses, even though the plan requires such a case to be `MIXED`. If strict
   family AP reverses but pooled semantic AP remains above risk+tool with enough
   compression, the current fallback branch returns `MIXED`, even though the
   plan declares a family direction reversal `CONTRADICTED`. Implement the
   predeclared supported/mixed/contradicted conditions directly and report the
   boolean evidence for every condition. The present small preflight happens to
   return `CONTRADICTED`, but it does not exercise these latent branches.

5. **Produce one internally consistent successful output directory.**
   The successful preflight has `execution-status.json` and `metrics.json`
   marked `PASS`, but the same directory retains an older `need-more.json`
   claiming 9,000 attempts and zero valid strict replicates. Remove or replace
   stale terminal/status artifacts when a fresh run starts and delete
   `need-more.json` after success. Rerun the repaired preflight so a reviewer
   never has to infer which contradictory status is authoritative.

## Recorded, Non-blocking Deviations

- Exact official TS-Guard metric equality is skipped for the deliberately
  partial preflight and remains mandatory for the complete 7,182-row run. This
  is the correct distinction between path testing and full execution.
- AgentProf frame normalization was discovered only by the real run. Adapting
  the operation-file representation is an appropriate preflight repair, but it
  must not silently change the exact raw-tool scientific key as it currently
  does.
- The report heading “Frozen Inputs” is unnecessary terminology; “Approved
  Plan Inputs” would describe the same ordinary Markdown plan without implying
  a freeze protocol.

## Re-review Condition

Run the same real preflight after the five local repairs. Re-review needs only
to confirm exact raw-key partition preservation, approved prefix selection,
runner-recorded version, plan-exact verdict branches, a clean terminal output
directory, and unchanged passing isolation/AgentProf/bootstrap/metric checks.
The full 7,182-row run remains unauthorized until that review returns PASS.

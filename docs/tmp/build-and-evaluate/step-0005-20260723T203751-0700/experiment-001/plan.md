# Experiment Plan: Separate Tool Question — Held-Out Projection Conformance

## Research Question

- **RQ exactly as written in the paper:** Given one independently derived
  source oracle, which action-only, artifact-linked, cross-session, and
  final-state facts can Final State, Counts, ProcGrep, bounded raw-log model
  analysis, and artifact-linked trajectories answer correctly, and at what
  evidence and computation cost?
- **Specific uncertainty tested here:** Can a precision-first repository
  projection, built only from existing `agent-session` fields, recover exact
  artifact-linked and cross-session facts on previously unseen native session
  files without the 28/60 wrong answers observed in Step 0004?
- **Why the answer matters:** RQ1--RQ4 and the separate tool claim share this
  projection. A representation that adds facts but silently returns wrong
  artifact identities or session joins cannot support longitudinal findings.

## Paper-Value Admission

- **Planned role:** decisive measurement-validity experiment.
- **Largest credible paper story this experiment could unlock:** a
  workspace-centered longitudinal study whose local measurements are
  independently source-conformant rather than merely projection-conditioned.
- **Strongest reject argument addressed:** the current paper's central local
  measurements are generated by an adapter that fails its own exact-fact
  audit; the empirical results may therefore be artifacts of path inference,
  identity tracking, or session joining.
- **Independent evidence beyond existing runs:** a sealed held-out corpus of
  48 complete native files from 48 distinct native-root sessions. It excludes
  every Step 0004 `(vendor, native_root_session_id)` group, includes a
  previously unstudied auto-research workspace, and is scored by an
  independently implemented source parser. Step 0004 becomes development
  evidence only.
- **Why this is not tautological or settled:** the repair is not a format
  conversion. It must reconcile vendor-native records, shell operands,
  workdirs, status, rename generations, source-stream identity, and temporal
  ordering. The current implementation demonstrably fails these relations.
- **Paper decision if positive:** replace the current negative implementation
  result with held-out conformance evidence, then recompute RQ1--RQ4 and
  supersede all projection-sensitive values.
- **Paper decision if contradictory, mixed, or inconclusive:** retain the
  negative capability conclusion; restrict local claims to source-direct
  subsets or remove the affected RQs rather than presenting projected counts
  as facts.
- **Best alternative:** run the bounded Raw reader again. It has lower decision
  value now because no Raw comparison can repair invalid ground measurements.

## Expected And Alternative Outcomes

- **Current expected answer:** most Step 0004 errors arise from five concrete
  contract violations: weak shell scopes admitted as exact file actions,
  failed attempts dropped entirely, unstable session/source identity,
  non-total tie ordering, and artifact-generation mistakes. A strict
  projection should remove wrong answers while retaining useful coverage.
- **Strongest competing explanation:** native records are too incomplete or
  vendor-divergent for post-hoc exact artifact lineage; a precision-first
  projection will either remain wrong or abstain on most relations.
- **Contradictory result:** any held-out wrong artifact-linked or cross-session
  answer, or correct coverage too sparse to support the paper estimands.

## Published Precedent And Real Assets

- **Closest published protocol:** ProcGrep's official native adapters and
  deterministic action procedures provide the action-only baseline; OCEL-style
  object identity and lifecycle semantics provide established machinery for
  artifact histories. This experiment tests conformance rather than claiming a
  new event-log formalism.
- **Official assets:** pinned ProcGrep
  `2e8277003dacaa774b5ef61ba150ae03a4f06693`; native Claude, Codex, and Gemini
  files; current `agent-session`; Git cutoff manifests.
- **Reused:** Step 0004's source records and discrepancies as development
  evidence, plus the independent-checker architecture. The v2 question
  specification and both source implementations are newly frozen.
- **Necessary glue:** deterministic exclusion of development-source hashes,
  a second selection seed, sealed pre-repair baseline output, and a scorer for
  current versus repaired projection. No new product IR, database, semantic
  labeler, or human annotation is introduced.

## Comparison

- **Proposed method (`strict-v1`):**
  1. `ToolEvent.paths` retains only exact-name structured file operands, patch
     paths, and a small declared shell file grammar; substring Tool-name
     matches are excluded, and distinct `(path, access, previous_path)` tuples
     in one call remain distinct;
  2. search/directory/ambiguous shell references remain only in existing
     `path_groups` and are excluded from exact measurements;
  3. attempted paths remain linked to failed Tool calls, while event status
     determines whether a mutation is an observed effect;
  4. every event retains its source Tool ordinal and repository actions are
     totally ordered by
     `(timestamp, source_stream_id, source_tool_ordinal, event_id)`;
  5. source-stream and native-root identities remain distinct: native root is
     the semantic session, while source stream is provenance only; and
  6. rename preserves identity only when explicit and same-worktree, while
     delete--create starts a new generation.
- **Main baseline (`current-v0`):** the unmodified pre-repair projection, run
  and sealed on held-out inputs before implementation.
- **Action control:** pinned ProcGrep. `strict-v1` A-family answers are derived
  from its own ordered `RepositoryEvent` sequence, never copied from ProcGrep.
  Equality or disagreement is then measured. Disagreement with the separate
  source action grammar remains an adapter-boundary result rather than an
  artifact-projection result.
- **Final-state control:** Git/index-based Final State for D-family facts.
- **Development diagnostic:** Step 0004's 72 sessions and 120 questions may be
  used for taxonomy and repair tests, never for the final capability estimate.
- **Raw model:** remains N/A in this repair experiment. It is neither a
  projection-conformance baseline nor a substitute oracle.
- **Conclusion if the baseline matches or wins:** the redesign adds no
  validated capability and the exact-fact claim remains rejected.
- **Information and leakage fairness:** current and repaired projections see
  identical complete native files and cutoff state. The held-out source list,
  oracle specification, question set, v0 output, and hashes are frozen before
  production code changes. Selection excludes the whole
  `(vendor, native_root_session_id)` group of every development source and
  admits at most one source stream per held-out native root. The freeze reports
  file-hash overlap, root-group overlap, and duplicate-call overlap; all must
  be zero. The implementer may inspect only Step 0004 development errors until
  `strict-v1` is code-frozen. Held-out answers and v0 scores are not opened
  before that point.

## Workloads And Metrics

- **Development set:** Step 0004's 72 files from six projects.
- **Held-out set:** eight native-root-disjoint source files each from AgentSight, ActPlane,
  bpf-developer-tutorial, eunomia.dev, the previously unstudied bpf-benchmark,
  and the previously unstudied kernel-script-paper auto-research workspace.
  Every source SHA-256
  and every `(vendor, native_root_session_id)` group must be absent from Step
  0004. The natural held-out corpus contains Claude and Codex only; no result is
  generalized to Gemini.
- **Session semantics:** a semantic session is one native root. Source streams
  are provenance. If multiple streams from one root are ever used outside this
  held-out set, calls with the same native call ID are deduplicated within root
  and C1--C5 order native roots by first event, then native-root ID. The
  held-out selector avoids this ambiguity by admitting one stream per root.
- **Questions:** 20 per project: A/B/C/D, five each, under a new
  `native-root-conformance-v2` specification and hash. B uses attempted strict
  artifact references. C ranges over native-root sessions, never transcript
  files. Step 0004 remains immutable development evidence under its old
  stream-session specification; its scores are not pooled with v2. The
  intended strict path semantics are retained, but implementation defects that
  treated a `sed` program or option argument as a file path are corrected
  independently before the new freeze.
- **Primary correctness object:** the complete held-out ordered multiset of
  strict attempted edges keyed by `(session_ordinal,
  native_root_session_id, source_stream_id, source_call_id,
  source_tool_ordinal, event_ordinal, action_ordinal, path, access,
  previous_path, artifact_id)`.
- **Primary metric and gate:** strong-edge precision = 1.0 and recall = 1.0
  against the independent source oracle, both overall and within each
  represented vendor. Any discrepancy rejects complete strict-edge
  conformance.
- **Status/effect gate:** for every native Tool call that contributes a strict
  edge, production and oracle `ok`/`fail`/`observed` status must agree exactly;
  the derived confirmed-effect edge multiset must also have precision = 1.0
  and recall = 1.0 overall and within vendor. Edge equality without these two
  equalities cannot pass.
- **Question-level capability gate:** B+C must be 60/60 correct, 0 wrong, and
  0 abstain. This is supporting evidence over relations derived from the
  already gated complete edge set, not a substitute for edge conformance.
- **Supporting metrics:** independently derived A-family comparison with
  ProcGrep, D-family agreement with Final State, per-project B+C correctness,
  source/projection edge precision and recall by evidence class, and
  v1-minus-v0 paired changes.
- **Ground truth:** the frozen standalone checker reparses native sources,
  rebuilds paths/generations/native-root session order, independently pairs
  Tool results to calls, derives `ok`/`fail`/`observed`, and imports neither
  production parser nor projection code.
- **Attempt/effect contract:** strict edges record attempted file references
  regardless of result. A confirmed artifact effect requires `status=ok`.
  Failed and unknown-status mutations remain attempted actions but never
  create, rename, delete, or supersede an artifact in RQ1--RQ4. Confirmed
  reuse likewise requires a successful later access; unknown-status activity
  is reported as coverage, not upgraded to an effect. A confirmed effect
  clears any same-path attempted-only identity, preventing a failed generation
  from being revived after a later confirmed delete.
- **Uncertainty:** exact project-stratified values and a seeded project-block
  bootstrap interval over the six held-out cases. It describes corpus
  sensitivity, not population inference.
- **Post-validation extraction:** the original 2,049-session corpus lacks an
  immutable copy of every native file and dirty worktree at its old cutoff, so
  old/new paired estimand differences are not claimed. After conformance,
  create one new stable observation cutoff and run only `strict-v1`; the new
  rows supersede projection-sensitive old values and are explicitly
  non-comparable across cutoffs.

## Execution

- **Authoritative freeze command:**
  `python3 agentvis/research/rq7_measurement.py freeze
  --projects-file <experiment>/heldout-projects.json
  --private <experiment>/private
  --release <experiment>/raw/freeze
  --procgrep <pinned-procgrep>
  --seed 20260723-heldout-v1
  --sessions 8
  --raw-bytes 268435456
  --exclude-freeze <step-0004>/private/freeze.json
  --exclude-native-root`.
  The implementation must make `--seed` effective; there is no seed retry
  after source selection, question generation, or scoring. The 256 MiB cap is
  per project selection bundle and also excludes any individual source larger
  than the cap.
- **Held-out projects file:** AgentSight, ActPlane,
  bpf-developer-tutorial, eunomia.dev, bpf-benchmark, and
  kernel-script-paper, with fixed repository roots.
- **Comparison workflow:** reuse the independent oracle and add a deterministic
  `compare-projections` path that scores two sealed outputs plus full edge and
  status conformance.
- **Freeze order:** plan review, then held-out freeze and current-v0 projection,
  then implementation. Record the Git tree and production file hashes before
  and after repair.
- **Ordering:** production and oracle both derive
  `source_stream_id = SHA256(vendor || native_root_id || source_stem)[0:16]`
  and `source_tool_ordinal` from native Tool appearance order. Equal timestamps
  use `(source_stream_id, source_tool_ordinal)`; opaque call IDs never establish
  temporal order.
- **Real preflight:** one held-out project is executed only after `strict-v1`
  is code-frozen; it must parse real archived native records, build the
  repository projection, and complete independent scoring.
- **Public conformance fixtures:**
  `agent-session/tests/fixtures/strict-action-grammar.json` and
  `agentvis/tests/fixtures/strict-lifecycle.json` are the sole authoritative
  development fixtures. One command checks them against Rust production and
  both independently written Python oracles before held-out unsealing.
- **Full completion:** 48 root-disjoint source files with zero development
  file/root/call overlap, 120 oracle questions, current-v0 and strict-v1
  outputs, complete attempted-edge and call-status ledgers, exact provenance
  hashes, all parser/projection tests, all six held-out projects, and
  independent result review.
- **Raw path:** this experiment's ignored `private/`.
- **Released path:** `raw/`, `figures/`, `result.md`, and review reports.
- **Recovery:** immutable freeze plus per-run JSON outputs; a failed run is
  retained and never silently regenerated with a different corpus.

## Interpretation

- **Positive:** `strict-v1` has exact held-out attempted-edge, call-status, and
  confirmed-effect equality; 60/60 correct B+C answers; improves over
  `current-v0` on the same held-out v2 questions; and reports independently
  computed A/D controls. RQ1--RQ4 are then recomputed at one new cutoff and the
  paper reports only repaired values.
- **Negative:** any remaining wrong B+C answer retains the rejected
  exact-fact claim; source-direct subsets or fewer RQs replace projection-wide
  conclusions.
- **Mixed:** any partial edge recall or B+C abstention is a precision/coverage
  boundary and fails the complete exact-fact gate.
- **Target paper figure:** paired v0/v1 correct--wrong--abstain partitions by
  fact family on development and held-out corpora, with per-project held-out
  B+C correctness.

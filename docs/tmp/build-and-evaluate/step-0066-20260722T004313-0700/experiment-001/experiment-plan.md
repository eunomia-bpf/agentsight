# Experiment Plan: recursive operation segmentation

Timestamp: 2026-07-22T00:43:13-07:00
Status: approved after five serial independent review rounds

## Research question and tested hypothesis

- Paper RQ, unchanged: **RQ3: How accurate are the tags?**
- Tested hypothesis: when an LLM Agent is asked to find one most important
  semantic responsibility transition inside an interval and then recursively
  applies the same decision to the two resulting intervals, it avoids both
  previously observed degeneracies—one leaf per turn and one segment per
  session—and produces a useful variable-depth operation partition over real
  agent trajectories.
- The experiment judges only this tested constructor. It does not change the
  paper thesis, story, four RQs, or positive hypothesis if the backend fails.

## Why this experiment is distinct and necessary

Two complete prior mechanisms establish a common bottleneck rather than an
answer:

1. the online Qwen2.5-3B stack policy made a new leaf for essentially every
   operation (`new_frame_rate=0.99957`), so local transitions fragmented the
   trajectory; and
2. the whole-trajectory Qwen3.6-27B segment-list policy emitted exactly one
   segment for all 405 sessions, so a legal shortest response collapsed the
   trajectory.

The new mechanism is not another score, cutoff, dataset, or prompt-only retry.
It changes the decision topology. Each call can make only one high-value split
or stop. A split creates two smaller scientific questions and recursion forces
the Agent to reconsider both sides. A stop explicitly asserts that no further
semantic responsibility transition is warranted inside that interval.

## Algorithm contract

The unit of recursive decision is a source-native Agent turn. All primitive
operations in one turn remain together. Each turn carries a replay-stable first
source-operation ID, plus visible intent, progress, planned source action, and
observed result. Official stages and all scoring labels remain unavailable.
The fixed source-visible turn projection is reused from the completed global
experiment: at most 256 characters of intent, 128 of progress, 128 of planned
action, and 256 of result, retaining both the beginning and end when a source
field exceeds its declared budget. These budgets are part of the input
representation and do not change by interval, session, model output, or score.

For one session:

```text
DECOMPOSE(interval, ancestors, current_operation)
    if interval contains one turn:
        emit ancestors + current_operation for that turn
        return

    Agent reads the concrete user task, ancestor path, current operation,
    and every visible turn summary in this interval.

    Agent returns either:
        STOP
    or:
        SPLIT(split_before_turn_id, left_operation, right_operation)

    STOP:
        emit ancestors + current_operation for the entire interval

    SPLIT:
        recursively DECOMPOSE(left interval,
                              ancestors + current_operation,
                              left_operation)
        recursively DECOMPOSE(right interval,
                              ancestors + current_operation,
                              right_operation)
```

`split_before_turn_id` must address an existing non-first turn in the current
interval, so both children are nonempty and termination follows from strict
interval shrinkage. There is no configured depth cap, leaf-count cap, minimum
interval length, numerical split threshold, or post-hoc contraction.

The Agent may split only when it can name the two sides as distinct persistent
task responsibilities or task-progress states. A tool, command, file, action,
status, error string, or field change alone is not a semantic split. The two
child names must be distinct from each other and from all ancestors after
normalization. Only an explicit Agent `STOP` stops a multi-turn interval. Any
invalid `SPLIT`, including a child-name collision, is an inference error and
does not emit marks. The semantic STOP/SPLIT judgment is the sole fragmentation
guard; there is no tuned length threshold.

Before recursion, one grammar-constrained Agent call names the root operation
from target-blind public task text extracted before any manifest is opened. For
287/405 trajectories this is the raw role-user message. The remaining 118
OpenHands archives expose no recoverable role-user message through the public
adapter, so the registered fallback is the public `recall` query already used
by the source-native extractor. The code reports this split explicitly and
does not call the fallback a first-user message. The root call sees only the
text, not which source form supplied it, and cannot see the session name,
source-path slug, manifest `task_name`, official task cluster, stage string,
recurrence output, prior candidate name, or score. Child names are generated by
the Agent from the same target-blind public task text plus visible turn
evidence.
Canonical normalized display names map to stable semantic operation IDs; equal
names share an ID across sessions. The shared pool is built only from these
target-blind root and recursive outputs; it never imports reference names. The final sparse marks use Step 0065's
backend-neutral operation-mark contract and are replayed by AgentPProf into one
standard pprof.

## Fixed backend and information boundary

- Model: local Qwen3.6-27B Q4_K_M GGUF, SHA-256
  `f7da7eee0f1ffa280742a293f02052d1f58d3253c9e109c1be8fb0067eb1b3a9`.
- Runtime: local llama.cpp, one 32,768-token slot, temperature zero, seed
  `20260722`, grammar-constrained JSON.
- Visible source fields: target-blind public task text (raw role-user message
  where present, otherwise the registered public OpenHands recall query),
  current semantic ancestor path, and every turn's visible intent, progress,
  planned action, and result inside the current interval.
- Hidden until all predictions are complete: the verified manifest, manifest
  task names/clusters, CodeTrace stage IDs and boundaries, recurrence
  assignments, prior candidate names, and all candidate scores. Source path
  and session slug are provenance only and are not placed in a model prompt.
- The model receives complete future context within the current interval. This
  is an offline Agent-assisted annotation backend, not an online causal policy.

## Workload and comparisons

- Real workload: all 405 retained CodeTraceBench trajectories, 17,148
  source-native turns, and 20,866 operations across OpenHands, SWE-agent,
  Terminus2, and mini-SWE-agent.
- Main baseline: the retained complete multi-resolution recurrence assignment.
- Mechanism controls, reused without rerun:
  - whole-trajectory Qwen3.6-27B one-shot segmentation;
  - online Qwen2.5-3B task-stack transitions; and
  - causal Qwen2.5-3B exact-leaf paths.
- Product control: the emitted marks must replay through AgentPProf with exact
  operation coverage and one readable `.pb.gz`; no alternate renderer or
  product output is admitted.

These alternatives demonstrate that the same operation-stack interface can be
fed by recurrence, online LLM transitions, one-shot interval lists, recursive
LLM splitting, or Agent-authored marks. Only the new recursive candidate is
executed in this experiment because the other full outputs already exist.

## Metrics and decision

- Primary standard metric: ordinary unweighted operation-level B-cubed F1 as
  defined by Bagga and Baldwin (1998), against official contiguous stages
  opened only after predictions complete. For each operation, the predicted
  cluster key is its complete emitted visible semantic operation-ID path scoped
  to its trajectory—not the leaf name alone and not an internal binary-node or
  cache instance.
- Secondary standard diagnostic: exact adjacent-boundary precision, recall,
  and F1.
- Additional diagnostics: predicted group count, session leaf-count
  distribution, recursion call count, STOP/SPLIT count, leaf turn-length
  distribution, semantic depth distribution, sessions with internal splits,
  and exact mark/pprof coverage.
- No token-weighted B-cubed, Recall@budget, top-k reader score, custom weighted
  metric, or scalar calibration is introduced.
- Positive evidence: the recursive candidate avoids both degeneracies and
  improves the retained recurrence B-cubed F1 with a paired task-cluster 95%
  interval wholly above zero, while the fixed semantic-review collections and
  questions below pass their predeclared review contract.
- Mixed evidence: it produces useful variable-depth paths and avoids
  degeneracy but does not clearly exceed recurrence. The backend remains an
  Agent-assisted optional constructor; the tested hypothesis remains active.
- Contradictory evidence: it collapses, fragments, or is clearly worse. Record
  the backend failure in research history, retain the fixed paper hypothesis,
  and do not put the negative development result in the paper.

CodeTrace's flat stages validate only the leaf partition induced by complete
operation paths. They do not validate nested ancestor topology, semantic name
meaning, or cross-session equivalence. Those require independent whole-profile
review and product cases.

## Fixed multi-session semantic-review collections

Semantic review uses two substantial collections fixed before inference. A
case study is always an aggregate over many complete sessions. No single
session, hand-picked trace, or favorable output can substitute for a
collection; individual sessions may appear only as source-evidence drilldowns
from an aggregate path.

1. **Complete-population collection:** all 405 retained CodeTrace sessions,
   comprising 17,148 source-native turns and 20,866 operations. This collection
   tests whether shared semantic names expose recurring responsibilities across
   heterogeneous agents and tasks without erasing source lineage.
2. **Long-horizon collection:** the longest decile of the same population,
   selected before inference solely by descending source-visible operation
   count with trajectory ID as a deterministic tie-break. The fixed collection
   contains 41 complete sessions with at least 95 operations each and 5,750
   operations in total, spanning Terminus2, OpenHands, and SWE-agent. Outcome,
   stage, and candidate output are not used for membership. This collection
   tests whether a deep, variable operation stack explains where long-running
   agents repeat work, pursue expensive paths without a task conclusion, and
   enter repair work.

For each complete collection, an independent reviewer uses only the aggregate
pprof, its `source_session`/`evidence_id` labels, and the corresponding raw
visible turn summaries to answer four fixed questions:

1. What persistent responsibilities decompose the user request, and do the
   paths have genuinely variable semantic depth?
2. Which named responsibility or progress state recurs within or across
   sessions, rather than merely which tool/action repeats?
3. Which high-operation paths end without a source-visible task conclusion or
   are followed by repair/retry work?
4. Can every reported path be drilled down to the source turns that justify
   its boundary and name?

For every path reported by the four fixed aggregate queries, the reviewer
drills down to its cited source turns and records any split that lacks
convincing distinct-responsibility evidence and any non-root label that is only
a tool/command/file/path/status/error string as a local semantic error or
limitation. This bounded review does not claim an exhaustive semantic error
rate over every recursive node. An isolated local error does not erase the
standard metric or make the entire profile useless. The
collection-level semantic usefulness contract fails only if either collection
degenerates to whole-session operations or turn-singleton leaves, all paths
have the same semantic depth, no path reaches five semantic frames including
the root, any reported path lacks reversible source evidence, or the aggregate
pprof cannot support one of the four predeclared user questions. No error-count
or acceptance-ratio threshold is introduced. This review is required only for
semantic usefulness; it does not replace the standard partition metric or
authorize claims beyond these fixed collections.

## Paper-facing pprof figures

An accepted paper result must contain real flame graphs derived from the
emitted pprof rather than a schematic or a custom renderer. After inference,
the root opens the complete-population and long-horizon `.pb.gz` files with stock
`go tool pprof`, inspects their flame-graph views at readable zoom levels, and
records the exact profile hash and query used for each captured paper figure.
If the complete result passes its registered scientific and collection-level
semantic interpretation, at least the long-horizon aggregate enters the paper.
Its caption and adjacent text must identify the collection size and one
source-verifiable diagnosis visible in the aggregate profile. A visually deep
profile is not sufficient by itself: the figure must answer a fixed user
question about task decomposition, recurring work, an expensive path without
conclusion, or subsequent repair. A contradicted backend remains in research
history and does not force a negative development figure into the paper.

The existing AgentRewardBench differential case remains the second paper case:
125 mixed-outcome tasks, 440 complete sessions, and 338 bad--good pair
occurrences folded into one signed pprof. The earlier four-session AgentCap
profile and three-session repeated-task family are development/drilldown
evidence only and must not be presented as standalone paper case studies.

## Fail-closed inference policy

- The output grammar enumerates only existing non-first turn IDs inside the
  current interval for `SPLIT`; a one-turn interval is assigned without a model
  call.
- Unknown, first, or out-of-interval split IDs; malformed/empty names;
  post-normalization collisions; names equal to each other or an ancestor;
  malformed JSON; timeouts; server errors; and context overflow are inference
  errors. They never silently become `STOP`.
- Preflight may repair implementation or grammar wiring without changing the
  semantic prompt. A failed request may be rerun unchanged. Any unresolved
  session leaves the full run incomplete.
- Every prompt includes every fixed projected turn summary in its interval.
  After the predeclared projection above, no prompt or field is dynamically
  truncated to fit the 32,768-token slot; a non-fitting interval is a reported
  context-overflow error.

## Cost and recovery

Each recursive call reads only its current interval. Total prompt work is
proportional to the sum of interval lengths over the Agent-produced tree, not
to primitive operation count times an arbitrary fixed depth. Completed session
decisions are cached by exact model, prompt, grammar, source archive, interval,
ancestor path, and algorithm identity. Cache reuse is compute recovery only;
it is not a scientific gate, Git condition, freeze protocol, or product output.
The cache contract includes a deterministic hash of both system prompts,
grammar shape, seed, completion budget, prompt-construction functions, and the
fixed source projection; a preflight wiring change invalidates prior sessions.

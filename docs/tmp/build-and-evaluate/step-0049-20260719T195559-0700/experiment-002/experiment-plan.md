## The Single Algorithm

Let `S_0 = []`. For each operation `t = 1..n` in trajectory order, let the
stack before the operation be an ordered variable-length list of frame
instances `S_(t-1)`. A frozen local model reads:

- the current stack's short semantic labels;
- the trajectory's visible root task text;
- the current source action or tool invocation;
- the preceding source observation, when one exists.

It returns only two values:

```json
{"keep_depth": 1, "append": ["write introduction"]}
```

The model proposes only the appended suffix. Retained frames, labels, and
instance identities are retained by the transition function rather than copied
or regenerated by the model. The transition is

```text
S_t = prefix(S_(t-1), keep_depth) + new_frames(append)
```

Depth is variable and has no fixed maximum. `append` may contain zero or more
short verb phrases. A transition is valid exactly when `keep_depth` is an
integer in `0..|S_(t-1)|`, every appended value is a non-empty lowercase short
verb phrase of at most 48 characters, and `|S_t| >= 1`. Each append creates a
fresh within-trajectory frame-instance identity. Operation `t` is assigned to
the leaf instance of `S_t`; its full ancestor path is retained for profile
folding. Any invalid transition makes the run incomplete: there is no repair,
retry, clamping, inferred default, or fallback transition. This one rule
contains all required cases:

- retain the whole prefix and append nothing: continue the current operation;
- retain the whole prefix and append: enter one or more subordinate operations;
- retain a shorter prefix and append nothing: return to an ancestor;
- retain a shorter prefix and append: change to a sibling or another branch.

The current weighted operation is assigned to the resulting leaf and all its
ancestors. Labels describe goals, not commands, files, stages, benchmark IDs,
explanations, or new terminology.

### Fixed visible-text representation

After trimming leading/trailing whitespace, fields appear in the model prompt
in this fixed order: (1) root task, (2) serialized complete current stack,
(3) preceding observation or the literal `none`, and (4) current action. Root
task is limited to 1,200 characters, preceding observation to 2,400, and
current action to 2,400. Text within budget is unchanged. Longer text is
deterministically represented by its first `floor((N-1)/2)` characters, one
Unicode ellipsis, and its last `ceil((N-1)/2)` characters, for budget `N`.

The complete stack is serialized in root-to-leaf order without truncation,
because `keep_depth` indexes that exact list. Each appended label is already
limited to 48 characters. If the fixed 8,192-token llama.cpp context cannot
hold the complete serialized prompt, execution is incomplete rather than
dropping an ancestor. These budgets, ordering, and representation cannot
change after plan approval.

The model never sees target stages, stage counts, incorrect-step labels,
resource weights, future actions, or the current action's result. There is no
NPMI, clustering, threshold, depth cap, training, reference corpus, embedding,
or target-time calibration. Grammar-constrained JSON decoding and deterministic
temperature-zero inference enforce the output shape; invalid depth or empty
labels make execution incomplete rather than silently changing the stack.

The conceptual precedent is the dynamic focus stack of Grosz and Sidner
(Computational Linguistics 1986): active purposes form a stack, subordinate
purposes push, and returning to a dominating purpose pops one or more spaces.
The contribution is not inventing push/pop; it is applying incremental semantic
task stacks to conserved cross-run agent profiling.

## Comparisons And Standard Metrics

The primary comparison set is fixed:

1. this local semantic task stack;
2. the completed multi-resolution recurrence candidate from Experiment 001;
3. the current released coarse recurrence;
4. source-derived phase grouping;
5. matched raw-action grouping.

The candidate partition is the within-trajectory leaf frame-instance assigned
to each operation. The main metric is ordinary unweighted per-operation B-cubed
precision, recall, and F1 against all official stage partitions. Exact adjacent
boundary precision, recall, and F1 are secondary standard segmentation metrics.

Report candidate-minus-each-main-baseline differences and a paired 10,000-
resample task-cluster bootstrap interval for candidate minus the strongest
baseline. Also report all four frameworks separately, predicted group count,
operation and transition coverage, depth distribution, stack validity, model
calls, prompt/generated tokens, wall time, and peak memory. Depth and cost are
diagnostics, not substitute accuracy metrics.

CodeTraceBench supplies flat stages rather than gold open-vocabulary frame
names or a complete nested task tree. Therefore no custom semantic-similarity
score, LLM judge, or claimed literal-name accuracy is admitted. The experiment
tests leaf-instance partition fidelity and whether the variable-depth mechanism
runs coherently; it does not overstate unannotated hierarchy semantics.

## Fixed Interpretation

- **Supported and adopted:** candidate B-cubed F1 exceeds every comparison,
  the paired task-cluster 95% interval against the strongest comparison is
  wholly positive, all four framework effects are non-negative, and all source,
  schema, coverage, and stack-validity checks pass.
- **Promising but not adopted:** candidate point estimate is highest but its
  interval includes zero or a framework materially regresses. Retain it as a
  research result and seek a genuinely independent hierarchy evaluation rather
  than tune this population.
- **Contradicted:** candidate B-cubed F1 does not exceed the strongest existing
  comparison.
- **Invalid/incomplete:** any label leakage, missing operation, future evidence,
  invalid transition, parser mismatch, incomplete model run, or scoring failure.

A supported result authorizes one bounded implementation of the semantic-stack
backend and replacement of recurrence-owned design, implementation, evaluation,
and paper text. It does not authorize a story or RQ change. Any other valid
result keeps the current release algorithm and records this branch without
inventing another prompt or model variant inside the same experiment.

This is a system-level mechanism comparison. The candidate uses source-visible
task, action, and preceding-observation text, whereas recurrence comparisons
use their registered action or action-detail transition evidence. A supported
result authorizes adopting this complete semantic-stack backend over the listed
constructors on this population under ordinary B-cubed. It does not establish
matched-input superiority under action-only features, gold nested-hierarchy
fidelity, literal open-vocabulary frame-name accuracy, or that any gain comes
solely from stack discipline rather than the visible language evidence.

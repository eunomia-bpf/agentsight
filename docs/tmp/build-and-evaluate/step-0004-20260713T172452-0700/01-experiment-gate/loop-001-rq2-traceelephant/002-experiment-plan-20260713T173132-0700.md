## Research Question

- **RQ exactly as written in the paper:** **RQ2: Does Profiler Output
  Correspond to Real Problems?**
- **Specific uncertainty tested here:** whether one fixed target-blind semantic
  operation stack propagates a shared released failure-suspicion signal across
  recurring component roles, intents, actions, and observed outcomes so that
  official decisive failure steps can be recovered with less atomic-step
  inspection than the strongest source-native component and raw-action/tool
  profile over the same 220 real failures.
- **Why the answer matters:** the current paper's reader-facing RQ2 ranking is
  target-informed. A positive result on independently annotated real executions
  would replace that reject-critical weakness with a fresh target-blind test of
  the original profiling prediction. This experiment is evidence toward RQ2;
  it cannot by itself answer all of RQ2 or change the four-RQ contract.

## Expected And Alternative Outcomes

- **Current expected answer:** the role/intent/component/action/status stack will place
  the official decisive steps into higher-ranked recurring groups than a
  source-native system/component/raw-action stack with identical score
  propagation, reducing total atomic-step work at the same 80% macro recall.
- **Strongest competing explanation:** any favorable result is caused by the
  released All-at-Once localizer, smaller groups, extra LLM-derived fields, or
  score propagation rather than decision-relevant semantic responsibility.
- **Contradictory result:** after a valid complete run, the lower endpoint of
  the paired AgentProf-minus-raw work interval is above zero, so AgentProf
  reliably requires more inspection work.
- **Evidence effect of contradiction:** this would bound this fixed semantic
  tag/propagation construction on TraceElephant. It is not a direct challenge
  to the necessary paper thesis that agent observability needs profiling rather
  than only debugging.

### Common visible operation construction

Before loading scorer-only labels, every official step becomes one unit-valued
operation with a stable trace/cell identifier and these visible fields:

1. `system`: Captain-Agent, Magentic-One, or SWE-Agent from the official source
   directory;
2. `component`: the source `agent_name`;
3. `role`: one target-blind tag from `coordination`, `information`, `artifact`,
   `execution`, `verification`, `response`, or `unknown`;
4. `intent`: one tag from `plan`, `inspect`, `transform`, `act`, `verify`,
   `recover`, `report`, or `unknown`;
5. `raw_action`: exact normalized source action/tool identity derived by the
   target-independent algorithm below;
6. `status`: one tag from `progress`, `success`, `failure`, `blocked`, or
   `unclear`;
7. `localizer_hit`: one only for the step predicted by the shared released
   All-at-Once call for that trace, otherwise zero.

The fixed tagger uses the same Qwen model with temperature zero. It operates in
consecutive source-order chunks of at most 20 steps from exactly one trace;
batches never mix traces. Each step exposes its agent name,
immediate last input message, current response content, tool names/arguments,
and current tool log. To fit the real context without trace-length-dependent
fallback, each free-text field uses a fixed target-blind head-plus-tail excerpt:
600 Unicode characters from each end for the immediate input and response, and
400 from each end for tool arguments/logs. Task instruction,
agent-system introduction, and agent configuration use 2,000 characters from
each end once per batch. The prompt emits exactly one role, intent, and status
label per source step and no diagnosis or mistake prediction. Missing or invalid
labels are retried; the only terminal fallback is
`role=unknown`, `intent=unknown`, and `status=unclear`, never a target-informed
replacement.

The exact tagger instruction is:

```text
You assign ordinary profiling fields to target-blind agent execution steps.
Do not diagnose a failure and do not predict a mistake.
Choose exactly one role from: coordination, information, artifact, execution,
verification, response, unknown.
Choose exactly one intent from: plan, inspect, transform, act, verify, recover,
report, unknown.
Choose exactly one status from: progress, success, failure, blocked, unclear.
Role means the component's primary responsibility in this step. Intent means
what the step is trying to accomplish. Status means only the outcome visibly
present in the current step.
Return one JSON object with key steps, whose value is an array in input order.
Every item must contain exactly integer step, string role, string intent, and
string status. No explanation.
Task instruction: <fixed excerpt>
Agent system introduction: <fixed excerpt>
Agent configuration: <fixed excerpt>
Steps: <compact JSON rows in source order>
```

The reviewed version removes the reference outcome from this prompt. The
version-0 materialization with that now-removed line yielded 405 batches and a
maximum of 17,315 input tokens; version 1 is strictly shorter. Before any tag
inference, however, the adapter must submit every exact chat-template-rendered
request to the actual llama.cpp tokenizer and assert
`prompt_tokens + 2,048 <= 32,768`. A context failure makes execution
`INVALID / INCOMPLETE`; it may not trigger adaptive truncation, a smaller batch,
a dropped step, or a changed prompt after approval.

Tag requests use temperature zero, seed `20260713`, one model worker, a
600-second timeout, and at most three byte-identical attempts for transport,
HTTP, empty-output, schema, missing-step, duplicate-step, or invalid-enum
failure. After the third failed attempt, every step in that batch receives
`role=unknown`, `intent=unknown`, and `status=unclear` only as an explicit
terminal missing-tag fallback; this fallback is reported and never selected
from targets.

The field vocabulary, excerpts, batch size, prompt, decode settings, action
mapping, and retry rules are fixed by this reviewed plan. They are not selected
from TraceElephant targets. The tag values are ordinary experimental fields,
not new paper abstractions; RQ3 remains responsible for tag-accuracy evidence.

### Exact source-native raw action

Construct `raw_action` without an LLM or target access:

1. If `output` is an object and `output.choices` is a list, traverse its
   dictionary choices in released order. For each choice whose `message` is a
   dictionary and whose `message.tool_calls` is a list, traverse those calls in
   released order. A valid call is a dictionary with a dictionary `function`
   and a string `function.name` that remains nonempty after Unicode NFKC,
   leading/trailing whitespace stripping, and Unicode case-folding. Ignore
   malformed entries.
2. If and only if the first path contains zero valid calls, traverse
   `tool_logs` when it is a list. Its exact released paths are
   `tool_logs[*].function.name` and `tool_logs[*].function.arguments`; apply the
   same valid-call rule and ignore malformed entries. Never combine calls from
   the two source copies.
3. Preserve every valid selected call and its order, including duplicates.
   Encode `%`, `+`, and `:` inside each normalized name as `%25`, `%2B`, and
   `%3A`, respectively, then join call identities with the literal `+`. This
   makes a multi-tool step one exact ordered action identity.
4. For `str_replace_editor` only, read `function.arguments`. Accept either a
   dictionary or a JSON string that decodes to a dictionary; malformed JSON,
   arrays, scalars, and null supply no subtype. Normalize a string `command` as
   above and append `:<command>` only when it is exactly one of `view`,
   `create`, `str_replace`, `insert`, or `undo_edit`. Other arguments, paths,
   shell text, URLs, and user content never enter the key.
5. If both paths contain zero valid calls, traverse `output.choices` in released
   order and use the first scalar string `finish_reason`, normalized as above,
   as `response:<finish_reason>`; when none exists, use `response:unknown`.

The 17 released tool names and the special editor command values are source
identities, not a custom nine-family ontology. The same `raw_action` field is
present in both primary conditions.

### Shared target-blind suspicion signal

For each complete trace, the adapter calls the official All-at-Once prompt
builder in `response_only` mode. It includes the task instruction, official
reference answer or test status, system introduction, step agent names, and
current responses, but never failure annotations. The exact scope is
**reference-assisted, failure-annotation-blind localization**: the published
default reference outcome is visible only inside this shared localizer, whereas
`mistake_agent`, `mistake_step`, and `mistake_reason` are not. The semantic
tagger, operation fields, and either profile condition never receive the
reference outcome. A without-reference condition would test a different
published application scenario and is not bundled here. The paper may not
generalize this result to no-reference deployment. Deterministic decoding
returns exactly one predicted agent and integer step plus a reason. A valid
in-range predicted step receives `localizer_hit=1`; all other steps receive
zero. A terminal parse failure or out-of-range prediction is retained as a
no-hit trace rather than excluded. The 220 terminal response records are shared
unchanged by every grouping method.

Call the response-only builder directly; never attempt the released full-input
path or rely on its broken exception-driven fallback. Use temperature zero,
seed `20260713`, a 1,024-token output reserve, one model worker, a 600-second
request timeout, and at most three identical attempts for transport, HTTP,
empty-output, or parse failures. The final failed attempt becomes the retained
terminal no-hit status. The predicted reason and agent never enter tag or
profile construction.

### Profile scores

For a nonempty group with `h` shared localizer hits among `n` operations, set
`z = 1.959963984540054`, `p = h/n`, and use the 95% Wilson lower bound:

```text
W(h,n) = [p + z^2/(2n)
          - z * sqrt((p(1-p) + z^2/(4n))/n)]
         / [1 + z^2/n]
```

`h` and `n` are non-negative integers with `0 <= h <= n`. Define
`W(0,n) = +0.0` explicitly for every `n > 0`; do not evaluate the displayed
binary64 expression in that branch. A zero-weight group
in a bootstrap replicate is absent and receives no score; the implementation
must never call `W` with `n=0`. Compute once with IEEE-754 binary64 operations in
the displayed order. The canonical tier identity is Python `float.hex(score)`.
All units with the same canonical score form one complete tier, including all
zero-hit groups whose computed lower bound is exactly zero. No ordinal, key,
group width, or target breaks a score tie.

- **AgentProf:** run the real binary with stack
  `system -> role -> intent -> component -> raw_action -> status`, consume its
  emitted folded leaves, compute the Wilson score at each emitted prefix, and
  assign each leaf the maximum score on its root-to-leaf path. Inspect all
  operations in a tied leaf-score tier together.
- **Headline source-native raw baseline:** run the same real binary with stack
  `system -> component -> raw_action`, consume its emitted leaves, apply the
  identical Wilson function at every emitted prefix, and assign each leaf the
  maximum root-to-leaf score. Inspect identical-score tiers under the same rule.

The adapter writes two operation JSONL files over the identical ordered rows.
Every record has exact schema `{"value": <positive integer>, "fields":
{...}}`. Every raw field value is encoded injectively as `hex:` followed by the
lower-case hexadecimal UTF-8 bytes; round-trip and collision checks must pass.
The count file uses `value=1`; the shifted file uses
`value=1+localizer_hit`. For each of the two primary stacks, invoke:

```bash
agentpprof/target/release/agentpprof \
  --operation-file <count-or-shifted.jsonl> \
  --view operations --format json --output <profile.json> \
  --stack <comma-separated-fields> --deterministic-output
```

The process stdout must decode to an object with `status == "ok"`; the output
must contain integer `profile.stacks` counters. The count profile supplies
`n`; the shifted-minus-count counter at each exact emitted prefix supplies
`h`. Negative differences, an unexpected shifted key, or nonconservation is
`INVALID`. The expected operation leaf is exactly the semicolon join of
`<field>:<hex-encoded-value>` in stack order. For both the six-field proposed
path and three-field headline path, its independent counter must equal the real
binary's emitted leaf counter, and independent reconstruction must exactly
match emitted prefix counts, hit differences, scores, tiers, assignments, and
complete work curves. Scoring therefore consumes the real binary output rather
than silently replacing either primary path with a local group-by.

The tagger is run once as common construction, and its output rows are available
to both conditions. The baseline deliberately implements the credible competing
position that exact component/action identity is sufficient; it is not denied the raw
trace, localizer hit, model, or compute budget. The only load-bearing algorithmic
choice is whether fixed semantic role, intent, and observed status add useful
responsibility above that strongest raw stack.

| Condition property | AgentProf | Headline raw-action baseline | Why matched or controlled |
|---|---|---|---|
| Initial knowledge/artifacts | Same official visible traces, shared tags, exact raw actions, and shared localizer hits | Identical | Reference outcome enters only the shared signal; no failure target enters either path |
| Algorithm/control flow | Six-field semantic/component/action stack plus prefix-max Wilson | Three-field source-native component/action stack plus identical prefix-max Wilson | Semantic responsibility fields are the only disputed addition |
| Tools and authority | Same adapter, model outputs, operation rows, scorer boundary | Identical | Neither can query scorer labels |
| Observed inputs | Same 5,960 visible operations and 220 terminal hit records | Identical | Raw baseline chooses not to group by semantic fields |
| Compute/state budget | Shared model/tag artifacts; count and shifted AgentProf folds | Same artifacts and the same two real binary folds | Proposed receives no extra target-time model call |

### Trivial-positive check

A win would not show merely that an API ran or that extra information was
available: both methods start from the same completed operation table and
shared suspicion signal. It would change the disputed belief that raw action
identity is sufficient for cross-run failure inspection by showing that a fixed
responsibility profile propagates noisy evidence to independently decisive
steps with lower work.

## Controls And Why They Are Not Separate Hypotheses

Only raw action is the headline baseline. The following are interpretation
controls over the same operation rows and score; none receives its own
optimization or positive criterion:

- **independent step:** rank individual steps by `localizer_hit`, showing the
  released localizer without cross-run propagation;
- **session:** group by complete trace, showing coarse per-run aggregation;
- **source-native:** group by trace and source component/agent name, preserving
  the released execution identity available at each step;
- **flat all-in-one:** a lower-resolution work sanity check;
- **flat exact reconstruction:** reconstruct every AgentProf prefix assignment
  and score relationally; it must exactly match AgentProf and is an identity
  control, never a superiority baseline;
- **width-only:** rank AgentProf leaves by inverse width without localizer hits,
  checking whether small semantic groups alone explain the result; and
- **matched semantic permutation:** within every headline raw leaf
  `(system, component, raw_action)`, jointly permute each operation's complete
  `(role, intent, status)` tuple. This preserves the exact raw membership,
  semantic-tuple multiset, proposed leaf sizes, and every prefix topology/count
  opportunity while breaking semantic alignment to operations, localizer hits,
  and later scorer targets; and
- **scorer-only oracle:** order official decisive target steps first to show the
  metric lower bound; it is never compared as a deployable method.

These controls test the same primary comparison's mechanics. Official
All-at-Once exact agent and step accuracy are reported as shared-signal
engagement, not as another headline comparison.

Control definitions are fixed: session uses `system -> trace_id`; source-native
uses `system -> trace_id -> component`; both use the same prefix-max `W(h,n)`.
Independent step uses the binary `localizer_hit` directly. Flat all-in-one uses
`W(total_hits, total_steps)`. Width-only assigns each AgentProf leaf `1/n_leaf`
and uses the same `float.hex` tier rule. Exact-flat reconstructs every AgentProf
and headline prefix from the operation table and must match leaf membership,
scores, tiers, and the complete work curve for both primary paths. The oracle
assigns target steps score one and all others zero after scorer entry, charging
both complete tiers normally.

Materialize 200 matched permutations before scorer labels are loaded. Sort
operations by `(cell, trace_id, step_id)` and raw leaves by canonical compact
JSON of `[system, component, raw_action]`. For permutation index `k=1..200` and
each raw leaf, seed a fresh Python `random.Random` with the unsigned big-endian
integer from the first eight bytes of
`SHA256("20260713\0" + str(k) + "\0" + raw_leaf_json)`, Fisher-Yates shuffle the
tuple vector in canonical operation order, and zip it back to those operations.
Duplicates remain duplicates. Each permuted six-field stack runs through the
same count/shifted real AgentProf path and score. This construction uses no
`mistake_*` value, decisive target, localizer hit, or result-dependent seed.
The point randomization value is
`p=(1 + # permutations whose work <= actual AgentProf work) / 201`; semantic
mechanism engagement requires actual AgentProf work to be strictly lower than
all 200 permutations, hence `p=1/201`. This is one interpretation control for
the primary hypothesis, not a second optimized comparison. It is evaluated on
the complete population and is not recomputed inside the paired trace
bootstrap.

## Workloads And Metrics

### Complete workload

All 220 official failures and all 5,960 source steps across the five official
system/task cells must be present. No trace or source cell may be dropped for
model failure, output format, long context, missing tool logs, or an unfavorable
result. The scorer checks exact integer step identity and exact normalized agent
identity.

### Primary metric

**Atomic-step work at at least 80% macro decisive-step recall.** Rank complete
group tiers. After each tier, compute decisive-step recall separately for each
of the five official system/task cells, then take their unweighted mean. Select
the first complete tier reaching at least 0.80 macro recall. Work is the number
of unique atomic steps in all selected tiers divided by all 5,960 steps. If a
method never reaches the threshold before the final tier, its work is 1.0.

Because every trace has one official decisive step, cell recall is the fraction
of traces whose exact decisive step has entered the inspected groups. Work
counts atomic steps, not group labels, model tokens, or traces. Ties are never
broken using targets or stable ordinals; the complete tied score tier is charged.

### Secondary descriptive metrics

- work at 50% and 90% macro recall;
- macro and micro recall at 10%, 20%, and 30% atomic-step work;
- group count and tied-tier count;
- first decisive-step work, clearly secondary;
- official exact responsible-agent and decisive-step accuracy of the shared
  All-at-Once outputs; and
- per-cell primary work/recall curves.

No secondary metric can rescue a failed primary criterion.

### Uncertainty

Run 10,000 paired bootstrap replicates with seed `20260713`. Resample traces
with replacement independently inside each of the five cells, carrying all
steps and the one target attached to each sampled trace. For every replicate,
recompute group hit/count scores, tied tiers, and work at 80% macro recall for
the two primary conditions, plus their independent exact reconstructions.
Report percentile 95% intervals for the two point metrics and the paired
AgentProf-minus-raw-action work delta. The other interpretation controls remain
complete-population point checks. Preserve repeated sampled traces
as multiplicities rather than deduplicating them.

Each replicate draws exactly 12 Captain/AssistantBench, 73 Captain/GAIA,
17 Magentic-One/AssistantBench, 74 Magentic-One/GAIA, and 44
SWE-Agent/SWE-Bench traces from the corresponding cells. Every draw receives a
new occurrence identifier. All steps, localizer hits, and the decisive target
from a repeated trace are repeated; semantic and raw group counts include those
multiplicities, while session/source-native keys use the occurrence identifier
so duplicate draws do not collapse. The replicate work denominator is the
total number of step occurrences drawn, and each cell's recall denominator is
its fixed number of trace occurrences above. Macro recall remains the
unweighted mean of the five cell recalls.

For every metric and paired delta, sort the 10,000 replicate values ascending
and use the nearest-rank order statistics: element 250 for the 2.5% endpoint
and element 9,750 for the 97.5% endpoint under one-based indexing (zero-based
indices 249 and 9,749). Do not interpolate or substitute a standard-error
interval.

### Positive criterion

Support for the tested hypothesis requires all of the following:

1. valid completion of all 220 localizer outputs, all 5,960 tag/operation rows,
   both primary profile paths, every control, and all 10,000 paired replicates;
2. AgentProf reaches at least 80% macro decisive-step recall;
3. AgentProf's primary work point estimate is lower than raw action; and
4. the upper endpoint of the paired 95% AgentProf-minus-raw-action work interval
   is below zero; and
5. the matched semantic-permutation control has `p=1/201`.

After valid full completion, classify the tested hypothesis exhaustively:

- `SUPPORTED` iff the paired delta upper endpoint is below zero and the matched
  semantic-permutation control has `p=1/201`;
- `CONTRADICTED` iff the paired delta lower endpoint is above zero; and
- `INCONCLUSIVE` otherwise.

The point-estimate and recall requirements above remain necessary for
`SUPPORTED`; a numerical inconsistency between them and the interval makes the
result review `INVALID`, not a discretionary verdict. Run status `INVALID` or
`INCOMPLETE` is always judged separately from the tested hypothesis.

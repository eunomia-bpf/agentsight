### Required implementation-contract repair

The approved Experiment 001 plan review required the existing raw open-vocabulary session-tag contract to remain unchanged and available alongside the new declared task field. The current implementation preserves a separate `session_tag` field, but it does not preserve the old inference semantics when `--task-choice` is active.

The old path computes the raw session tag as:

```text
kind = "session"
text = title + cwd + prompt text
hints = source + model
```

The declared-task branch currently calls:

```rust
tagger.tag_with_declared_choices("task", &prompt_text, &[], task_choices)
```

and assigns its `raw_tag` to `session.session_tag`. Thus the optional path changes the tag kind from `session` to `task`, the input from `title + cwd + prompt text` to prompt text only, and the hints from source/model to none.

The existing unit test proves only that separate `session_tag` and `task_tag` fields fold together; it does not prove preservation of the prior raw session-tag request contract.

Impact:

- The independently measured `task_tag` accuracy remains valid. Its declared-task request uses the intended goal and declared descriptions, and the scorer never uses `session_tag`.
- The paper's bounded AgentBoard numbers do not need to be discarded.
- The implementation and reports cannot claim that the established raw-tag behavior is unchanged until the raw path really uses the previous session input, kind, and hints.
- A full AgentBoard rerun is unnecessary if the repair changes only raw-session-tag computation and leaves the declared-task request byte-equivalent. If the declared-task request changes, the corresponding complete result must be rerun.

Exact repair condition:

1. In declared-task mode, compute `session_tag` through the same old `tag("session", session_input, [source, model])` path.
2. Compute `task_tag` separately from the intended task input and declared choices.
3. Add a focused test that distinguishes the old session request contract from the declared task request rather than merely checking two stored fields.
4. Update the Step 0031 implementation/report wording to state exactly what was preserved.
5. Verify that the declared-task request is unchanged; otherwise rerun the complete registered profile set.

This is a bounded implementation repair, not a new experiment, new algorithm, or reason to weaken RQ3.

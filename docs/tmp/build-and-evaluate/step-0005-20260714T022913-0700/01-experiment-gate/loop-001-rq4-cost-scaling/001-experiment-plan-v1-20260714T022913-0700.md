## Tested hypothesis

> Complete AgentProf profile construction has practical and predictable
> scaling on the four complete existing real public workloads and their exact
> union, while prior fixed-input evidence shows that the shared tag-cache
> mechanism eliminates repeated LLM field-derivation calls.

The experiment may change the conclusion drawn from the measurements, but it
must not change RQ4. A failed construction or measurement is repaired and the
same plan is rerun; an unfavorable valid result is recorded rather than hidden.

## Evidence reused instead of rerun

1. **R327/R328 machinery:** current `agentpprof` construction path,
   deterministic JSON output, output parsing, and cost-measurement conventions.
2. **R160 cache result:** prior fixed-input evidence that the shared tag-cache
   mechanism eliminates repeated LLM calls. On eight fixed real Codex sessions
   and 76 tag requests, one clean construction took 1.64 s with 60 uncached
   llama.cpp calls; one identical-input cached reconstruction took 0.11 s with
   76/76 cache hits and zero LLM calls. The sanitized input manifest confirms
   identical inputs. R160 used the predecessor AgentFlame CLI and provides one
   clean/cached pair, so it supports the cache mechanism but is not treated as
   repeated performance evidence for the current release `agentpprof` binary.
3. **Four tracked real public inputs:** no new download, conversion, or label
   work is needed.

R160 is not rerun because its exact private session paths were intentionally
redacted and its scientific cache comparison is already complete. Recreating
the environment with newly selected sessions would test a different input and
add LLM-server/model variance without filling the current RQ4 gap.

## Two fixed profile constructions

Both profiles use `--view operations`, JSON output, and
`--deterministic-output` on the same input rows.

- **AgentProf semantic profile:**
  `project,agent,task,phase,op,tool,status`
- **Raw-action cost control:**
  `project,agent,action,status`

These fields already exist in all four operation files. The comparison is a
cost envelope for the paper's richer semantic hierarchy versus a simple raw
action hierarchy; it is not an accuracy experiment and does not rank either
profile by diagnostic quality.

## Complete new execution matrix

- 5 input sizes
- 2 profile constructions
- 3 complete repetitions per cell
- **30 total measured profiler invocations**

One smallest-workload semantic invocation is used as the real preflight. It is
not substituted for any of the 30 full-run cells. The full run executes every
cell to terminal success or recorded failure.

## Measurements

For each invocation, record:

- end-to-end wall-clock milliseconds;
- peak resident set size from GNU `time -v`;
- operation rows and derived operations/second;
- output bytes;
- reported samples and unique stacks;
- exit status and profiler stdout/stderr.

For each workload/profile cell, report the median of three repetitions and all
three raw observations. Fit the simple descriptive line
`median wall time = intercept + slope * operation rows` separately for semantic
and raw-action profiles, reporting slope and R-squared. No resampling,
significance test, or hidden model-selection step is used.

## Predeclared interpretation

- Report monotonicity, the descriptive linear fit, milliseconds per operation,
  unique stacks, and output bytes for all five complete inputs. These
  measurements characterize predictability, but no single R-squared cutoff
  determines validity because the four public workloads are heterogeneous and
  non-nested.
- **Practical scaling over the tested range is supported** when the 27,765-row union's
  median semantic construction completes within 10 seconds and peak RSS stays
  below 1 GiB on the recorded machine.
- The R160 pair is reported as cache-mechanism support: its identical-input
  cached reconstruction was about 14.9x faster and issued zero new LLM calls.
  It is not promoted to a repeated current-binary performance estimate.

All thresholds are fixed before the new full run. Report the measurements even
if a threshold is missed. Machine identity and software version are descriptive
context, not validity gates.

## Execution implementation

Use a thin parameterized runner around the existing release
`agentpprof/target/release/agentpprof` and GNU `/usr/bin/time -v`. Reuse parsing
helpers from `script/operation_profile_cost_eval.py` where doing so shortens the
implementation. The runner may write detailed outputs under
`.agentsight/experiments/rq4-cost-scaling-v1/` and a compact result report under
the timestamped step directory.

Do not add source-tracked-clean checks, Git hashes, manifests, seals, packets,
or publication status to experiment validity.

## Validity checks

- all four input files exist and their nonblank row counts match the table;
- every input exposes every selected stack field;
- semantic and raw profiles for a cell receive identical input files and row
  counts;
- profiler returns success and its reported sample count equals the input
  operation-value total;
- every planned repetition is present before result interpretation;
- R160 cache claims are read from the committed sanitized result, not memory.

## Explicit exclusions

- no new benchmark, synthetic scale duplication, or partial subsampling;
- no rerun of all 76 historical specs;
- no new LLM server, model, tag prompt, session selection, or cache experiment;
- no bootstrap, permutation test, confidence-interval framework, or reviewer
  robustness matrix;
- no paper, story, RQ, or shared-skill edit inside this experiment loop.

## Required result disposition

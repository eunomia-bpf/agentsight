# Plan Review Round 01 — Fixed-Instruction Follow-On Structure Fidelity

**Reviewer role:** independent read-only experiment-plan reviewer
**Verdict:** **NEEDS REVISION**

## Scientific assessment

This is a worthwhile supporting RQ3 analysis. Filtering the already fixed
405-session rows to the manifest-defined 364-session complement directly tests
whether the headline A2--recurrence effect is driven by the 41 sessions used
for product design and visual inspection. The population is real and complete,
the candidate and comparisons use the same operations and official reference,
ordinary B-cubed is the appropriate primary partition metric, and the baseline
set is minimal. Multi-resolution recurrence is the strongest runnable
alternative, native structure answers a distinct competing explanation, and
the native-turn row is correctly demoted to a diagnostic control. Treating
ACT*ONOMY as cited closest work rather than manufacturing an incompatible
numerical row is scientifically fair.

The arithmetic population checks are internally consistent: 364 sessions and
15,116 operations imply 14,752 within-session adjacent pairs, and the declared
framework counts sum to 364. The result must nevertheless remain supporting,
manifest-defined follow-on evidence within an already observed CodeTrace
family, not external or untouched generalization.

## Must-fix issues

1. **Remove the unsupported “pre-specified” characterization.** The complete
   405-session aggregate result was already observed before this complement
   analysis was proposed. The manifest and annotation order may have been
   fixed earlier, but that does not make this particular analysis
   preregistered. Describe it consistently as a manifest-defined, post-design,
   post-aggregate subset reanalysis. Claim a pre-result split only if a dated
   record actually specified this exact 364-session test and decision rule
   before the union result was opened.

2. **Add an executable analysis path.** The plan gives inputs and outputs but
   no scorer/analysis implementation or exact preflight and full commands.
   Specify the one script or existing official analysis entry point, its input
   arguments, `10,000` resamples, seed, and output root. Define the bootstrap
   operationally enough to reproduce it: sorted task-cluster universe,
   sampling with replacement including multiplicity, operation-weighted
   B-cubed precision/recall followed by F1 for each draw, paired candidate
   minus recurrence, and the percentile interval convention. This is ordinary
   executability, not additional experiment infrastructure.

3. **Cite the paper-facing metrics.** Add the defining B-cubed citation and the
   CodeTrace/official protocol source for exact adjacent-boundary F1. Calling
   them “standard” without the defining paper or official benchmark citation
   does not satisfy the experiment skill's metric requirement.

4. **Correct the proposed paper sentence.** “More faithful ... on all 364”
   implies per-session dominance, which aggregate B-cubed and a cluster
   interval do not establish. Use “over the complete 364-session follow-on
   population,” then report the per-framework rows and any losing framework.
   Do not use “all” unless A2 actually beats recurrence in every individual
   session, which is not the registered test.

5. **Make the declared cluster count a completion check.** The manifest records
   sessions and operations but not the claimed 238 task-name clusters. Add
   exact verification of 238 unique `task_name` values to preflight/full
   completion, alongside the existing session, operation, pair, exclusion, and
   framework checks.

After these focused repairs, the plan is scientifically fair, simple, and
ready for real preflight. No additional baseline, benchmark, model run, custom
metric, or control protocol is required.
